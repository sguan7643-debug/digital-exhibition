# DEH-HAINENG-APPROVAL-FIELDS-20260924 产品需求文档

## 1. 产品目标与用户价值

### 1.1 产品目标

修复海能Work申请写入飞书多维表格“上架申请”时字段不完整的问题。一次申请成功后，同一条记录必须包含真实的飞书审批实例ID，以及申请页面中的适用用户和适用部门。

当服务重试或同一 `TEST_` 业务键再次投影时，应复用原记录并校验、补齐字段，而不是因为记录已经存在就直接跳过，也不得创建重复记录。

### 1.2 用户价值

- 运营人员可直接在“上架申请”表中看到审批实例与授权范围，无需人工对照其他表或页面。
- 接口成功意味着关键投影已经写入，不再出现页面显示提交成功但表内字段为空。
- 服务重试能够修复不完整记录，不会重复生成申请记录。

## 3. 范围

### 3.1 范围内

1. 新建海能Work上架申请记录时写入：
   - `审批实例ID = record.instanceId`
   - `授权用户 = application.users`（页面“适用用户”）
   - `授权部门 = application.accessDepartment`（页面“适用部门”）
2. 三个目标值任一为空时，在调用飞书写入前返回明确的数据不完整错误。
3. 同一 `TEST_` 业务键已存在时，显式启用“重放一致性修复”：按精确记录ID补写或纠正三个目标字段及当前审批状态，不新增重复行。
4. 没有显式启用一致性修复的其他 `createOnce` 调用保持原有“发现即返回”行为，避免改变其他表的幂等语义。
5. 飞书投影写入失败时，审批提交接口不得返回成功；错误保留可诊断代码和可重试语义。
6. 增加单元测试覆盖首次创建、默认重放不更新、显式重放补写、投影字段映射、写入失败传播和重复行防护。
7. 执行相关服务端测试及项目生产构建回归。

### 3.2 范围外

1. 不自动扫描或批量回填本任务上线前已经存在的历史记录。
2. 不修改RPA、EAD或其他应用类型审批。
3. 不改变申请页面表单、字典下拉、视觉样式或成功页交互。
4. 不创建、删除或改型飞书字段。
5. 不放宽 `TEST_` 测试写入限制，不允许模糊匹配或跨记录更新。
6. 不承诺飞书审批创建与多维表格投影具备跨系统数据库事务；失败通过幂等重放恢复。
7. 不部署、不发布、不推送GitHub、不合并主分支。

## 4. 主流程

1. 已授权用户进入 `/apps/onboarding/apply`，选择海能Work并填写申请信息、适用用户和适用部门。
2. 用户提交后，前端把 `users` 和 `accessDepartment` 放入海能Work审批请求。
3. 服务端校验两个授权范围字段非空，创建或复用飞书审批实例。
4. 服务端取得真实审批实例ID，并构造“上架申请”投影。
5. 若业务键不存在，创建一条完整记录。
6. 若业务键已存在，读取精确记录并在显式一致性修复模式下补齐/纠正目标字段和状态，不创建第二条记录。
7. 只有投影成功后接口返回审批实例ID和审批状态；失败则返回明确错误，后续相同幂等重放可继续修复。

## 5. 状态清单

| 状态 | 系统行为 |
| --- | --- |
| 首次写入成功 | 新建唯一记录，三个目标字段完整，接口成功返回。 |
| 幂等重放且字段一致 | 不新增、不执行无意义更新，返回原记录。 |
| 幂等重放且字段缺失/不一致 | 更新精确匹配记录，补齐目标字段和当前状态，返回修复后的记录。 |
| 页面授权范围缺失 | 在创建审批前返回 `400` 数据校验错误。 |
| 审批实例ID缺失 | 不写入不完整投影，返回明确错误。 |
| 多维表格写入失败 | 接口不报告成功，保留审批注册信息供后续幂等重试。 |
| 业务键重复匹配多行 | 返回冲突错误，不猜测更新目标。 |
| 非 `TEST_` 业务键 | 继续拒绝写入。 |
| 无需更新 | 不发送多余更新请求。 |

本任务不新增页面加载态、空态或禁用态；沿用现有申请页面行为。

## 6. 明确禁止事项

1. 不通过新增第二条“上架申请”记录绕过旧记录字段为空的问题。
2. 不用固定值、测试占位值或模拟数据代替页面适用用户、适用部门和真实实例ID。
3. 不以模糊查询结果选择更新目标。
4. 不让通用安全写入服务默认更新所有已存在记录；一致性修复必须由调用方显式选择。
5. 不吞掉飞书更新错误并向浏览器返回成功。
6. 不修改历史记录或生产配置作为本次代码验收步骤。

## 7. 范围批准需要确认的决定

1. 批准对新提交和请求链路中命中的同一 `TEST_` 记录执行字段补齐，但不做历史批量回填。
2. 批准“授权用户/授权部门”分别采用页面“适用用户/适用部门”的原始规范化文本。
3. 批准仅为“上架申请”投影显式开启重放一致性修复，其他表保持原幂等行为。
4. 批准投影失败时提交接口返回失败，依赖幂等重试恢复，不伪报成功。

## 8. 验收标准

### AC-01：首次创建写入完整

**Given** 已授权用户提交字段完整的海能Work申请，  
**When** 飞书审批返回有效实例ID且“上架申请”业务键不存在，  
**Then** 新建记录的“审批实例ID”“授权用户”“授权部门”均非空，并分别等于审批实例ID、页面适用用户和页面适用部门。

### AC-02：字段映射不串位

**Given** 页面适用用户为 `U002`、适用部门为 `专业分公司`，  
**When** 服务端构造“上架申请”写入字段，  
**Then** “授权用户”为 `U002`，“授权部门”为 `专业分公司`，不得互换或改用申请人/所属部门。

### AC-03：幂等重放补齐旧记录

**Given** 同一 `TEST_` 业务键已有唯一记录，但三个目标字段为空或与当前投影不一致，  
**When** 同一审批记录再次投影，  
**Then** 服务端更新该记录并补齐目标字段和当前状态，不创建第二条记录。

### AC-04：一致记录不产生多余更新

**Given** 同一 `TEST_` 业务键的唯一记录已经与当前投影一致，  
**When** 再次投影，  
**Then** 返回重放结果，不创建新记录，也不发送无意义更新。

### AC-05：其他调用默认行为不变

**Given** 其他表调用安全写入服务且未显式开启一致性修复，  
**When** 业务键已存在，  
**Then** 仍按原行为直接返回已有记录，不发生隐式更新。

### AC-06：缺失字段安全失败

**Given** 适用用户、适用部门或审批实例ID任一缺失，  
**When** 尝试创建“上架申请”投影，  
**Then** 返回明确的4xx数据不完整错误，不写入不完整记录。

### AC-07：投影失败不伪报提交成功

**Given** 飞书审批实例已创建，但“上架申请”创建或补写失败，  
**When** 提交接口等待投影结果，  
**Then** 接口返回失败而不是成功，并保留相同审批实例可供后续幂等重试，不重复创建审批实例。

### AC-08：冲突与安全边界

**Given** 业务键非 `TEST_`、精确业务键匹配多行或记录不属于允许的安全范围，  
**When** 尝试补写，  
**Then** 服务拒绝操作并返回明确错误，不更新任意候选记录。

### AC-09：回归验证

**Given** 修复完成，  
**When** 执行相关服务端测试和生产构建，  
**Then** 首次写入、重放补齐、重复防护、错误传播测试通过，且现有审批与安全记录测试无回归。
