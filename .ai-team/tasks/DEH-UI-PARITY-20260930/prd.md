# Product Requirements Document

## 1. Product Goal and Target User Value

让当前数智产品展厅在保留全部真实业务能力的前提下，使用产品指定源码包中的 UI 样式，使业务用户看到统一、稳定且符合产品验收基准的界面。

目标用户包括数智产品展厅 Web 端业务用户和负责界面验收的产品人员。用户价值是：页面外观不因真实接口和新增业务能力接入而偏离已确认的产品视觉标准。

## 2. Facts, Assumptions, and Evidence

### Facts

- **Fact:** 用户明确要求当前项目 UI 与 `digital-exhibition-SOURCE-20260916-165348.zip` 中的代码样式保持一致，并说明这是产品强制要求。证据：当前任务对话和 `task-brief.md`。
- **Fact:** 参考包是 Vue Web 项目，包含 `src/style.css`、`src/h5.css`、`src/components/ExhibitionShell.vue` 以及主要页面实现。证据：参考包文件清单。
- **Fact:** 当前项目也是 Vue Web 项目，但已经增加真实数据读取、OAuth、审批、缓存、权限和额外业务页面。证据：当前仓库 `package.json`、`src/integration/`、`src/pages/` 和 `server/`。
- **Fact:** 当前项目与参考包的全局样式、H5 样式、应用外壳和关键页面文件哈希均不同，不能通过整体覆盖安全实现。证据：任务建立时的文件哈希对比。
- **Fact:** 参考包 README 将 `#0060A6` 指定为主色，并描述了顶部导航、侧栏、应用卡片、标签、详情页和响应式行为。证据：参考包 `README-DEPLOY.md`。

### Assumptions Requiring Confirmation

- **Assumption:** “保持一致”指视觉呈现与交互外观一致，不要求把真实业务数据替换成参考包的固定演示内容。
- **Assumption:** 参考包没有的当前新增页面，应复用参考包的设计令牌、布局规则和共享组件，而不是删除这些页面。
- **Assumption:** 动态用户名、列表数量、审批状态和业务文案允许随真实数据变化；相同组件的排版和样式必须一致。
- **Assumption:** 视觉验收覆盖当前项目支持的桌面和 H5 响应式范围，具体基准视口和逐页对照矩阵在设计阶段锁定。

## 3. In Scope and Out of Scope

### In Scope

- 以指定源码包作为唯一视觉基准，不混用其他历史版本。
- 对齐顶部导航、用户区、侧栏、页面背景、内容宽度和主容器布局。
- 对齐颜色、字号、字重、行高、边框、圆角、阴影、间距和图标尺寸。
- 对齐按钮、输入框、下拉框、单选框、分页、标签、卡片、表格、弹窗和状态提示。
- 对齐首页、应用中心、应用详情及双方共有页面的页面级布局。
- 将同一视觉系统应用到当前新增的申请、审批、真实数据状态和管理页面。
- 覆盖成功、加载、空数据、错误、禁用和权限相关界面状态。
- 覆盖桌面端和现有 H5 响应式断点。
- 保留并回归验证现有真实接口、OAuth、审批、缓存、权限、上传和路由逻辑。

### Out of Scope

- 不恢复参考包的模拟数据、内存数据、旧网络守卫或纯演示逻辑。
- 不删除当前新增业务页面或功能。
- 不修改后端服务、接口协议、飞书多维表、数据库或服务器配置。
- 不改变应用上架、审批、权限、登录和缓存业务规则。
- 不在本任务中执行合并、部署、发布或生产环境变更。

## 4. Primary User Flow

1. 用户通过现有入口完成登录并进入数智产品展厅。
2. 系统继续使用当前真实身份和真实接口加载数据。
3. 用户在首页、应用中心、详情页、个人中心、申请与管理页面之间导航。
4. 页面使用参考包一致的外壳、组件和视觉状态呈现数据。
5. 当数据处于加载、为空、失败、禁用或权限受限状态时，页面仍使用同一视觉语言并保留当前业务语义。
6. 用户完成浏览、筛选、申请、审批或管理操作，功能结果与改造前一致。

## 5. State Inventory

- **Success:** 真实数据正常加载，页面布局和共享组件与视觉基准一致。
- **Loading:** 保留当前请求与静默刷新机制，加载占位、进度和提示样式使用基准视觉系统。
- **Empty:** 保留当前空数据判断与文案语义，空状态的排版、间距、色彩和按钮样式对齐基准。
- **Error:** 保留当前错误码、重试行为和旧数据回退机制，错误提示外观对齐基准。
- **Disabled:** 保留当前禁用条件，禁用控件在颜色、边框、光标和反馈方面采用基准样式。
- **Permission-dependent:** 保留当前登录、授权和权限判断，权限提示及可操作控件采用基准样式。
- **Responsive:** 桌面和 H5 下导航、侧栏、卡片、表格和表单遵循基准断点与布局规则；业务内容不得横向溢出或遮挡。

## 6. Explicit Non-goals / Things Not to Do

- 不以复制整个旧 `src` 目录的方式实施。
- 不为了视觉一致而降低、关闭或伪造真实接口能力。
- 不把真实用户、部门、审批状态或应用数据改成静态值。
- 不在样式任务中顺带重构无关业务代码。
- 不用仅修改截图或构建产物代替源码改造。
- 不以人工主观判断作为唯一证据，必须保留可复查的视觉对照和自动化回归结果。

## 7. Acceptance Criteria

### AC-1 Shared shell parity

**Given** 当前项目和参考包在相同桌面视口打开，且使用等价页面状态，  
**When** 对比顶部导航、用户区、侧栏、页面背景和主内容容器，  
**Then** 结构、尺寸、色彩、字体、间距、边框、圆角、阴影和交互状态应与参考基准一致，不存在未经批准的视觉差异。

### AC-2 Shared page parity

**Given** 某路由同时存在于当前项目和参考包，  
**When** 在设计阶段锁定的桌面与 H5 视口逐页截图对比，  
**Then** 页面布局和共享组件样式必须一致；仅真实动态数据值和由其导致的合理文本长度差异可以不同。

### AC-3 Current-only page consistency

**Given** 当前项目存在参考包没有的业务页面或状态，  
**When** 用户访问该页面或触发该状态，  
**Then** 页面必须使用与参考包相同的设计令牌、外壳、表单、卡片、按钮和反馈样式，不引入第二套视觉语言。

### AC-4 Real business behavior preservation

**Given** 当前项目已连接真实数据、登录、审批、缓存、权限和上传能力，  
**When** UI 样式迁移完成，  
**Then** 数据来源、请求地址、字段映射、权限判断、路由和提交行为均保持不变，且不得出现模拟数据回退。

### AC-5 State coverage

**Given** 页面进入加载、空数据、错误、禁用或权限受限状态，  
**When** 状态组件呈现，  
**Then** 业务语义和恢复操作保持有效，视觉外观与参考设计系统一致。

### AC-6 Responsive behavior

**Given** 用户使用设计阶段锁定的桌面和 H5 视口，  
**When** 浏览导航、卡片、表格、表单、弹窗和长内容页面，  
**Then** 不出现非预期横向滚动、文字遮挡、操作不可达或布局断裂，并与参考包相应断点行为一致。

### AC-7 Accessibility and interaction preservation

**Given** 用户使用键盘或可见焦点完成现有操作，  
**When** 依次访问导航、筛选、按钮、表单和弹窗，  
**Then** 焦点可见、语义标签和现有交互保持有效，视觉迁移不得造成可用性回退。

### AC-8 Regression evidence

**Given** 实施代码完成，  
**When** 执行项目静态检查、相关测试、完整测试、构建和视觉对照，  
**Then** 所有必需检查通过，并提供共同页面矩阵、视口、截图差异和已知风险证据。

## 8. Open Questions and Scope Decisions

范围批准时需确认以下解释：

1. UI 一致性以视觉样式和布局为准，真实动态数据值无需与演示包相同。
2. 参考包没有的当前新增页面必须保留，并套用相同设计系统。
3. 后端、数据表、接口、权限和业务流程不属于本任务修改范围。
4. 具体基准视口、路由对照矩阵和视觉差异判定方法在设计阶段形成，并在设计批准前由用户确认。
