# UI Handoff — 正式飞书读取性能与状态反馈

## 1. 输入、边界与保留的交互决定

本视觉交接服务于 `DEH-FEISHU-READ-LATENCY-20260918`，以已批准的[PRD](../prd.md)和[UX 交接](ux-handoff.md)为唯一行为输入，并以现有 [`src/style.css`](../../../../src/style.css) 为设计系统证据。它不改变以下 UX 决定：

- P0 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 热态目标是 p95 ≤2 秒；真正冷启动两秒内必须进入可恢复的“首次同步中”，不是长时间转圈或 504。
- 状态归属到 operation 所有者区域；只做一次页面汇总播报，不用全页遮罩，也不让一个慢请求锁住无关区域。
- 陈旧快照、首次同步、强一致查询、写后失效失败、401、403 的行为、文案、重试边界和焦点规则严格沿用 UX 交接。
- 本任务只声明 Vue Web；窄屏是响应式 Web，不宣称或交付 uni-app/原生端。

## 2. 视觉方向与信息层级

沿用展厅当前的“浅灰工作画布 + 白色业务卡片 + 海油蓝主操作”方向。性能状态应被识别为**所属业务区域的状态**，而不是另一个技术控制台：

1. 页面标题/既有业务标题仍是最高层级；不新增全局性能页或全屏 loading。
2. 分区标题下方或现有内容首行放置状态条；状态条后依次是来源时间、说明、恢复操作，保持 UX 的阅读顺序。
3. 有可读陈旧内容时，内容优先，状态条紧贴区域标题且不覆盖内容；无可读内容时，使用区域内空态面板。
4. 写后失效失败紧邻提交结果；强一致查询紧邻其结果区域；权限拒绝仅替换受影响的局部区域。

## 3. 现有视觉令牌与可访问性

不新增未被现有系统支持的颜色或组件。实现直接引用以下现有令牌/规则：

| 用途 | 令牌或现有规则 | 用法 |
| --- | --- | --- |
| 画布/内容卡 | `--xlt-canvas #f5f7fa`、`--xlt-surface #fff` | 页面画布与模块内容保持既有层级。 |
| 标题/正文/辅助文案 | `--xlt-ink #102a4c`、`--xlt-text #3e5571`、`--xlt-muted #6b7d91` | 标题、主体说明、来源时间分别使用；状态不得只以颜色表达。 |
| 主操作/链接 | `--xlt-navy-900 #0060a6`、`--xlt-navy-950 #052b57` | “重试”“重试同步”“查询最新状态”的主/悬停态。 |
| 边界/弱底 | `--xlt-line #d9e2ec`、`--xlt-divider #e7edf3`、`--xlt-soft #eaf1f8` | 卡片、状态条与局部 skeleton 的边界和背景。 |
| 卡片形状/层级 | `--xlt-radius 7px`、`--xlt-shadow` | 保持现有卡片圆角和低阴影，不制造浮层感。 |
| 焦点与错误 | `--form-control-focus #1f6fca`、`--form-control-error #c62828`、现有 `:focus-visible` ring | 所有恢复按钮的可见键盘焦点；不可恢复错误与失效失败的左侧标记/边框。 |
| 既有请求提示 | `.request-activity-banner`（`#eef6ff`、`#a9c9e8`、`#17304f`） | 仅作为页面级简短活动汇总的样式来源，不替代各区域状态。 |

正文与辅助文本分别沿用 `--xlt-font-meta` / `--xlt-font-caption`；分区标题沿用 `--xlt-font-section`，页面标题沿用 `--xlt-font-page-title`。在上述前景/背景组合上正文必须保持至少 4.5:1 对比度，边界、图标和焦点环等非文本信息至少 3:1；任何状态都同时有文字。

间距延续现有 8px 小间距、14px 区域 gap 和页面 18–22px 内边距：状态条内边距 10–12px、标题与状态条间距 8px、状态说明/时间/操作间距 6–8px。避免新增装饰插图；图标仅作文字的辅助，使用现有线性业务图标尺度（16–20px）。

## 4. 组件外观与状态变体

### 4.1 局部数据状态条

状态条是可复用的区域内组件，不是 toast，不固定在视口，也不遮挡操作。

- 基础：白色或 `--xlt-soft` 弱底、1px `--xlt-line` 边界、`--xlt-radius`，左侧 3px 竖向状态条；图标 + 加粗短标题 + 说明/来源时间 + 操作按逻辑顺序排列。
- `fresh`：不额外展示状态条；若页面已有更新时间位置，显示 `sourceUpdatedAt`，不称“实时”。
- `stale-refreshing`：使用既有浅蓝状态条外观和小型 16px spinner；显示“正在显示最近数据，并获取最新内容。”及“数据更新于 …”。无并列刷新按钮。
- `stale-not-refreshing`：同样保留最近数据和时间，标题改为“正在显示最近数据，暂未更新。”；可重试时仅一个次级描边“重试更新”。
- `miss-syncing`：无演示内容时使用同宽局部面板，三条静态/低动效 skeleton 只占内容区；标题“正在首次同步正式数据。”，附“你可以继续使用其他区域。”和一个“重试同步”。它必须是稳定说明而非无限旋转。
- `strong loading`：结果区显示“正在查询最新状态。”；请求发起按钮保留在原位置且原生 `disabled`，若保留上次值须标注“上次查询结果”。
- `empty`：使用无图或现有简洁业务图标的局部空态；只展示真实“暂无…”语义和既有筛选重置/导航，不能显示“重试”。
- `error / no fallback`：局部面板使用 `--form-control-error` 左条和同色可见标题，正文仍用 `--xlt-text`；提供一个主按钮“重试”（仅当服务端允许）。不显示原始 HTTP 文本。
- `error / invalidation`：与普通错误区分为更明确的动作结果摘要，先写“业务已提交”，再写“最新数据同步待完成”“请勿重复提交”；只显示“重试同步/查询最新状态”，不再显示提交按钮。
- `disabled`：控件使用既有禁用色与真实 `disabled`，保持原因文本（例如“正在同步”“等待重试时间结束”），禁止仅靠 50% 透明度造成不可读。
- `permission-denied`：移除私有旧内容后显示中性局部面板：“当前账号无权查看此内容。”；不显示刷新或 OAuth 动作，除非产品已有已批准入口。

`loading`、自动刷新和自动恢复使用现有 `prefers-reduced-motion` 规则：减少动效时 spinner 静止但文字、`aria-busy`、状态仍完整可见。

### 4.2 按钮、焦点与交互细节

- 主恢复操作：现有海油蓝实心按钮（`--xlt-navy-900`），hover 为 `--xlt-navy-950`；桌面最小高度 36px，窄屏/触控为 44px。
- 次级操作：白底、海油蓝文字、`#9fb4c9` 描边，不能与禁用态混淆。
- 同 operation 的重复入口在请求期间同步 disabled，保留清晰的 busy 原因；无关模块可继续操作。
- 键盘焦点沿用现有蓝色 ring；焦点不因背景刷新移动。重试成功后若按钮移除，按 UX 交接移到该区域标题；失败时保留焦点在按钮。

## 5. 页面层级与 P0 区域落点

| P0 operation | 视觉落点 | 视觉规则 |
| --- | --- | --- |
| COM-001 | 工作台 hero 的身份/问候信息 | 没有身份结果时只保留品牌/安全框架，绝不保留另一人的姓名、组织或头像语义。 |
| COM-002 | 主导航与侧栏个性化菜单 | 加载、失败或拒绝时只显示品牌、当前安全路由、跳至主内容；未确认菜单不闪现。 |
| COM-005 | 场景搜索与依赖字典的筛选控件 | 依赖字典的 select 显示 disabled 原因；自由文本输入保持可用。 |
| WB-001 | 工作台 hero、概览、推荐、培训、公告、统计面板 | 各面板可各自显示状态条，但共享一次 operation 的 busy/retry，不能给每块都加重复重试按钮。 |
| WB-002 | 热门应用推荐/搜索结果区域 | 新请求期间保留上一份仍合规内容并标明状态；只有最新请求可替换结果。 |

## 6. 响应式 Web 与未声明平台

### Web

- ≥1361px：保持既有多面板布局；状态条在对应标题下，动作可与来源时间同行但不压缩正文。
- 761–1360px：沿用现有两列收束；状态条内部可换行，按钮保持可见，不以横向滚动隐藏恢复操作。
- ≤760px：区域单列，状态信息严格按“状态 → 来源时间 → 操作”纵向排列；主/次级恢复按钮最小 44×44px，按钮之间至少 8px；固定提示不得遮挡焦点或主要内容。
- 所有宽度下 hover 只提供额外反馈，focus-visible 与文字状态始终存在；不因缩窄隐藏 trace、状态标题或操作原因。

### uni-app/原生端

任务未声明 uni-app、iOS、Android 或小程序。本交接不定义、不实施、不验收原生组件、刘海安全区、系统导航或设备断点；上述窄屏规则仅适用于浏览器 Web。若后续扩展到 uni-app，必须单独获批，并补充 44px 触控目标、安全区和原生通知规范。

## 7. 实施与验收视觉检查

1. 正式 remote 模式下，fresh/stale/miss-syncing/error/403 任一状态均不显示本地演示数据。
2. 首屏和分区状态不使用全页遮罩；页面级提示最多为一次简短活动汇总。
3. 所有六类基础状态（normal、loading、empty、error、disabled、permission-denied）都有上述明确外观；陈旧、首次同步、强一致、失效失败是其内容变体。
4. `sourceUpdatedAt` 有值时以“数据更新于 YYYY-MM-DD HH:mm”显示；无值时只显示“更新时间暂不可用”，不得伪造。
5. 文字、图标、按钮、焦点、reduced-motion 和窄屏阅读顺序均满足 UX 交接；安全 trace 只能显示已脱敏值。
