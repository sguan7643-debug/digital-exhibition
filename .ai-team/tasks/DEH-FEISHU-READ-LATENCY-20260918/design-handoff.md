# 设计汇总交接 — 正式飞书读取性能闭环

## 1. 汇总依据与结论

本文件由 Team Lead 汇总，输入为已批准的[PRD](prd.md)、[UX 交接](design/ux-handoff.md)及[UI 视觉交接](design/ui-handoff.md)。三者一致：本期不替换正式飞书多维表数据源；用服务端共享缓存、预热、SWR、可合并表读取、受控并行和精确失效解决 5–6 秒读请求，而非延长超时。

设计范围覆盖所有 65 个读取 operation：P0 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 的热态 p95 ≤2 秒；其余 operation 验证正确性、权限隔离、失效闭环与 0 个 504。9 个强一致 operation 不以缓存伪造 2 秒承诺。

## 2. 实施约束

1. 缓存只驻留进程内存：无磁盘、数据库、Redis、浏览器存储或日志持久化；真实冷启动两秒内返回 `miss_syncing`，再受控后台预热。
2. 按 PRD 的 `P0-T60`、`P0-U30`、`C-T60`、`C-U30`、`C-A30`、`S-U0`、`S-A0` 策略隔离缓存；派生响应的身份、权限、数据范围和版本维度不得跨用户复用。
3. 统一同一飞书表的原始读取与在途请求；读取投影从共享原始快照派生。上游仍最多 8 路安全并发；无依赖表并行，有依赖表不制造错误竞态。
4. 新鲜快照直接返回；合规陈旧快照立即返回并 single-flight 后台刷新；写后精确失效；强一致、权限确认和审批状态查询绕过陈旧快照。
5. 每个响应提供脱敏的 `sourceUpdatedAt`、`dataStale`、`refreshing`/等价刷新状态和安全 trace；不得返回或记录 token、Cookie、凭据、未脱敏个人信息。
6. remote 模式不得回退本地演示数据。缓存 miss、过期、失效失败和权限拒绝均 fail closed。

## 3. 页面与视觉交付合同

- 所有远程数据状态由 operation 所有者区域承载，不使用全页遮罩；页面初始并发读取只发一次汇总播报。
- `fresh` 直接呈现内容；`stale` 显示来源时间及“正在获取最新内容”或“暂未更新”；`miss_syncing` 显示稳定的“正在首次同步正式数据”；强一致显示“正在查询最新状态”。
- 写成功而失效失败，明确“业务已提交，最新数据同步待完成”“请勿重复提交”，只允许重试同步/查询，不允许再次提交。
- 保持既有 `src/style.css` 浅灰画布、白卡、海油蓝操作体系：使用既有 `--xlt-*`、`--form-control-*` 和 `.request-activity-banner`，不增加无依据的视觉令牌。
- 六项基础状态 `normal`、`loading`、`empty`、`error`、`disabled`、`permission-denied` 都有文本、可见焦点、键盘可达的恢复规则；状态不能只靠颜色/动效表示。

## 4. Web 与未声明平台

仅交付 Vue Web：≥1361px 多面板、761–1360px 收束、≤760px 单列且状态按“状态→来源时间→动作”排列。桌面恢复控件至少 36px；窄屏/触控至少 44px；状态条不得遮挡焦点，reduced-motion 不得丢失文字语义。

uni-app/iOS/Android/小程序未在任务中声明，既不实现也不验收；窄屏浏览器体验不等同于原生端支持。

## 5. 设计验收要点

1. P0 热态真实环境 p95≤2,000ms、0 个 504，正式来源可追溯。
2. 真实冷启动两秒内进入可恢复同步态，不等待到 504，不出现演示内容。
3. 陈旧、刷新失败、强一致失败、写后失效失败、401/403 的内容、可用范围、焦点和重试严格符合 UX 交接。
4. 同资源多个消费者只触发一次后台刷新；重复重试入口共享忙碌状态。
5. 65 operation 都有策略、隔离和写后失效映射；新增而未分类的 operation 默认 fail closed。

## 6. 仍待实施期取证的合同字段

实现需证明确切的 `refreshing`、`miss_syncing`、`retryAfterSeconds` 和安全 trace 载体。若服务端没有自动恢复指示，前端仅保留手动重试，不创设固定轮询。该项不是设计冲突，不影响设计评审。
