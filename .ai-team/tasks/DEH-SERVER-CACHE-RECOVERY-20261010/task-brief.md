# 任务简报 — 服务器缓存、同步任务与失败恢复链路重构

## Goal

以前置任务 `DEH-SERVER-CACHE-20261008` 的真实测试失败为证据，不再围绕单一错误码打补丁，重构本地缓存、同步任务、首页聚合与失败恢复链路，达到用户无需刷新即可取得完整正式数据的量化门槛。

## User

- 已授权数智展厅 Web 用户：有缓存时五秒内直接取得完整数据；无缓存时只等待一个后台任务并自动恢复。
- 测试与运维人员：能够区分当前可发布版本、失败任务与可回滚版本，且共享服务器资源不被失控同步消耗。

## Mode / Platforms

- Existing product。
- Web / Vue，实施范围仅后端源码、后端测试、systemd/部署配置和服务器部署包。
- Mobile/uni-app 未声明。

## Scope

1. 统一六维缓存键、规范化输入、任务键和快照键，消除 completed 后读写键不一致。
2. 任务必须先通过 success schema，再原子提交内存缓存和持久快照，最后进入 `completed`。
3. `failed`、`expired`、超时任务立即退出可复用的 in-flight 索引；有 last-known-good 时直接返回旧完整数据并静默刷新，无快照时创建新受控任务。
4. 首页五段 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 必须全部成功后一次性提交，禁止部分、空模块或代理占位冒充成功。
5. 将状态读取与业务执行隔离；存在且有权的任务状态查询始终 HTTP 200，实时撤权仍为 403，未登录仍为 401。
6. 修复飞书分页、鉴权和最多 3 路并发之间的预算竞争，保证后台任务在 25 秒内终态。
7. 五个代表 operation 完成后，相同隔离键和规范化输入立即命中缓存。
8. 增加自动化、部署包、校验值、部署/验证/回滚命令；Codex 不直接部署服务器。

## Out of Scope

- 不修改任何前端源码或前端构建产物。
- 不引入 Redis、其他数据库或新的服务器资源。
- 不缓存令牌、Cookie、Secret 或附件二进制。
- 不降低 401/403、权限、数据范围、审批、幂等、审计和强一致要求。
- 不用部分数据、代理数据或缩小测试 Base 规避验收。
- 不由 Codex 直接部署测试或生产服务器。

## Success Metric

- 强制冷首页 5/5 在 25 秒内 `completed`，结果完整包含五段。
- 暖首页至少 27/30 在 5 秒内首次 HTTP 200 完整返回。
- 所有 `/sync-jobs/{syncId}` 状态查询 0 次 HTTP 500/504。
- 轮询期间不重复 `POST /api/v1/homepage`。
- `COM-005`、`APP-002`、`MAT-001`、`WB-003`、`ADM-003` 全部成功，并在相同输入复读时直接 HTTP 200 命中缓存。
- 新请求不复用 `failed`、`expired` 或超时任务；真实页面无需刷新即可显示正式数据。
- 未登录 401、无权限或撤权 403、安全保护、CPU/内存/磁盘/并发限制全部无回归。

## Deadline / Risk

尽快完成。风险等级高；风险来源是缓存隔离、正式数据完整性、任务终态、飞书配额和共享服务器资源。所有现场性能声明必须来自新包部署后的原始逐次结果。

- 需要前置任务的源码、测试、Functional QA、Compatibility QA 和部署交接。
- 需要测试服务器上述 trace 对应的 `journalctl` 原始日志才能完成具体调用栈根因确认。
- 需要产品负责人部署新包并提供已登录测试会话执行现场验收；Codex 不直接操作服务器。
