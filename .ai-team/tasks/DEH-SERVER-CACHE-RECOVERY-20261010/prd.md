# Product Requirements Document — DEH-SERVER-CACHE-RECOVERY-20261010

## 1. 产品目标与目标用户价值

### 1.1 产品目标

在飞书多维表格继续作为唯一业务数据源、且不引入 Redis 或其他数据库的前提下，重构服务器本地缓存、同步任务与失败恢复链路，使首页和代表 operation 在真实测试环境中稳定达到以下最终效果：

- 命中完整 fresh/stale 缓存时，首次请求在 5 秒内以 HTTP 200 返回完整正式数据。
- 完全无缓存且 5 秒内无法完成飞书读取时，以 HTTP 202 交接给一个有效后台任务；浏览器只轮询该任务，任务在 25 秒内完成并携带完整结果。
- `failed`、`expired` 或超时任务不再污染后续请求；有仍处于批准 max-stale 窗口、schema 完整且通过实时安全校验的 last-known-good 时立即返回完整旧数据并静默刷新，无合格 last-known-good 时创建新的受控任务。
- 首页 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 五段只以原子完整结果对外成功。
- 登录、权限、数据范围、审批、幂等、审计、强一致 operation 与已批准资源限制不因缓存而被绕过或降低。

### 1.2 目标用户价值

- **已授权数智展厅 Web 用户：** 有缓存时直接取得完整正式数据；冷启动时只经历一次 loading 和一次后台任务，完成后页面自动展示正式数据，无需刷新或重新点击。
- **测试与运维人员：** 可通过明确的任务状态、日志、量化结果、部署包校验值与回滚材料判断版本是否可发布，并避免失败任务或失控同步持续消耗共享服务器与飞书配额。

## 3. 范围边界

### 3.1 继承的固定基线

1. **重试与总预算：** 每个同步任务总尝试最多 3 次，初次尝试计入；最多自动重试 2 次；两次重试前分别等待 500ms、1000ms，退避上限为 1000ms。任务排队、所有分页、实时鉴权等待、每次尝试和退避必须共同计入同一 25 秒总预算。工程设计只能确定哪些错误可重试以及如何在预算内调度，不得改变尝试次数、退避数值或总预算。
2. **TTL/max-stale：** 普通/租户缓存 fresh 60 秒、max-stale 15 分钟；用户/管理缓存 fresh 30 秒、max-stale 5 分钟。不得在本任务中延长这些窗口。
3. **operation 策略：** 继续使用前置已批准策略文件中明列的 54 个可缓存 operation 和 11 个强一致、禁止缓存 operation；任何未列出的 operation 默认不缓存。本任务不得通过增删名单规避验收。
4. **last-known-good：** 仅指年龄仍在对应 operation 批准 max-stale 窗口内、success schema 完整，并在返回前通过当前实时登录身份、权限集合和数据范围校验的完整快照或缓存；超过 max-stale、schema 不完整或授权不匹配的数据不得对外服务。
5. **强制冷读 QA 协议：** 5 次正式冷读样本必须使用同一固定身份、同一 Base、同一权限集合、同一数据范围和同一规范化输入；每次仅失效目标六维键及对应首页聚合缓存，不清空共享缓存。等价独立身份只能作为备用方法，必须预先证明其权限集合、数据范围、输入和数据量完全等价并单独记录，且不得与默认身份样本混入同一组 5 次结果。

### 3.2 In scope

1. 分析前置失败任务、trace 与服务器日志，形成可追溯的根因时间线；在日志到位前保持“事实/假设”边界。
2. 统一单接口、批量接口、首页聚合、任务合并与持久快照使用的六维隔离键：租户、用户、权限集合、数据范围、operation、规范化输入。
3. 统一输入规范化规则，保证语义相同输入在读、写、任务合并、快照恢复和失效路径上得到同一稳定键；任一隔离维度不同则禁止复用。
4. 将同步任务成功顺序固定为：完整读取 → success schema 校验 → 原子提交内存缓存与持久快照 → 验证可命中 → 标记 `completed` 并保存完整 `result`。
5. 使 `failed`、`expired`、超时任务立即退出可复用的 in-flight/merge 索引；后续普通请求不得返回“202 + 已失败任务”。
6. 有符合固定 max-stale、schema 和实时安全校验条件的 last-known-good 完整缓存或快照时立即 HTTP 200 返回旧完整数据，并仅在后台静默刷新；无合格 last-known-good 时创建新的受控任务。
7. 首页五段 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 全部成功并通过 schema 校验后，才原子提交首页缓存和任务 `completed.result`。
8. 修复 `COM-001`、`WB-003` 的分页、实时鉴权、队列等待、同步并发与 25 秒总预算竞争，并保持同步并发最多 3；所有排队、分页、尝试和固定退避均计入同一 25 秒。
9. 使 `/api/v1/sync-jobs/{syncId}` 与 `/api/v1/operations/sync-jobs/{syncId}` 对“已存在且当前用户有权查询”的任务始终以 HTTP 200 返回 `queued/running/completed/failed/expired`；临时上游慢或错误不得泄漏为 500/504。
10. 保证状态查询只做任务归属和实时身份/权限/数据范围校验，不重新执行原业务 operation。
11. 保证 `COM-005`、`APP-002`、`MAT-001`、`WB-003`、`ADM-003` 完成后，相同六维隔离键与规范化输入的下一次读取直接命中完整缓存。
12. 保留服务重启后的持久快照恢复；`ready` 只有在恢复完成且恢复数据能够实际命中后才可返回就绪。
13. 增加失败任务不复用、缓存提交顺序、首页五段原子性、状态 HTTP 合同、分页超时、重启恢复、权限撤销和资源上限的自动化测试。
14. 生成纯后端服务器部署包、SHA-256、逐条部署/验证/回滚命令；在产品负责人部署后收集真实测试环境原始证据。

### 3.3 Out of scope

1. 修改任何前端源码、根 `dist`、组件、样式、路由、文案或视觉资源。
2. 引入 Redis、外部缓存集群、独立数据库、新业务数据源或替换飞书多维表格。
3. 缓存飞书令牌、Cookie、Secret、审批凭据或附件二进制文件。
4. 削弱登录、权限、数据范围、审批、幂等、审计、强一致 operation 或写后校验。
5. 用部分数据、空模块、受控代理占位、缩小测试 Base、减少首页五段或降低量化门槛冒充成功。
6. 由 Codex 直接登录测试/生产服务器执行部署、发布、生产配置变更或现场回滚。

## 4. 主要用户流

### 4.1 入口

已授权用户进入真实首页，或调用一个受支持的普通读取 operation。后端先实时确认会话、任务归属、权限集合和数据范围，再计算六维缓存键。

### 4.2 决策与动作

1. **命中完整 fresh/stale 缓存：**
   - 首次响应在 5 秒内 HTTP 200 返回完整正式数据。
   - 如需刷新，仅创建或合并后台静默刷新；不得将当前用户重新送入 202 流程。
2. **没有可用缓存：**
   - 后端开始或合并一个与完整六维键一致的有效运行任务。
   - 若 5 秒内完成，则 HTTP 200 返回完整结果。
   - 若 5 秒内未完成，则 HTTP 202 返回有效 `syncId` 和正整数 `pollAfterMs`；浏览器仅轮询该任务。
3. **任务运行：**
   - 后端在最多三路同步并发和 25 秒总预算内完成排队、分页、实时校验、success schema 校验与缓存提交。
   - 总尝试最多 3 次且初次计入；最多重试 2 次，重试前固定退避 500ms、1000ms，所有尝试与退避共同占用该 25 秒预算。
   - 状态查询只读取任务状态并执行实时安全校验，不重跑业务 operation。
4. **任务成功：**
   - 内存缓存和持久快照已成功提交且可按同一键命中后，任务才进入 `completed`。
   - `completed.result` 保持原业务成功响应结构；前端自动结束 loading 并展示正式数据。
5. **任务失败、过期或超时：**
   - 该任务立即退出可复用任务索引。
   - 若存在仍在批准 max-stale 内、schema 完整并通过实时安全校验的 last-known-good，新的普通请求 HTTP 200 返回完整旧数据并静默刷新。
   - 若不存在合格 last-known-good，新的普通请求创建新的受控任务，不返回旧失败 `syncId`。
6. **权限变化：**
   - 未登录返回 401；无权限、任务 owner 不匹配或实时撤权返回 403。
   - 缓存、快照或旧任务结果均不得绕过该边界。

### 4.3 预期结果

用户在运行期仅看到既有 loading；成功后无需刷新即可看到完整正式数据。测试与运维人员可从逐次请求、任务状态、日志、缓存命中证据和资源观测判断是否达到发布门槛。

## 5. 状态清单

| 状态 | 触发条件 | 后端行为 | 用户可见结果 |
| --- | --- | --- | --- |
| Success / warm | 命中同六维键的完整 fresh/stale 缓存 | 实时安全校验后，5 秒内 HTTP 200 返回完整数据；需要刷新时后台静默执行 | 直接展示正式数据，不进入新的 loading/202 流程 |
| Loading / cold | 无可用缓存，业务读取尚在 5 秒等待窗口内 | 后台任务持续执行，不因浏览器请求结束而取消 | 保留现有 loading 气泡 |
| Pending / handed-off | 5 秒内未完成但任务仍有效运行 | HTTP 202 返回 `syncId`、正整数 `pollAfterMs`；后续只查询任务状态 | loading 持续，不重复提交原业务请求 |
| Queued / running | 已存在且有权任务尚未完成 | 状态接口 HTTP 200，body 使用 `queued` 或 `running` | loading 保持，不出现错误或首次同步提示 |
| Completed | 完整结果已通过 schema，内存与快照已原子提交并可命中 | 状态接口 HTTP 200、`state=completed`、携带完整 `result` | loading 自动消失并展示正式数据 |
| Stale fallback | 刷新失败或超时，但存在仍在对应 max-stale 内、schema 完整且实时授权匹配的 last-known-good | 普通读取 HTTP 200 返回完整旧数据；失败任务退出索引；后台静默刷新 | 页面保持完整可用，不停在“数据更新失败” |
| Empty | 飞书完整分页成功且正式结果确实为零记录 | 按 success schema 缓存并返回真实空集合 | 显示既有真实空态；不得把超时、权限失败或部分分页伪装为空 |
| Failed | 不可恢复任务失败，且状态记录仍在保留期 | 状态接口对有权用户 HTTP 200、`state=failed`、结构化 `error`；任务不可再合并复用 | 当前 release 验收样本出现该状态即不通过；新普通请求按 last-known-good/新任务规则恢复 |
| Expired | 任务终态记录达到过期条件 | 状态接口对仍可识别且有权任务 HTTP 200、`state=expired`；任务不可复用 | 新普通请求不取得旧 `syncId` |
| Authentication required | 无有效登录身份 | HTTP 401；不读取或释放缓存/任务结果 | 进入既有登录/重新授权路径 |
| Permission denied | 用户无权限、owner 不匹配、数据范围不匹配或权限被撤销 | HTTP 403；不释放缓存、快照或任务结果 | 进入既有访问受限路径 |
| Disabled | 既有业务规则导致控件不可用 | 缓存与同步改造不新增或改变 disabled 规则 | 保持既有表现；本任务不改前端 |
| Service warming | 服务启动后正在恢复持久快照 | `/health/ready` 在恢复完成且可实际命中前不得返回 ready | 不把尚不可用的服务标记为就绪 |

## 6. 明确非目标 / 不得执行事项

1. 不以修补某个错误码或隐藏错误文案作为完成标准。
2. 不把 HTTP 500/504 改写为表面 HTTP 200，却仍返回错误任务、部分数据或不可完成状态。
3. 不允许在标记 `completed` 后异步补写缓存；缓存与快照提交是 completed 的前置条件。
4. 不允许 `failed`、`expired`、超时任务继续留在可复用 single-flight/merge 索引中。
5. 不允许首页任一子 operation 失败时写入部分首页缓存或成功结果。
6. 不允许状态轮询重新调用首页或原 operation。
7. 不允许以延长浏览器等待到 5 秒以上、放宽 25 秒任务期限或增加并发突破资源限制来换取通过。
8. 不允许减少 success schema 字段、使用受控代理数据或空模块代替正式数据。
9. 不允许修改前端或 `dist` 来掩盖后端失败恢复问题。
10. 不允许在真实测试环境证据未达到全部门槛时标记 QA 或 release 通过。
11. 不允许延长 TTL/max-stale、改变 54 个可缓存/11 个强一致 operation 基线，或把未列出的 operation 默认加入缓存。
12. 不允许改变总尝试最多 3 次、最多重试 2 次、500ms/1000ms 固定退避与 25 秒共同预算合同。

## 7. 开放问题与 scope 批准所需决定

### 7.1 Scope 决策状态

固定重试参数和强制冷读 QA 协议均直接继承已批准基线，不再作为待用户重新决定的开放问题。当前没有需要新增产品能力、改变固定参数或降低验收门槛的开放问题；用户仍需对本 PRD 整体作出明确 scope 决策。scope 未批准前，不进入设计或开发。

### 7.2 验收依赖、责任人与门禁

| 依赖 | 责任人 | 最迟提供阶段 | 缺失时的门禁结果 |

## 8. Given / When / Then 验收标准

### AC-01：完整缓存首次命中

**Given** 已登录用户通过实时身份、权限和数据范围校验，operation 属于前置策略明列的 54 个可缓存项，且六维键存在 schema 完整的 fresh 缓存，或存在仍在对应 max-stale 内的合格 last-known-good；
**When** 用户以相同租户、用户、权限集合、数据范围、operation 和规范化输入发起读取；
**Then** 首次响应必须在 5 秒内以 HTTP 200 返回符合原 success schema 的完整正式数据，且后台刷新不得让该请求进入 HTTP 202；普通/租户使用 fresh 60 秒、max-stale 15 分钟，用户/管理使用 fresh 30 秒、max-stale 5 分钟，11 个强一致项和未列出项不得命中业务缓存。

### AC-02：完全冷请求五秒交接

**Given** 当前六维键没有可用内存缓存或持久快照；
**When** 飞书完整读取在首次请求 5 秒内未完成；
**Then** 服务必须在 5 秒内返回 HTTP 202、有效运行中的 `syncId` 和正整数 `pollAfterMs`，后台任务继续运行且不因浏览器请求结束而取消；任务总尝试最多 3 次（初次计入）、最多重试 2 次、固定退避 500ms/1000ms，排队、分页、尝试和退避均计入同一 25 秒。

### AC-03：首页冷任务完成门槛

**Given** 使用同一固定 Base、同一固定授权身份、同一权限集合、同一数据范围和同一规范化输入连续执行 5 次首页强制冷读；
**When** 每次仅失效目标六维键及对应首页聚合缓存、不清空共享缓存，并且只轮询首次响应返回的同一个 `syncId`；
**Then** 5/5 必须在任务创建后 25 秒内进入 `completed`，`completed.result` 必须包含 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 五段完整正式数据，且无需手动刷新。

备用独立身份只有在样本开始前已证明权限集合、数据范围、输入和数据量完全等价并单独记录时可使用，且不得与默认身份混入同一组 5 次样本。

### AC-04：任务状态 HTTP 合同

**Given** `/api/v1/sync-jobs/{syncId}` 或 `/api/v1/operations/sync-jobs/{syncId}` 对应任务真实存在，且当前用户有权查询；
**When** 任务处于排队、运行、完成、失败或过期状态，或实时鉴权暂时变慢；
**Then** 每次状态查询必须返回 HTTP 200，并仅通过 `queued/running/completed/failed/expired` 表达状态，不得出现 HTTP 500/504；未登录仍为 401，明确无权限或撤权仍为 403。

### AC-05：状态轮询不重跑业务

**Given** 首页首次请求已返回 HTTP 202 和 `syncId`；
**When** 客户端持续查询该任务直至终态；
**Then** Network 和服务日志中只能有一次原始 `POST /api/v1/homepage`，状态查询不得重新执行首页或其原业务 operation。

### AC-06：失败任务退出复用索引

**Given** 某六维键对应任务已经 `failed`、`expired` 或超过任务预算；
**When** 相同用户和输入再次发起普通读取；
**Then** 服务不得返回旧失败 `syncId`，不得把旧任务表示为运行中；仅当 last-known-good 仍在该 operation 批准 max-stale 内、schema 完整且通过当前实时身份/权限/数据范围校验时，才立即 HTTP 200 返回完整旧数据并静默刷新；否则必须创建新的受控任务并返回新的 `syncId`。

### AC-07：首页原子完整提交

**Given** 首页同步任务正在读取五个子 operation；
**When** 任一子 operation 未完成、分页不完整、schema 失败、超时或权限校验失败；
**Then** 不得写入新的首页内存缓存、持久快照或 `completed.result`；只有五段全部成功并通过 schema 后，才能一次性提交完整首页并标记任务 `completed`。

### AC-08：缓存提交先于 completed

**Given** 任一可缓存 operation 的后台任务已取得完整成功结果；
**When** 服务准备进入 `completed`；
**Then** 必须先使用统一六维键成功提交内存缓存和持久快照，并验证相同键可命中，之后才记录 `completed` 与完整 `result`；提交失败时不得标记 `completed`。

### AC-09：五个代表 operation 一致命中

**Given** `COM-005`、`APP-002`、`MAT-001`、`WB-003`、`ADM-003` 分别使用适用且有权的固定身份完成首次完整读取；
**When** 每个 operation 完成后立即以完全相同六维隔离键和规范化输入复读；
**Then** 五个 operation 都必须在 5 秒内首次 HTTP 200 返回完整 success schema 数据，不得再次返回 HTTP 202；缓存资格必须遵守既有 54 个可缓存/11 个强一致/未列默认不缓存基线，强一致或未列 operation 不得被错误缓存。

### AC-10：暖首页量化门槛

**Given** 首页完整缓存已经形成，测试 Base、身份、权限集合、数据范围与输入保持不变；
**When** 连续执行 30 次暖首页读取并保存逐次原始结果；
**Then** 至少 27/30 必须在 5 秒内首次 HTTP 200 返回完整五段数据，且所有状态查询累计 0 次 HTTP 500/504。

### AC-11：真实页面自动恢复

**Given** 已登录用户重新加载真实首页，且首次请求返回 200 或 202；
**When** 用户不刷新、不重新点击，客户端保持现有 loading 并只轮询原任务；
**Then** loading 必须自动消失并展示完整正式数据，不得显示“正式飞书数据正在首次同步”“数据缺失”，也不得停在“数据更新失败”并要求用户手动刷新。

### AC-12：真实空结果与失败区分

**Given** 飞书完整分页成功且授权范围内确实为零记录；
**When** operation 完成 schema 校验；
**Then** 服务以 HTTP 200 返回并缓存合法空集合；超时、部分分页、权限失败或同步未完成不得被转换为空集合。

### AC-13：实时安全边界

**Given** 缓存、快照或旧任务结果已经存在；
**When** 请求者未登录、无权限、任务 owner 不匹配、数据范围变化或权限被撤销；
**Then** 未登录必须返回 401，明确无权限/撤权必须返回 403，且不得释放旧授权范围的数据；审批、幂等、审计、写入与强一致 operation 继续实时校验。

### AC-14：重启恢复与 ready

**Given** 服务磁盘中存在合法持久快照；
**When** 服务重启并恢复快照；
**Then** `/health/ready` 只有在恢复完成且代表缓存可实际命中后才返回 ready，重启后相同暖请求不得全部重新进入冷启动。

### AC-15：资源与敏感数据限制

**Given** 冷任务、后台刷新、状态轮询和快照持久化同时运行；
**When** 执行自动化与真实环境资源观测；
**Then** CPU 上限保持 1.5 核、进程内存不超过 2GB、缓存目录不超过 3GB、同步并发不超过 3，且缓存/包/日志中不保存飞书令牌、Cookie、密钥或附件二进制；若运维未提供现场资源证据，本 AC 的现场部分必须为 `blocked/not executed`，不得 release。

### AC-16：根因与 trace 证据

**Given** 测试环境运维已提供失败 syncId 和 trace 对应的原始服务器日志；
**When** 完成修复交接；
**Then** 必须提供每条 trace 的时间线、失败子 operation、分页/鉴权/队列/deadline 证据、对应代码路径及修复关联；没有日志支持的结论必须继续标记为假设，日志未提供时本 AC 必须为 `blocked/not executed` 且不得 release。

### AC-17：交付物与变更边界

**Given** 后端修复和自动化测试全部完成；
**When** 生成交付物；
**Then** 必须提供修改文件清单、测试命令与结果、纯后端服务器部署包、SHA-256、逐条部署/验证/回滚命令，并证明前端源码与根 `dist` 零变更；Codex 不直接部署服务器。

### AC-18：发布阻断条件

**Given** 新包已由产品负责人部署并执行真实环境验收；
**When** 冷首页不是 5/5 在 25 秒内 completed、暖首页低于 27/30 在 5 秒内首次 HTTP 200、任一有权状态查询出现 500/504、五个代表 operation 任一失败或复读不命中、真实首页需要手动刷新、401/403 回归或资源上限被突破；
**Then** 该版本必须保持不可发布并触发回滚/继续修复，不得记录 QA 或 release 通过；若运维、产品负责人、业务/飞书管理员或 QA 的任一必需输入未提供，则对应 AC 必须为 `blocked/not executed`，同样不得 release。
