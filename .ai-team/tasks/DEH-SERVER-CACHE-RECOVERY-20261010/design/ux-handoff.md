# UX / Interaction Handoff — 缓存、同步任务与失败恢复链路

## 1. 文档定位与约束

- 任务：`DEH-SERVER-CACHE-RECOVERY-20261010`
- 阶段：`design`
- 平台：Web / Vue；mobile、uni-app 与其他移动目标未声明。
- 批准依据：[task.json](../task.json)、[task-brief.md](../task-brief.md)、已批准的 [prd.md](../prd.md)。
- 设计目的：定义现有 Web 页面能够观察到的后端交互合同，使缓存命中、冷任务接管、任务完成、失败恢复和安全拒绝形成一个无需手动刷新的完整用户流程。
- 硬边界：不新增或修改页面、路由、组件、布局、视觉资源、文案、UI tokens、前端源码或根 `dist`；保留现有页面结构、loading 气泡、一次原请求及同一 `syncId` 自动轮询方式。
- 本文件不构成设计批准、视觉签署、开发路由或发布批准。

## 2. 行为证据与设计依据

### 2.1 已批准产品合同

1. 同一租户、用户、权限集合、数据范围、operation 与规范化输入命中完整 fresh/stale 缓存时，首次响应在 5 秒内以 HTTP 200 返回完整正式数据。
2. 完全无缓存且 5 秒内不能完成读取时，HTTP 202 交接给一个有效运行任务；客户端只轮询该 `syncId`，任务在创建后 25 秒内 `completed` 并携带完整 `result`。
3. 首页只有在 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 五段全部成功并通过 schema 校验后，才可作为一个完整结果对外成功。
4. `failed`、`expired` 或超时任务不再被后续普通请求复用；合格 last-known-good 直接服务并静默刷新，否则新建受控任务。
5. 已存在且当前用户有权查询的任务，两个状态接口始终使用 HTTP 200 和 `queued/running/completed/failed/expired` 表达状态；未登录仍为 401，明确无权限或撤权仍为 403。
6. 状态查询只读取任务状态并实时校验任务归属、身份、权限与数据范围，不重新执行首页或原 operation。
7. `/health/ready` 只有在持久快照恢复完成且代表缓存能够实际命中后才可进入 `ready`。

### 2.2 前置现场证据

- [Functional QA](../../DEH-SERVER-CACHE-20261008/functional-qa-report.md) 证明现有前端只提交一次 `POST /api/v1/homepage`，之后只轮询同一 `syncId`；loading 会在终态结束，前端轮询方式本身正确。
- 同一报告记录了错误用户结果：冷首页仅 4/5 完成、暖首页 0/10 首次 HTTP 200、失败任务被后续请求复用、状态查询出现 HTTP 500、页面 45 秒后仍停留在“数据更新失败”。
- [Compatibility QA](../../DEH-SERVER-CACHE-20261008/qa-report.md) 将上述问题归纳为四个阻断缺陷；当前交互设计必须修复后端可观察结果，不得通过改前端、改文案或降低门槛掩盖。
- 前置 QA 已观察到 `normal`、`loading`、`error` 和未登录路径；真实 `empty`、`disabled`、`permission-denied` 及完整读屏矩阵因缺少受控身份或环境未完成，仍需在本任务 QA 中保留为真实验证项。

## 3. 信息架构

现有信息架构不变：用户进入现有页面，页面发起一次业务读取，只感知现有 loading、完整成功结果、真实空结果、终态错误、登录要求或权限拒绝。缓存类型、快照、任务合并、内部重试、分页、并发、`syncId` 和 trace 均为服务端内部信息。

不新增同步进度页、任务详情页、倒计时、重试按钮或手动刷新入口；不展示缓存来源、快照年龄、任务编号、重试次数或分页进度；不因后台刷新禁用页面、遮挡完整数据或重新显示 loading。

## 4. 核心用户流程

### 4.1 Warm：完整 fresh/stale 缓存命中

1. 用户进入页面或执行既有读取动作，现有 loading 生命周期开始。
2. 后端实时校验登录身份、权限集合和数据范围。
3. 后端在 5 秒内以 HTTP 200 返回原 success schema 的完整数据。
4. 页面展示正式数据，loading 自动结束。
5. 如需刷新，只在服务端静默执行；用户不进入 HTTP 202 流程，不出现第二次 loading、提示或焦点移动。

### 4.2 Last-known-good：静默恢复

1. 当前刷新失败、超时，或此前任务已进入失败终态。
2. 若存在仍在批准 max-stale 内、schema 完整且通过实时安全校验的 last-known-good，普通读取直接 HTTP 200 返回完整结果。
3. 页面进入 `normal` 或真实 `empty`，不显示警告、失败、代理数据或缓存来源。
4. 后端可静默刷新；刷新失败不得替换、清空或降级页面已展示的完整结果。
5. 静默刷新不触发浏览器轮询，也不要求用户刷新或重新点击。

### 4.3 Cold：5 秒内完成

1. 无可用缓存时，现有 loading 连续显示。
2. 后端读取正式飞书数据并完成全部分页、schema 校验及缓存提交。
3. 若在 5 秒内完成，直接 HTTP 200 返回完整结果。
4. 非空结果进入 `normal`；经完整分页确认的零记录进入 `empty`；loading 自动结束。

### 4.4 Cold：HTTP 202 接管与同一任务轮询

1. 5 秒内未完成但任务仍有效运行时，初始请求返回 HTTP 202、有效 `syncId` 和正整数 `pollAfterMs`。
2. 前端不再次提交 `POST /api/v1/homepage` 或原 operation，只查询同一 `syncId`。
3. `queued/running`：状态接口 HTTP 200；同一个 loading 生命周期保持，不显示错误、不重复公告、不更换 `syncId`。
4. 同一任务内部受控重试对用户透明，仍使用原 `syncId`；排队、分页、重试和退避共同受 25 秒总预算约束。
5. `completed`：状态接口 HTTP 200，并直接携带原业务成功结构的完整 `result`；前端消费结果、自动结束 loading 并展示数据，不重新调用原业务接口。
6. `failed/expired`：状态接口仍为 HTTP 200；前端结束 loading 并进入既有 `error`，不得继续伪装 `running` 或无限轮询。
7. 正式验收中的 cold 首页必须 5/5 在 25 秒内 `completed`；出现失败、过期或超时即阻断版本，不能用错误态可显示替代成功门槛。

### 4.5 失败任务隔离与后续请求

1. `failed`、`expired` 或超时任务立即退出可复用任务索引。
2. 后续正常读取有合格 last-known-good 时 HTTP 200 返回完整旧数据并静默刷新；无合格快照时创建新任务和新 `syncId`。
3. 后续请求不得得到“HTTP 202 + 旧失败 `syncId`”，也不得因旧任务持续停在错误状态。
4. 恢复不增加前端按钮或手动刷新要求；真实首页必须由同一请求生命周期自动取得完整结果。

### 4.6 首页原子完整展示

1. 首页 loading 覆盖整个聚合请求，不按五个子 operation 分裂提示。
2. 五段全部成功、分页完整、schema 有效且缓存/快照可按同一隔离键命中后，才返回 HTTP 200 或 `completed.result`。
3. 任一段失败、超时、权限不匹配或不完整时，不释放部分首页，不以空白模块或代理占位冒充成功。
4. 用户只会看到完整首页、合格 last-known-good 完整首页，或真实终态错误，不会看到模块逐段跳变。

### 4.7 页面离开

- 用户按现有方式离开时不拦截导航；前端释放当前页面 loading token，旧 loading 不跨页面残留。
- 服务端已接管任务可继续执行，但不得主动拉回用户，也不得跨身份或数据范围复用。

## 5. 后端可观察交互合同

| 场景 | HTTP / body 合同 | 页面行为 |
| --- | --- | --- |
| 完整 fresh/stale 或合格 last-known-good | HTTP 200；原 operation 完整 success schema | 展示完整正式数据；后台刷新静默 |
| 冷读 5 秒内完成 | HTTP 200；完整 success schema | 自动进入 `normal` 或真实 `empty` |
| 冷读 5 秒时仍运行 | HTTP 202；有效运行 `syncId`；正整数 `pollAfterMs` | 保持同一 loading，只轮询该任务 |
| 任务排队/运行 | 状态接口 HTTP 200；`state=queued/running` | 保持 loading，不重发原请求 |
| 任务完成 | 状态接口 HTTP 200；`state=completed`；完整 `result` | 自动展示并结束 loading |
| 任务失败/过期 | 状态接口 HTTP 200；`state=failed/expired`；失败时含结构化 `error` | 结束 loading，进入既有 error；任务不再可复用 |
| 未登录 | HTTP 401 | 进入既有登录/重新授权路径，不释放缓存或任务结果 |
| 无权限、owner 不匹配、数据范围变化或撤权 | HTTP 403 | 进入 permission-denied，不泄露缓存、快照或任务结果 |
| 服务恢复中 | `/health/ready` 为非 ready / `warming` | 实例不应承接正常业务流量，不释放半恢复缓存 |
| 恢复完成且代表缓存可命中 | `/health/ready` 为 ready | 实例可承接正常业务流量 |

补充约束：

- `/api/v1/sync-jobs/{syncId}` 与 `/api/v1/operations/sync-jobs/{syncId}` 使用同一状态语义。
- 对存在且有权任务，临时上游慢、鉴权等待或任务自身失败不得泄漏为 HTTP 500/504。
- `completed.result` 不再包一层新结构；状态轮询不得重新执行首页或原 operation。
- HTTP 404 只用于任务不存在；401/403 安全语义不得被 HTTP 200 状态合同吞掉。

## 6. 六种必备状态

| 状态 | 触发条件 | 内容行为 | 允许动作与恢复 | 焦点、顺序与公告 |
| --- | --- | --- | --- | --- |
| `normal` | warm HTTP 200、cold 5 秒内 HTTP 200、轮询 `completed`，或合格 last-known-good 非空结果 | 一次性展示完整正式数据；不展示缓存来源或后台刷新信息 | 保留既有操作；后台刷新不阻塞、不改变当前内容 | 缓存命中、轮询和后台刷新不移动焦点；只产生一次终态内容更新，不播报技术信息 |
| `loading` | 初始读取、5 秒等待，或同一任务 `queued/running` | 只保留现有 loading 气泡和“请求处理中”语义 | 用户可等待或离开；无需刷新、重复点击或操作任务 | 开始礼貌公告一次；轮询、内部重试和状态切换不重复公告；不抢焦点、不形成焦点陷阱 |
| `empty` | 正式飞书数据完成全部分页、schema 与授权校验后确认为零记录 | 使用现有真实空态；未完成、超时、部分分页和权限失败不得为空 | 保留既有空态动作，不新增动作 | 与 loading/error 区分；只公告一次真实空结果，不因后台刷新跳焦 |
| `error` | 当前任务最终 `failed/expired` 且无可服务 last-known-good，或其他非权限终态错误 | 结束 loading，进入现有结构化错误；不显示空态、代理占位、部分首页或首次同步提示 | 不新增手动刷新要求；后续独立读取按 last-known-good/新任务恢复，不复用旧任务 | 错误只公告一次；不自动跳转、不循环聚焦；内部重试不得提前触发错误公告 |
| `disabled` | 仅由既有业务规则或原控件条件触发 | 沿用现有禁用内容；缓存、刷新和轮询不得新增页面级 disabled | 保留原启用条件，不新增恢复控件 | 维持原 Tab 顺序和语义化禁用，不得视觉禁用但仍可触发 |
| `permission-denied` | 已登录但无权限、owner/数据范围不匹配或撤权，HTTP 403 | 停止释放缓存、快照、旧任务和业务结果；不显示空集合或任务细节 | 不自动重试；沿用现有访问受限/重新授权路径 | loading 结束；访问受限公告一次；拒绝内容操作不进入后续 Tab 顺序 |

HTTP 401 属于既有 authentication-required 流程，不归并为 `error`、`empty` 或 `permission-denied`。服务 `warming` 属于运维就绪态，不新增终端用户页面状态。

## 7. 内容规则

保留现有 loading 气泡、“请求处理中”语义、正常内容、真实空态、结构化错误和访问受限承载。

禁止出现：

- “正式飞书数据正在首次同步”及要求稍后手动重试的同义提示。
- “数据缺失”及把同步未完成、部分分页、权限失败或 schema 失败描述为无数据。
- “当前页面使用受控代理数据”或以代理/占位内容冒充正式数据。
- `syncId`、trace、缓存键、快照、TTL、分页、重试次数和内部错误栈等技术信息。
- 后台静默刷新触发 loading、成功/失败气泡、焦点变化或页面内容清空。

## 8. 键盘、焦点与辅助技术

- 本任务不新增可聚焦元素，不改变既有 Tab 顺序、键盘命令、浏览器返回或导航行为。
- loading 不抢焦点、不形成焦点陷阱；五秒接管、轮询、内部重试、缓存命中和后台刷新都不移动焦点。
- `completed`、真实 `empty`、`error` 和 `permission-denied` 只执行现有状态边界的单次终态焦点行为，不因响应重放多次跳焦。
- 请求开始由现有状态区礼貌公告一次；`queued/running` 保持同一 busy 生命周期，不按轮询或重试重复公告。
- `completed` 结束 busy 并按现有内容更新方式呈现结果，不追加“缓存命中/同步完成”公告。
- `empty`、`failed/expired`、403 分别由现有对应状态区公告一次；401 沿用登录流程，不先公告空态或一般错误。
- 页面离开时异步任务不阻止导航，旧请求活动状态必须释放。

前置 QA 尚未完成真实 empty、disabled、permission-denied 与读屏全矩阵。因本任务禁止前端变化，QA 必须验证现有状态区是否满足上述焦点和公告行为；若既有前端不满足，应记录独立前端无障碍缺陷，不得在本任务中暗改，也不得用未执行替代通过。

## 9. Web 与移动端差异

- Web 是唯一声明平台，继续使用现有 Vue 页面、全局请求活动状态和自动轮询方式；桌面与窄 Web 的布局、导航、鼠标、键盘和浏览器行为保持现状。
- Mobile / uni-app 未声明，不适用；不得推断移动端已支持这些轮询、loading、焦点或公告行为。

## 11. 开放问题、冲突与下游边界

## 12. 供设计批准的关键交互决策

1. 前端页面、loading 气泡和同一 `syncId` 轮询方式原样保留，前端源码与 `dist` 零变化。
2. warm 与合格 last-known-good 统一表现为 5 秒内 HTTP 200 完整成功；后台刷新完全静默。
3. cold 超过 5 秒只交接一次有效任务，客户端不重发原请求；`completed.result` 自动展示，25 秒内未成功即阻断版本。
4. 首页五段只有原子完整成功，部分数据、空模块和代理占位均不可见。
5. 失败或过期任务不再被新请求复用；状态查询对有权任务始终 HTTP 200，同时保留 401/403 实时安全边界。
6. 六态保持现有页面承载，并明确单次焦点/公告、无重复提示、无手动刷新要求。
