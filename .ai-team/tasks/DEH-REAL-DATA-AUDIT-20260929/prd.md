# 系统真实数据展示与静态假数据清理审计 PRD

## 1. 产品目标与目标用户价值

### 产品目标

- **Fact：** 审计并修复 Web 端系统中“已有真实数据，但界面仍展示静态测试数据、示例编码或错误回退值”的问题。
- **Fact：** 所有正常态页面的用户可见业务数据，应来自当前飞书授权会话或既有真实接口；真实字段缺失时，应展示明确空值、空集合或空态，不得伪造数据。
- **Fact：** 通过逐页面/逐字段真实数据审计矩阵、生产源码扫描、自动化回归和测试环境部署包构建，证明静态测试身份、部门或伪造业务记录不会进入正式构建；范围验收必须以审计矩阵不存在未处置项为门槛。

### 目标用户与价值

- **Fact：** 目标用户为通过飞书授权进入数智产品展厅的普通用户、运营人员和管理员，包括查看个人、应用、申请、消息、培训、运营及人才信息的用户。
- **Fact：** 用户应看到与当前授权账号和真实业务记录一致的姓名、组织、部门、邮箱、电话、状态、编码及业务数据，避免因静态值或错误映射造成身份误认、业务误判或数据可信度下降。

## 3. 范围边界

### In Scope

1. 扫描全部 `src/pages`、`src/components`、共享前端状态和展示映射中的用户可见静态测试值、示例编码、错误回退值和伪造业务记录。
2. 区分以下两类内容：
   - 会进入正式构建并在正常态展示的静态假数据；
   - 仅存在于测试文件中的受控夹具。
3. 对照现有 OAuth 会话、飞书通讯录、多维表只读接口及 operation contracts，核对接口响应字段、页面读取计划和最终展示字段。
4. 修复正常态页面中的静态姓名、组织、部门、邮箱、电话、状态、编码及伪造业务记录，使其展示当前授权用户或真实接口数据。
5. 当真实字段为空、缺失或无记录时，按现有页面语境展示“—”、空集合或明确空态。
6. 覆盖个人、应用、申请、消息、培训、运营及人才相关的现有 Web 页面和共享组件，不新增业务能力。
7. 增加防回归自动化测试，验证静态假数据不进入正式构建、真实字段映射正确、缺失数据安全降级。
8. 执行 Web 全量回归并重新构建测试环境部署包。
9. 建立并完成“真实数据展示审计矩阵”，逐页面、逐共享组件、逐用户可见字段记录审计结论。矩阵至少包含：
   - 页面路由或入口、页面/组件名称及触发状态；
   - 用户可见字段及数据类别；
   - 当前读取路径、当前回退值或静态值；
   - 权威真实数据源、适用合同及具体字段；
   - 数据源优先级与字典转码规则；
   - 缺失值、加载、错误和权限不足时的展示行为；
   - 是否发现静态值、来源冲突或跨会话串用风险；
   - 处置结论、涉及文件或“不需要修改”的理由；
   - 对应自动化测试、人工验证或构建扫描证据；
   - 最终状态，且只能以“已验证”或有证据的“不适用”关闭。
10. 审计矩阵必须覆盖动态拼接内容、CSS 伪元素、共享组件默认值和仅在特定状态出现的用户可见值；关键词扫描仅作为发现手段，不可代替矩阵验收。
11. 按以下确定性规则核对并修复数据来源：
    - 已有合同存在明确规则时，以该合同为最高优先级，并在矩阵中引用；
    - 无额外合同规则时，当前登录身份以授权会话为主；通讯录只补全会话缺失的组织、部门和联系方式，不覆盖会话已有非空值；
    - 业务记录使用对应页面 operation contract 指定的数据源；
    - 字典只负责将真实编码转为用户可见文字，不覆盖或改写真实原值；
    - 多来源冲突必须进入矩阵并按合同处置，不得用硬编码或跨业务默认值消解。
12. 个人信息仅在现有授权与既有接口权限范围内读取和展示；防回归测试使用脱敏构造数据，并覆盖不同会话之间的身份数据隔离。

### Out of Scope

1. 写入、清理或修正飞书真实业务数据。
2. 创建、删除或修改飞书多维表、字段或表结构。
3. 新增后端数据库、新的外部服务或未声明的集成。
4. 修改测试环境或生产环境服务器配置。
5. 直接部署、发布或修改生产环境。
6. 重新设计页面视觉风格、导航信息架构或既有业务流程。
7. 将测试文件中的受控夹具误判为线上静态数据并删除。
8. 扩展至移动端或其他未声明平台。
9. 为姓名、组织、部门、邮箱、电话等个人信息新增持久化、跨用户缓存或明文日志。
10. 将个人信息固化到构建产物、测试快照或真实个人信息夹具中。

## 4. 主要用户流程

1. **入口：** 用户通过飞书授权进入数智产品展厅 Web 系统。
2. **授权身份建立：** 系统从既有 OAuth 会话获得当前授权用户上下文，并按现有合同读取可用的通讯录信息。
3. **页面访问：** 用户进入个人、应用、申请、消息、培训、运营或人才相关页面。
4. **真实数据读取：** 页面通过既有接口和共享状态读取当前用户信息或真实业务记录。
5. **字段映射决策：**
   - 先检查既有合同是否为字段规定了明确来源与优先级；如有，以合同为准并在审计矩阵中引用；
   - 无额外合同规则时，当前登录身份以授权会话为主，通讯录仅补全会话中缺失的组织、部门和联系方式；
   - 业务记录按当前页面 operation contract 指定的数据源读取；
   - 若字段返回编码且已有对应字典，则字典仅转换用户可见文字，不覆盖或改写真实原值；
   - 若多个真实来源值冲突，则将来源、值差异、适用合同和处置结果记录到审计矩阵，不以硬编码或跨业务默认值消解；
   - 若真实字段缺失、为空或无记录，则显示“—”、空集合或明确空态；
   - 不得以静态姓名、部门、示例编码或伪造记录作为正常态回退值。
6. **个人信息边界：** 页面只在当前授权会话和既有接口权限内读取及展示个人信息；不得新增持久化、跨用户缓存、明文日志、构建固化或真实信息夹具。
7. **页面结果：** 用户看到与当前授权身份及真实业务记录一致的信息，或清晰识别数据暂缺、加载失败、权限不足等状态。
8. **审计闭环：** 每个页面、共享组件和用户可见字段的来源、映射、缺失值行为、冲突、处置和验证证据都进入审计矩阵；未处置项清零后方可进入范围完成验收。
9. **验证结果：** 自动化回归使用脱敏构造数据验证字段映射和会话隔离，正式构建扫描确认用户可见静态假数据及真实个人信息未进入构建产物，并生成测试环境部署包供后续受控流程使用。

## 5. 状态清单与验收标准

### 状态清单

| 状态 | 预期行为 |
| --- | --- |
| 成功 | 展示当前授权会话或既有真实接口返回并正确映射的数据；用户身份与业务记录不得被静态值替代。 |
| 加载中 | 沿用现有页面的加载机制；加载期间不得短暂展示静态测试身份、示例编码或伪造业务记录。 |
| 空数据 | 对单值字段显示“—”；对集合显示空集合或明确空态；不得用示例值填充。 |
| 错误 | 沿用现有错误呈现机制，并安全降级；不得因接口错误回退到伪造业务数据。 |
| 禁用 | 沿用现有禁用规则；禁用控件或不可用功能不得展示虚假的可操作数据。 |
| 权限依赖 | 当用户无权读取某项真实数据时，沿用现有权限行为或明确空态；不得借助静态值伪装为已获取数据。 |
| 来源冲突 | 按既有合同优先；合同无额外规则时按本 PRD 的确定性优先级处理。冲突及结论必须记录在审计矩阵中，不得静默覆盖。 |
| 会话切换 | 切换授权用户或建立新会话后，只展示新会话所属用户的数据；不得沿用上一会话身份、组织、部门或联系方式。 |

### Given / When / Then 验收标准

#### AC-01：授权用户身份展示

- **Given** 用户已通过飞书授权，且既有合同未规定其他优先级，授权会话或通讯录接口返回姓名、组织、部门、邮箱或电话中的可用字段；
- **When** 用户查看任何展示这些身份字段的正常态页面或共享组件；
- **Then** 页面以授权会话的当前登录身份为主，仅使用通讯录补全授权会话缺失的组织、部门和联系方式，不覆盖授权会话已有非空值，并且不展示固定测试姓名、固定组织、固定部门、示例邮箱或示例电话。

#### AC-02：真实业务记录展示

- **Given** 对应页面的 operation contract 指定了应用、申请、消息、培训、运营或人才业务记录的数据源；
- **When** 页面完成数据加载；
- **Then** 用户可见记录来自该 operation contract 指定的数据源及其真实响应，不得由其他业务来源、前端静态数组、示例对象或伪造回退记录替代。

#### AC-03：编码与状态映射

- **Given** 真实接口返回状态编码、业务编码或用户标识，且现有字典或映射中存在对应的用户可见值；
- **When** 页面展示该字段；
- **Then** 页面通过字典展示对应的用户可见文字或用户名称，同时保留真实原值作为数据事实；字典不得覆盖、改写或伪造真实原值，也不得使用硬编码测试值。

#### AC-04：真实字段缺失

- **Given** 当前用户或业务记录的真实字段为空、缺失或接口无对应记录；
- **When** 页面渲染该字段或记录集合；
- **Then** 单值字段显示“—”，集合显示空集合或明确空态，并且不生成静态身份或伪造业务记录。

#### AC-05：加载状态

- **Given** 页面正在等待既有真实接口响应；
- **When** 加载尚未完成；
- **Then** 页面沿用现有加载呈现，且加载过程中不闪现静态测试身份、示例编码或伪造业务记录。

#### AC-06：接口错误状态

- **Given** 既有真实接口请求失败或响应不可用；
- **When** 页面进入错误或安全降级状态；
- **Then** 页面沿用现有错误呈现或明确空态，不回退展示静态姓名、部门、邮箱、电话、编码或伪造业务记录。

#### AC-07：权限依赖状态

- **Given** 当前授权用户无权读取某个字段或业务集合；
- **When** 页面处理该权限结果；
- **Then** 页面沿用现有权限行为、禁用状态或明确空态，且不以静态值伪装成已读取的真实数据。

#### AC-08：逐页面/逐字段真实数据审计矩阵

- **Given** 审计范围覆盖正式构建中的全部用户可见页面、共享组件、共享状态与展示映射；
- **When** 完成真实数据展示审计；
- **Then** 必须交付逐页面/逐字段审计矩阵，覆盖正常、加载、空数据、错误、禁用、权限依赖、来源冲突和会话切换状态，以及动态拼接、CSS 伪元素、组件默认值和特定状态内容；矩阵每项均包含真实来源、合同/字段、当前回退值、缺失值行为、发现、处置和验证证据。

#### AC-09：审计矩阵关闭门槛

- **Given** 真实数据展示审计矩阵已经形成；
- **When** 申请本任务范围完成验收；
- **Then** 矩阵中不存在“待核对”“待修复”“待验证”或其他未处置项，每项只能以有验证证据的“已验证”或有明确理由和证据的“不适用”关闭；仅有关键词扫描无命中不得视为验收通过。

#### AC-10：接口合同与来源冲突

- **Given** 页面声明或实际读取既有 OAuth、通讯录、多维表只读接口或 operation contract 字段；
- **When** 核对接口响应、页面读取计划和展示映射；
- **Then** 三者字段含义一致，并首先遵守既有合同；合同无额外规则时遵守本 PRD 的确定性数据源优先级。发现多来源值冲突时，矩阵记录来源、差异、适用合同、处置结论和验证证据，不得以硬编码或跨业务默认值消解。

#### AC-11：个人信息处理边界

- **Given** 页面需要展示姓名、组织、部门、邮箱或电话等个人信息；
- **When** 系统读取、传递、展示、测试或构建相关功能；
- **Then** 个人信息仅在现有授权和既有接口权限内读取及展示，不新增持久化、跨用户缓存、明文日志或构建固化，不使用真实个人信息制作测试夹具或快照。

#### AC-12：会话隔离

- **Given** 自动化测试使用两个或以上不同的脱敏构造授权会话；
- **When** 依次或并行加载展示个人信息的页面和共享组件；
- **Then** 每个会话只展示自身身份及可访问数据，不读取、复用或显示其他会话的姓名、组织、部门、邮箱或电话，且测试证据记录在审计矩阵中。

#### AC-13：自动化防回归

- **Given** 静态值清理和字段映射修复完成；
- **When** 执行新增及既有自动化测试；
- **Then** 测试使用脱敏构造数据，覆盖真实字段展示、确定性数据源优先级、空值降级、错误/权限边界、来源冲突、会话隔离以及正式构建静态假数据和真实个人信息固化检查，并全部通过。

#### AC-14：Web 回归与构建产物

- **Given** 范围内修改完成且自动化测试通过；
- **When** 执行 Web 全量回归和测试环境部署包构建；
- **Then** Web 检查通过，测试环境部署包成功生成，且不执行服务器部署或发布。

#### AC-15：平台和数据边界

- **Given** 本任务仅声明 Web/Vue 且真实飞书数据与表结构不属于修改范围；
- **When** 完成任务；
- **Then** 不产生移动端实现，不写入或清理飞书真实业务数据，不修改飞书表或字段，不新增数据库或外部服务。

## 6. 明确非目标 / 禁止事项

1. 不借本次审计新增页面、业务流程、角色、指标或集成。
2. 不改变现有视觉风格、导航结构和交互架构。
3. 不为填满页面而生成或保留貌似真实的默认身份和业务记录。
4. 不以清理静态数据为由删除合法字典、固定产品文案或测试文件中的受控夹具。
5. 不修改飞书真实数据、表结构、字段配置或生产环境配置。
6. 不直接部署或发布构建产物。
7. 不将范围扩展至移动端或未声明平台。
8. 不在范围批准前开始设计、开发、测试修改或发布活动。
9. 不新增个人信息持久化或跨用户缓存，不将个人信息以明文写入日志，不将其固化进构建产物。
10. 不使用真实姓名、组织、部门、邮箱或电话制作自动化测试夹具、测试快照或演示默认值；测试只能使用脱敏构造数据。
11. 不以关键词扫描无命中代替逐页面、逐字段、逐状态审计矩阵，也不允许带未处置项通过验收。
