# UI Visual Handoff：系统真实数据展示与静态假数据清理审计

## 1. 来源、目标与视觉边界

- 任务：`DEH-REAL-DATA-AUDIT-20260929`。
- 产品来源：[`../prd.md`](../prd.md)。
- UX 来源：[`./ux-handoff.md`](./ux-handoff.md)。
- 范围批准来源：[`../decision-log.md`](../decision-log.md)。
- 平台：仅 Web / Vue；响应式 Web 属于 Web 实现。mobile 原生应用与 uni-app 均为 **not declared / 不适用**。
- 本任务是数据可信度修复，不是视觉重设计。保持现有信息架构、导航、页面构图、字体、主色、卡片、表格、按钮、标签、抽屉与状态容器不变。
- 视觉工作的唯一目标是：静态假数据移除后，真实数据、空值、空态及六类状态仍以现有设计语言稳定呈现，不因字段缺失而塌陷，不以装饰性占位伪装成真实业务内容。
- 不新增视觉品牌、插画体系、图标家族、阴影层级、动效语言或移动端设计；不通过视觉设计改变 PRD 或 UX 的数据源、状态、操作与恢复规则。

## 2. 现有视觉方向

沿用当前“克制的企业信息界面”：深蓝导航、浅灰画布、白色信息表面、细分隔线、低阴影、清晰中文层级。真实数据替换只改变内容，不改变用户熟悉的版式。

### 2.1 视觉层级

1. 全局层：`#0060a6` 顶栏、白色侧栏、`#f5f7fa` 内容画布。
2. 页面层：页面标题与说明、筛选/操作区、结果区。
3. 信息层：白色卡片、统计卡、表格、详情定义列表、人才详情抽屉。
4. 状态层：现有 `state-surface`、`inline-state`、页面内状态卡及可见恢复操作。
5. 辅助层：更新时间、单位、来源说明、字段级“—”与中性头像占位。

数据变化不得通过增加更强阴影、饱和色块或弹窗来强调。后台刷新遵循 UX 要求，不显示持续干扰气泡；状态在现有页面状态区或“数据更新时间”附近表达。

## 4. 对比度与键盘焦点

### 4.1 对比度规则

- `#3e5571` 在白底对比度约 7.66:1，`#102a4c` 在白底约 14.41:1，`#0060a6` 在白底约 6.51:1，`#8f2d24` 在白底约 8.18:1；可用于普通字号正文或操作。
- `#7b5b16` 在 `#fff7dc` 上约 5.85:1，可继续用于禁用说明。
- `#6b7d91` 在白底约 4.23:1，低于普通文本 4.5:1 门槛。被本任务触达的更新时间、空值说明、状态说明和联系人辅助信息如使用普通字号，改为复用 `--xlt-text: #3e5571`；`--xlt-muted` 不得承载唯一信息。
- `#929dab` 在 `#f2f4f7` 上约 2.50:1，只允许用于语义上真正禁用的控件；不可作为可操作或正常内容颜色。
- 状态不得只靠红、绿、蓝区分，必须同时显示状态文字；图标为辅助，不替代文字。

### 4.2 焦点规则

- 输入框继续使用 `--form-control-focus: #1f6fca` 与 `--form-control-ring: rgba(0,96,166,.16)`。
- 链接、按钮、可聚焦表格滚动区和抽屉控件必须有 `:focus-visible`。触达组件统一复用项目中已有的复合焦点表达：3px `#ffb648` 外轮廓，并以 `#0060a6` 内层/阴影确保白底和蓝底均能识别；不得仅使用白底对比度不足的单层橙色轮廓。
- Windows 强制颜色模式继续复用 `Highlight`。
- 焦点样式不得改变组件尺寸或导致布局跳动。

## 5. 组件外观与最小变更规则

### 5.1 顶部账号与联系人信息

- 顶部账号区域保留现有 38px 圆形头像、名称/部门两行结构、白色与半透明白色文字。
- 名称使用授权会话真实值；未确认身份时显示 UX 规定的中性“当前用户”，不得显示旧账号或测试姓名。
- 部门/组织缺失显示“—”，保留第二行高度，避免顶栏抖动；窄桌面按现有规则隐藏第二行，响应式 Web 不新增信息层。
- 个人中心联系人、组织、部门、电话和邮箱沿用定义列表/表单当前网格、边框和字号。只替换值；缺失单值显示“—”，表单自动填充失败则字段留空。
- 中性头像继续复用 `.identity-placeholder` 的 `#e7edf4 / #cbd7e4` 分区图形和准确替代文本，不使用暗示特定人员的固定头像。

### 5.2 未读计数徽标

- 保留现有红色圆角徽标位置、大小和白字外观，但徽标必须由真实计数渲染为 DOM 内容，不能使用 CSS `content:'8'`。
- 真实计数大于 0 时显示；为 0、缺失、加载中、错误或无权限时不显示徽标。
- 可见数字与消息链接 `aria-label` 完全一致；较大计数按现有空间使用简短格式或既有上限规则，不扩大顶栏高度。
- 徽标消失时消息图标仍保持 32×44px 桌面命中区、44×44px 窄屏命中区。

### 5.3 统计卡

- 沿用白底、1px 边框、7px 圆角、弱阴影、标题—数值—单位/说明的既有层级。
- 有真实值时按当前 KPI 字号显示；`0` 仅在接口明确返回真实零值时显示。
- 值缺失显示“—”，不得显示 `0`、示例数量、固定增幅或伪造趋势。
- 整组无真实统计且没有独立价值时按 UX 隐藏区块；不保留空卡填版。部分字段缺失时保留真实字段，并在缺失项显示“—”。
- 卡片数量变化沿用现有 CSS Grid 自动重排；不得引入彩色装饰图或新的高度。

### 5.4 状态、编码与标签

- 已有字典映射时，继续使用现有 `mark`/状态徽标外观展示中文；原始编码如业务需要保留，放在现有详情字段或辅助文本中，不与主状态争夺层级。
- 无映射时按合同显示原编码或“—”，不得用看似有效的中文标签猜测。
- 中文状态文字决定标签宽度，允许水平内边距自适应；不得固定宽度截断“权限不足”“审批中”等完整状态。

### 5.5 详情区块

- 应用、申请、公告、素材等详情继续使用现有白色卡片、区域标题左侧蓝色竖线、定义列表和细分隔线。
- 单字段缺失：标签保留，值显示“—”；不得用示例编码、负责人或默认数量填充。
- 业务集合为空：在原区块内容区居中显示现有空态；如果合同根本不提供该数据域或整区无独立价值，则整区移除，并让相邻 Grid 自然补位。
- 删除整区后不得留下空标题、空边框、无内容的固定高度或可聚焦空控件。
- 缓存数据可展示时，在当前区块标题或现有状态信息附近使用 caption/meta 层级显示“数据更新时间：YYYY-MM-DD HH:mm”；不使用浮动气泡。

### 5.6 人才详情

- 保留现有右侧抽屉、标题、基本信息定义列表、关闭按钮及焦点管理。
- “培训计划”“参与项目”等仅在 operation contract 返回真实集合时展示；列表项沿用当前正文与 `mark` 标签风格。
- 没有真实培训/项目字段时：若该区块无独立信息价值则整个区块隐藏；若合同返回空集合且区块应保留，则显示现有页面语气的明确空态，不展示固定年度、固定项目名或“数量：3”。
- 基本信息字段缺失时显示“—”；标签集合为空时显示“—”，不得渲染空 `mark`。
- 抽屉中区块减少后允许高度自然收缩，底部“关闭”操作仍位于正常文档流/现有页脚位置，不增加填充留白。

### 5.7 表格、列表与卡片集合

- 真实记录继续使用现有表格行、列表项或卡片样式；不为“看起来完整”创建占位业务行。
- 集合为空显示现有明确空态；筛选空结果保留“清空筛选”等已有恢复操作。
- 删除伪造记录后分页总数、结果数量、页码和可访问播报必须同步，不保留原静态数量。
- 表格横向滚动区域保持现有 `role="region"`、可聚焦和可见焦点样式。

## 6. 六个必需状态

| 状态 | 最小视觉方案 | 内容与操作 |
| --- | --- | --- |
| `normal` | 复用现有卡片、表格、标签和真实数据字号；缓存更新时间用 meta 层级置于相关区域内 | 显示权威真实值；缺失字段为“—”；真实 0 才显示 0；计数与辅助文本一致 |
| `loading` | 无缓存时复用 `state-surface` 或页面现有状态卡；有当前会话有效缓存时保留内容，在更新时间旁显示“正在更新” | 不渲染静态默认业务值；容器 `aria-busy="true"`；不使用遮挡全页的新增浮层 |
| `empty` | 集合使用现有居中空态；字段为空保留标签与“—”；无价值可选区块整体隐藏 | 保留真实可用的清空筛选、返回或发起申请入口；不显示占位记录 |
| `error` | 无缓存时复用白底状态卡/`state-surface`，错误文字使用 `#8f2d24`；有缓存时内容不变，在更新时间附近显示失败说明 | 显示现有“重试/重新读取”；不得回退到静态数据；不暴露内部响应与个人信息 |
| `disabled` | 复用 `.disabled-notice` 黄底说明和控件现有灰色禁用态；保留准确原因文本 | 原生 `disabled`；不可操作数据不伪装为可点击卡片；禁用说明不能仅在 `title` 中 |
| `permission-denied` | 复用 `state-surface` 或页面内白色状态卡，标题“访问受限”，正文使用高对比度错误色 | 隐藏受保护真实值、旧缓存和联系人信息；保留重新授权、返回工作台或联系管理员的既有路径 |

补充状态：

- 部分成功：成功区保持正常外观；失败区使用自身状态卡与重试，不以其他 operation 或静态记录补齐。
- 后台刷新：只在现有内容区标示“正在更新/更新失败”和更新时间，不显示持续气泡，不改变页面布局，不抢焦点。
- 会话切换：旧身份区域立即切换为中性加载/隐藏状态；不得先显示上一账号再替换。

## 7. 响应式 Web

### 7.1 断点

复用现有断点，不新增断点体系：

- `> 1420px`：主导航等宽分配；页面按现有多列布局。
- `1361–1420px`：沿用现有桌面压缩；应用/收藏/素材卡片仍可保持多列。
- `1201–1360px`：卡片集合按现有规则转为两列。
- `1001–1280px`：顶栏、导航和用户信息按现有紧凑规则；用户真实值允许省略，不能替换为静态短名称。
- `761–1100px`：保留 220px 侧栏；页面多列按各组件现有规则降列。
- `<= 760px`：响应式 Web 单列，移动导航抽屉，页面边距 10–12px，控件最小高度 44px。
- `<= 430px`、`<= 380px` 与 `<=760px` 横屏：完全沿用 `src/h5.css` 已有规则。

### 7.2 重排规则

- 统计卡：桌面多列；中宽两列；`<=760px` 单列。隐藏无真实值卡片后，剩余卡片自然补位。
- 详情定义列表：桌面保持当前双列或标签/值双栏；窄屏按现有规则单列或保持最小 128px 标签列，长值 `overflow-wrap:anywhere`。
- 联系人信息：真实姓名、部门、邮箱和电话不得横向溢出；允许换行，不通过截取后拼入静态后缀。
- 人才抽屉：桌面保持 `clamp(520px, 38vw, 680px)`；窄桌面转单列；`<=760px` 使用现有全宽/安全区规则。
- 数据更新时间紧随所属区块，不固定到视口角落，避免与筛选和主操作重叠。

### 7.3 触控与安全区

- 响应式 Web 的按钮、导航、关闭控件、输入控件最小 44×44px；复选框/单选框视觉控件 20×20px，但标签整体命中区不小于 44px 高。
- 继续使用 `env(safe-area-inset-top/right/bottom/left)` 处理顶栏、侧栏抽屉、底部操作与页脚。
- 本节只描述窄屏 Web 浏览器，不代表声明原生 mobile 或 uni-app。

## 8. 动效与图像

- 保留现有 0.14–0.22s 的输入、颜色和侧栏过渡；数据更新本身原位替换，不增加闪烁、计数跳动或强调动画。
- `prefers-reduced-motion: reduce` 时停止旋转和位移动画，继续遵循现有规则。
- 加载旋转器继续使用现有 24px 蓝色环；只有请求真实处于活动状态时显示。
- 头像、应用图标、附件预览必须来自受控真实 URL；缺失时使用已有中性占位，不新增人物照片或示例业务图。

## 9. 视觉验收清单

1. 全部 32 个 Web 路由与共享壳层保持当前视觉体系和导航结构。
2. 顶部账号、个人中心、申请表单及认证相关联系人区域不出现固定姓名、部门、组织、电话或邮箱。
3. 未读徽标只在真实计数大于 0 时出现，DOM 数字与 `aria-label` 一致，CSS 不生成固定数字。
4. 统计卡仅显示真实数值；缺失与真实零值可视觉区分，不以 0 伪装缺失。
5. 详情区块删除假数据后无空标题、空卡框、固定高度洞或可聚焦空控件。
6. 人才详情不展示固定年度培训、固定项目名称或固定项目数量；区块按真实合同显示、空态或隐藏。
7. normal/loading/empty/error/disabled/permission-denied 六态均使用既有视觉组件，状态文字清晰且不只依赖颜色。
8. 桌面、中宽、`<=760px` 响应式 Web 下无内容重叠、横向溢出或操作遮挡；窄屏命中区不少于 44px。
9. 所有触达控件键盘焦点清晰；高对比度/强制颜色模式可识别；后台刷新不抢焦点。
10. 更新时间与缓存/刷新状态位于所属内容区，不以持续气泡遮挡页面。

## 10. Web 与 uni-app 差异
