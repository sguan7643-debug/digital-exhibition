# UX Handoff：系统真实数据展示与静态假数据清理审计

## 1. 设计基线与边界

- 任务：`DEH-REAL-DATA-AUDIT-20260929`。
- 已批准产品基线：[`../prd.md`](../prd.md)，范围批准记录见 [`../decision-log.md`](../decision-log.md)，独立范围评审见 [`../reviews/product-review.md`](../reviews/product-review.md)。

## 2. 当前行为与研究证据

### 2.1 页面与数据合同

- `src/fixtures/pages.js` 登记 32 个正式 Web 路由；`src/App.vue` 将这些路由分派到 32 个 Vue 页面，并将页面数据统一从 `integrationEnvelope` 传入。
- `src/integration/page-integration-matrix.js` 为工作台、消息、收藏、个人中心、公告、应用、申请、积分、培训、运营、认证、人才和素材页面声明现有 operation contract 与字段域。
- `src/integration/page-read-request-plan.js` 为当前用户、列表、详情和查询参数定义实际读取输入；业务记录应遵循这些既有合同，不应由页面静态数组替代。
- `src/components/PageStateBoundary.vue` 已具备正常、加载、空数据、错误、禁用和权限不足的统一页面边界、焦点恢复及无障碍播报，可作为本任务的既有交互基础。

### 2.2 已观察到的风险实例

- `src/components/ExhibitionShell.vue` 的顶部未读消息入口当前将“8”同时写在 `aria-label` 和 CSS 伪元素中；这是共享组件、动态计数、辅助技术文本和 CSS 生成内容必须同时审计的直接证据。
- `src/pages/TalentPeoplePage.vue` 的人才详情中固定展示“2026年培训计划”“AI前沿技术培训计划”“海上平台智能监测项目”“数据中台建设项目”“参与项目数量：3”；当真实合同未提供这些字段时，应隐藏对应业务区块或显示字段级缺失态，不能展示伪造记录。
- `src/pages/ProfilePage.vue` 已从授权会话与个人中心接口组合姓名、组织、部门等字段，并以“—”处理缺失字段；这是身份展示的参考行为。
- `src/pages/OnboardingPage.vue` 已在审批同步失败时保留最后成功结果，并展示最近同步时间；这是“可用旧数据 + 明确时效 + 可重试”的参考行为。
- `src/App.vue` 已区分首次同步、部分超时、缓存数据和可用内容，并提供请求活动与恢复播报；本任务不得让静态值在这些状态中短暂闪现。
- `src/integration/browser-data-cache.js` 使用命名空间构造 IndexedDB 键并通过 `BroadcastChannel` 同步；`persistent-read-client.js` 和 `persistent-homepage-client.js` 会返回缓存时间及新鲜度。用户可见身份或联系方式只能在已确认当前授权身份与缓存命名空间一致后显示。

保持现有信息架构与导航完全不变：

2. 普通用户：工作台、消息、收藏、个人中心、公告、应用中心及九类应用详情、我的申请、上架申请、积分、培训、认证、素材。

## 4. 数据来源与界面呈现规则

### 4.1 确定性优先级

每个用户可见字段按以下顺序决定界面内容：

1. 若既有 operation contract 对字段来源或优先级有明确规则，以合同为最高优先级。
2. 当前登录身份字段以授权会话的非空值为主；通讯录只补全会话缺失的组织、部门、邮箱和电话，不覆盖会话已有非空值。
3. 应用、申请、消息、公告、培训、运营、人才、积分、认证、素材等业务字段，只使用当前页面 operation contract 指定的真实业务记录。
4. 字典只把真实编码转换成用户可读中文，不改写原始事实；有已知映射时显示中文，必要时可在详情或辅助文本保留原编码。没有映射时不得猜测中文，可显示原编码或“—”，并在审计矩阵记录。
5. 多个真实来源发生冲突时，界面只展示合同判定的权威值；不得混拼、轮换或用静态值消解。冲突来源、合同与处置结论必须进入审计矩阵。
6. 如果没有可用真实值，使用本交付第 4.2 节的缺失策略，不使用示例姓名、部门、电话、邮箱、状态、编码、数量或业务记录。

### 4.2 空值、不展示与保留结构策略

| 数据类型 | 无真实值时的界面行为 | 禁止行为 |
| --- | --- | --- |
| 身份核心字段：姓名、组织、部门、工号 | 保留字段标签并显示“—”；姓名尚未确认时显示中性文本“当前用户”，但不得显示任意真实或测试姓名 | 使用固定人员、组织或部门；把上次会话身份当作当前身份 |
| 联系方式：电话、邮箱 | 保留字段标签并显示“—”；表单自动填充失败时字段保持空白并允许用户按既有规则填写 | 使用示例电话、示例邮箱或其他用户的缓存值 |
| 单条业务字段：状态、编码、负责人、时间、数量 | 显示“—”；状态有字典时显示字典文字，无字典时按合同决定显示原编码或“—” | 生成默认编码、默认数量、虚构状态或虚构负责人 |
| 业务记录集合 | 显示该模块现有明确空态；列表、卡片、图表不得生成占位业务记录 | 用前端静态数组填充正常态 |
| 整个可选业务区块 | 合同没有该数据域，或所有字段均无真实值且区块没有独立业务价值时，整个区块不展示 | 展示固定培训、项目、统计或推荐记录来维持版面 |
| 图片/头像 | 有受控真实 URL 时展示；否则沿用中性占位图形并提供“默认用户头像”等准确替代文本 | 使用暗示特定人员身份的固定头像 |
| 计数徽标 | 仅在真实计数大于 0 时展示并同步更新可见文本与 `aria-label`；0 或不可用时不展示徽标 | CSS 伪元素固定数字、可见数值与辅助文本不一致 |
| 最后成功缓存 | 可展示，但必须同时展示“数据更新时间”；刷新失败时继续保留并说明这是最后成功结果 | 把缓存内容描述为刚刚更新，或在身份未确认时展示个人数据 |

### 4.3 避免静态值闪现

1. 首次进入、硬刷新或会话确认中，不得先渲染页面默认业务对象再替换为远程数据。
2. 数据尚未确定时只显示现有加载态、骨架结构或中性占位；姓名、部门、电话、邮箱、计数、状态、编码和业务记录不得预填静态值。
3. 页面从缓存恢复时，只有缓存键已验证属于当前授权用户后才能显示；同时显示缓存更新时间，并在后台刷新。
4. 路由切换时可以复用同一授权会话、同一合同和同一请求参数下已加载的数据；不得把前一路由的业务记录作为新页面占位。
5. 后台刷新成功后原位更新字段，并通过礼貌型实时区域播报“数据已更新”；不强制抢夺键盘焦点。
6. 后台刷新失败时保留当前已标注的最后成功数据，并提供可执行的重试入口；不能退回静态数组或示例对象。
7. 用户退出、重新授权、账号变化或会话失效时，立即隐藏上一身份的个人数据和用户范围业务数据，再进入登录确认或加载态。

## 5. 关键用户流程

### 5.1 首次进入与会话确认

1. 用户进入系统。
2. 登录状态未确认：只显示“正在确认登录状态”或既有登录检查失败界面，不显示缓存身份或业务数据。
3. 登录确认成功：建立当前授权用户命名空间，开始读取当前路由所需合同数据。
4. 有新鲜缓存且归属当前用户：立即显示缓存内容和“数据更新时间”，后台静默刷新。
5. 无可用缓存：显示加载态，成功后进入正常态；失败则进入错误或权限不足态。

### 5.2 页面切换与数据复用

1. 用户通过现有导航进入另一页面。
2. 系统只复用同一用户、同一 operation、同一请求参数的数据。
3. 复用命中时立即显示并标记更新时间；后台更新完成后原位替换。
4. 复用不命中时进入加载态，不展示目标页面静态记录。
5. 返回上一页时保留现有筛选、分页、滚动与焦点恢复行为，但业务数据仍须通过当前会话隔离检查。

### 5.3 字段映射与来源冲突

1. 页面收到真实响应。
2. 按合同选择权威来源；身份字段再按“会话优先、通讯录补全”处理。
3. 编码存在字典时显示中文；字典缺失时按第 4.1 节处理。
4. 多来源冲突不向用户展示两个相互矛盾的值；界面展示合同权威值，审计矩阵记录差异与证据。
5. 字段缺失则显示“—”或隐藏无价值区块，不创建伪数据。

### 5.4 会话切换与跨标签页更新

1. 检测到账号变化、重新授权或会话失效时，先清除当前视图中的个人信息和用户范围结果。
2. 新会话身份确认前，不从 IndexedDB、内存或其他标签页展示旧会话数据。
3. `BroadcastChannel` 更新只在用户命名空间、operation 和参数均匹配时接收；不匹配的消息不可改变当前界面。
4. 匹配更新到达时原位刷新数据和更新时间，并礼貌播报，不弹窗、不抢焦点。

### 5.5 审计与验收流程

1. 以 32 个正式路由及全局共享组件为固定清单建立审计矩阵。
2. 对每个页面逐字段检查 DOM 可见文本、属性/辅助文本、CSS 伪元素、动态拼接、默认值、空态和特定状态内容。
3. 每个字段必须分别验证正常、加载、空数据、错误、禁用、权限不足及会话切换；不适用状态需给出理由。
4. 自动化验证后，由人工在浏览器中核对可见内容、焦点、播报、重试和缓存更新时间。
5. 只有所有矩阵行均为“已验证”或有证据的“不适用”，且不存在待核对、待修复、待验证项时，才满足 UX 验收。

## 6. 必需状态交互合同

| 状态 | 触发条件 | 内容行为 | 允许操作与恢复 | 焦点、播报与可访问性 |
| --- | --- | --- | --- | --- |
| 正常 `normal` | 当前会话已确认，合同数据成功返回或已验证缓存可用 | 展示权威真实值；空字段按第 4.2 节处理；显示数据更新时间；不得混入静态业务值 | 保留现有导航、筛选、分页、详情、刷新和安全操作 | 页面标题与区域标题层级保持现状；动态更新使用 `aria-live="polite"`；计数的可见值与可访问名称一致 |
| 加载 `loading` | 首次请求、无可用缓存、会话切换后重新读取 | 显示现有加载文案或结构；业务值区域不显示静态默认值；若同一会话存在已验证缓存，可继续显示缓存并标注“正在更新” | 可继续使用不依赖该请求的区域；重复提交和冲突操作禁用 | 容器设置 `aria-busy="true"`，礼貌播报一次；加载完成后按现有行为聚焦结果标题，不反复抢焦点 |
| 空数据 `empty` | 请求成功但集合为空，或字段真实值为空 | 集合显示明确空态；单值显示“—”；没有真实内容的可选业务区块隐藏 | 保留清空筛选、返回、发起申请等现有且真实可用的恢复入口 | 空态使用 `role="status"`；筛选导致的空态播报结果数量；恢复后焦点到结果标题 |
| 错误 `error` | 网络、超时、服务、结构校验或未知读取失败 | 没有缓存时显示明确错误；有当前会话最后成功数据时保留内容、显示更新时间与失败说明；不得显示静态回退记录 | 提供现有“重试/重新读取”；不依赖失败数据的导航可继续使用 | 首次错误使用 `role="alert"`；重试状态使用礼貌播报和 `aria-busy`；失败信息不得泄露个人信息、令牌或内部响应正文 |
| 禁用 `disabled` | 合同或功能明确未开放，或写能力未启用 | 只显示准确的不可用说明；不展示看似可操作的静态数据或示例结果 | 控件保持不可操作；通过可见说明或关联描述解释原因；保留安全返回路径 | 原生 `disabled` 优先；说明通过 `title` 之外的可见文本或 `aria-describedby` 可获得；禁用态不进入 Tab 顺序 |
| 权限不足 `permission-denied` | 未授权、授权过期、403 或合同判定不可访问 | 隐藏受保护字段与缓存内容；显示完成授权、返回工作台或联系管理员的既有路径；不得用静态值填补 | 允许重新授权、重试登录检查或返回安全页面 | 使用 `role="alert"`；焦点移动到“访问受限”标题；链接名称说明目的；不得在错误详情中暴露上一会话身份 |

补充状态：

- 部分成功：保留成功区域，失败区域独立显示错误与重试；不得用别的 operation 数据或静态记录补齐失败区域。
- 后台刷新：不遮挡页面，不显示持续干扰的气泡；在数据更新时间附近或页面已有状态区表达“正在更新/更新失败”。
- 来源冲突：用户只看到合同权威值；冲突本身进入审计证据，不新增面向普通用户的冲突弹窗。

## 7. 逐页逐字段审计矩阵的交互验收方式

### 7.1 固定覆盖清单

矩阵必须覆盖以下路由组以及每组共用组件，不得抽样：

| 路由组 | 必审页面/入口 | 重点字段域 |
| --- | --- | --- |
| 全局壳层 | 所有 32 个路由共同使用的顶部栏、账号菜单、消息徽标、收藏入口、侧栏、页脚 | 当前用户名、组织/部门、头像、未读数、角色可见性、CSS 伪元素与辅助文本 |
| 首页与个人 | `/workbench`、`/profile`、`/messages`、`/favorites` | 身份、组织、联系方式、统计、消息、收藏、待办、最近记录、更新时间 |
| 公告 | `/announcements`、公告详情 | 公告类型、状态、发布人/部门、时间、范围、阅读数据、附件与关联记录 |
| 应用 | `/apps`、九类应用详情 | 名称、类型、业务域、负责人、部门、状态、编码、计数、版本、附件、关联培训/素材/评论 |
| 上架 | `/apps/onboarding/status`、`/apps/onboarding/apply` | 申请人、部门、电话、邮箱、应用类型、业务域、授权对象、审批状态/节点/实例、附件 |
| 积分与培训 | `/points`、`/points/details`、`/training` | 余额、流水、规则、课程、状态、时间、报名/学习入口 |
| 运营与后台 | `/operations`、公告管理/编辑、应用管理/编辑、`/admin` | 指标、状态、负责人、统计、配置、日志、集成健康、禁用写能力 |
| 认证 | `/certification` | 认证名称、状态、考试/预约、时间、用户联系信息 |
| 人才 | `/talent/people`、`/talent/projects`、`/talent/progress` | 人员、部门、专业、培训、项目、数量、进度、文档、负责人；固定人才详情内容必须逐项处理 |
| 素材 | `/materials` | 名称、类型、业务域、创建人、更新时间、关联应用、下载状态 |

### 7.2 每一矩阵行必须记录

1. 路由、页面/组件、触发状态和用户角色。
2. 用户可见字段、数据类别及其所有呈现位置：文本节点、表单值、属性、可访问名称、CSS 生成内容、下载名、提示和动态拼接。
3. 当前读取路径、当前默认/静态/回退值。
4. 权威 operation contract、响应字段、字典及优先级。
5. 正常、加载、空数据、错误、禁用、权限不足、会话切换时的预期行为。
6. 是否存在静态值、来源冲突、缓存串用或短暂闪现风险。
7. 处置结果、涉及文件、自动化测试、人工复核与构建扫描证据。
8. 最终状态只能是“已验证”或有理由和证据的“不适用”。

### 7.3 交互验收场景

每个字段至少使用以下场景之一产生证据，身份与联系方式字段必须全部覆盖：

- 会话 A 返回完整值：界面展示会话 A 的权威值。
- 会话 A 缺少组织/部门/联系方式，通讯录有值：只补全缺失字段。
- 会话值与通讯录值冲突：保留会话非空值，并在矩阵记录冲突。
- 业务接口返回编码且字典有映射：显示中文；字典无映射：不猜测、不伪造。
- 字段为空、集合为空：分别显示“—”和明确空态。
- 首次慢请求：加载期间不出现任何静态身份、计数或业务记录。
- 有当前会话缓存且刷新成功：立即展示缓存与更新时间，随后原位更新。
- 有当前会话缓存且刷新失败：保留最后成功结果、更新时间和重试入口。
- 403/授权过期：受保护数据立即隐藏，焦点进入权限说明。
- 会话 A 切换到会话 B：在 B 确认前不显示 A；确认后只显示 B。
- 两个浏览器标签页：只接收同一会话命名空间的更新，更新时间同步变化。
- 键盘与屏幕阅读器：状态播报不重复；焦点顺序、禁用状态、可访问名称与可见内容一致。

## 8. 搜索、筛选、分页与详情行为

- 搜索和筛选只作用于真实已加载记录或对应服务端查询，不得把静态记录混入结果。
- 输入防抖期间保留用户输入；加载提示不得覆盖表单值。最终结果数量通过礼貌型实时区域播报。
- 清空筛选恢复当前真实数据全集；如果真实全集为空，显示业务空态，不恢复测试夹具。
- 页面切换或返回时可恢复筛选、分页、滚动和焦点，但必须重新确认数据仍属于当前会话。
- 详情抽屉或详情页仅展示所选真实记录的字段。合同未提供培训、项目、附件等关联域时，隐藏对应区块或显示准确空态。
- 禁用的新增、编辑、导出等能力必须说明真实原因，不以“演示数据”或可点击假结果暗示功能可用。

## 9. 可访问性行为

- 状态文字不能只依赖颜色或图标；正常、错误、权限、禁用和缓存状态均需有文本。
- 加载和后台更新使用 `aria-busy` 与 `aria-live="polite"`；会阻止继续操作的错误和权限不足使用 `role="alert"`。
- 页面级权限不足后把焦点移到状态标题；筛选结果更新后可把焦点移到结果标题，但后台静默刷新不得抢焦点。
- 徽标、计数、状态和编码翻译的可见文本必须与 `aria-label`、隐藏文本一致；CSS `content` 不得是唯一信息来源。
- 空值“—”的字段标签保持可感知；整区隐藏时不保留可聚焦的隐藏控件。
- 禁用控件使用原生禁用语义；禁用原因必须可由键盘和辅助技术获得，不能只依赖鼠标悬停。
- 缓存更新时间应使用用户可理解的本地时间文本；若使用 `<time>`，其 `datetime` 保留机器可读值。
- 个人信息不得进入错误堆栈、请求追踪文案、辅助文本或调试播报。

## 10. Web 与 uni-app 差异

- Web：适用本文件全部行为；保留现有桌面/响应式导航、浏览器历史、焦点恢复、IndexedDB、`BroadcastChannel` 和键盘交互。
- uni-app：本任务未声明该平台，`不适用`。不得据此创建移动端页面、缓存规则或交互实现。

## 11. 设计验收门槛

进入开发前，设计汇总必须确认：

1. 保持现有视觉和导航，没有新增页面或业务流程。
2. 数据源优先级、缺失值、区块隐藏、缓存更新时间和会话隔离规则无歧义。
3. 六个必需状态及部分成功、后台刷新、来源冲突均有明确交互与恢复方式。
4. 全部 32 个路由和共享组件进入审计矩阵，动态拼接、属性、辅助文本与 CSS 伪元素不遗漏。
5. 顶部固定未读数和人才详情固定培训/项目等已知风险被明确纳入实施与验证。
6. 不使用真实个人信息作为测试夹具、快照或构建内容。

本 UX 交付不代表设计批准，也不授权开发或发布；需由 AI Team Lead 汇总后提交用户进行明确设计批准。

## 12. 开放问题

- 无需用户新增产品决策。若实施中发现某字段存在多个真实来源且既有合同没有给出优先级，应暂停该字段的实现并回到产品决策，不得由开发或 UX 临时选择。
- 若某页面没有可用的真实 operation contract，按“禁用/明确空态”处理，不得保留静态业务记录；是否新增合同超出本任务范围。
