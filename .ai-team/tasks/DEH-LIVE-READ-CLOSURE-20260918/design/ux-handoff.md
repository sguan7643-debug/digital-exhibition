# UX Handoff — 正式飞书 65 项读取全量闭环

## 1. 目的、依据与交互边界

本交接实现已批准的 [PRD](../prd.md)，任务为 `DEH-LIVE-READ-CLOSURE-20260918`。它定义受控执行人员如何启动、理解、取消、恢复并复核一次正式飞书读取闭环；不新增面向业务用户的页面，不改变现有产品导航、业务页内容或视觉系统。

行为依据：

- [Task brief](../task-brief.md)：授权身份、8 项精确权限、`TEST_` 临时记录和 `65/65` 验收边界。
- [Decision log](../decision-log.md)：Product Owner 已批准范围和正式数据写入授权。
- [Product review](../reviews/product-review.md)：长期权限与临时数据必须采用不同生命周期；文件 token 只能只读复用；所有剩余假设必须 fail closed。
- [既有 65 项证据](../../DEH-LIVE-101-20260914/evidence/reads-65-20260918.json)：40 passed、20 项权限阻断、5 项上下文缺失、0 failed 的基线。
- [现有 65 项 runner](../../../../tools/verify-live-read-operations.mjs)、[输入解析器](../../../../server/feishu-live-read-inputs.mjs) 和 [operation runner](../../../../server/feishu-live-operation-runner.mjs)：当前行为按只读 registry 顺序执行、逐 operation 生成 passed/blocked/failed 结果，并在输入解析时从正式表读取上下文。

本交接不授权：通配权限、正式业务对象写操作、非本次创建记录的删除、媒体上传、凭证或生产配置修改、合并、部署或发布。

## 2. 平台与操作界面声明

**仅 Web。** `task.json` 声明 `platforms=["web"]`、Vue Web，未声明 uni-app 或其他移动端目标；因此本交接不定义移动端、原生端或触屏专属流程。

本任务的主要交互面是受控命令入口、阶段化标准输出和脱敏证据文件，不要求增加业务页面。若已有内部 Web 验证入口调用同一执行器，它必须遵守相同的阶段、状态、取消、恢复和安全规则，但不得因此新增正式用户可见功能。

## 3. 信息架构

一次执行以唯一 `runId` 为根，包含七个连续阶段和三个互相隔离的账本：

1. **预检**：身份、65 项清单、正式表结构、精确删除能力、证据目录和脱敏器。
2. **权限快照**：读取 `3d8egf55` 的现有权限并计算 8 项精确差集。
3. **权限原子补齐**：仅写入缺失项，随后重读验证；部分失败仅回滚本次新增项。
4. **资源上下文准备**：先只读发现兼容文件 token，再创建可精确删除的 `TEST_` 表记录。
5. **65 项读取**：完整运行 read-only registry，不以原 25 项局部重跑替代。
6. **补偿清理与复核**：所有终态进入；按记录 ID 删除本次 `TEST_` 记录并独立复核无残留。
7. **回归与结论**：清理完成后运行相关测试与生产构建，生成最终脱敏证据。

三个账本不得混用：

| 账本 | 内容 | 生命周期 |
| --- | --- | --- |
| `permissionBaseline` / `createdPermissionRecordIds` | 写入前既有权限、本次新增权限记录 ID | 8 项完整验证前允许按本次新增 ID 回滚；完整验证后长期保留 |
| `temporaryRecordLedger` | 本次创建的 `TEST_` 表名、record ID、业务资源 ID、对应 operation | 成功、失败、超时、取消均必须清理并复核 |
| `fileContextLedger` | 现有文件来源表、脱敏记录标识、token 指纹/摘要、契约兼容性 | 全程只读；不修改、不删除、不输出完整 token |

## 4. 端到端流程与顺序

### Flow A — 启动与只读预检

1. 操作者从受控入口启动任务。系统先生成 `runId`，创建仅含非秘密元数据的运行清单；此时不得写飞书数据。
2. 服务端从真实 OAuth 会话解析 AD 账号。只有精确等于 `3d8egf55` 才继续；浏览器参数、环境变量中的任意“用户 ID 覆盖值”不得替代会话身份。
3. 校验只读 operation registry 恰为 65 项、ID 唯一且无遗漏，并保存清单摘要。
4. 只读核对权限表字段、账号/权限唯一键、既有记录可追溯字段；同时核对 `applicationId`、`certificationId`、`exportId` 所需记录均存在逐 record ID 删除 API 和独立复核路径。
5. 启动证据脱敏守卫，先以哨兵值验证日志和 JSON 输出不会泄露 access token、refresh token、Cookie、Authorization、应用密钥、完整 file token 或完整个人敏感信息。
6. 任一预检失败，进入 `disabled` 或 `error` 终态；不执行任何正式写入，也不启动 65 项读取。

### Flow B — 权限快照与原子补齐

1. 只读获取 `3d8egf55` 当前权限，保存脱敏的写入前快照。每项标记为“既有”或“缺失”；既有记录永不更新或删除。
2. 只允许对批准的 8 个精确权限码执行幂等补齐。每次写入后立刻把正式记录 ID 追加到 `createdPermissionRecordIds`；不能仅在全部写完后才记录。
3. 写入完成后从正式权限投影重新读取，确认：8 项全部有效；无重复有效授权；没有通配权限；没有给其他账号写入；没有写入第 9 项权限。
4. 若验证成功，将 8 项标记为“长期权限已完整建立”。此后无论读取失败、超时或取消，都不自动撤销。
5. 若写入、超时、取消或写后验证发生在完整建立之前，仅按 `createdPermissionRecordIds` 精确回滚本次新增行，随后重读并确认写入前既有权限未变。回滚失败必须进入需人工处理的 `error`，不得继续准备上下文。

权限补齐对操作者表现为一个不可并发重复启动的事务阶段；“原子”指最终只能留下“完整 8 项有效授权”或“恢复到写入前基线”，不表示把多个远程 API 请求伪装成单次数据库事务。

### Flow C — 文件上下文只读发现

1. 在创建任何 `TEST_` 记录之前，只读扫描 PRD 已确认的合法候选来源，例如“素材中心”和“附件资料”。
2. 分别按 `COM-008`、`MAT-003` 的既有请求契约验证候选是否当前有效、来源合法且用途兼容。可由同一个 token 满足两个 operation，也可分别选择；必须逐 operation 记录兼容结论。
3. 标准输出和证据只显示来源表、脱敏 record ID、不可逆指纹及兼容/不兼容原因；禁止显示完整 token、下载 URL 中的 token 或文件正文。
4. 若任一 operation 找不到合法兼容 token，状态为 `File context unavailable`：停止，不创建 `TEST_` 记录，不上传媒体，不运行 65 项读取，任务保持未通过。

### Flow D — `TEST_` 上下文创建

1. 只有身份、权限完整验证、文件上下文可用和精确删除路径全部成立后，才允许创建临时表记录。
2. 为 `APP-010`、`CER-003`、`COM-010` 创建字段最小化且带 `TEST_<task>_<runId>` 唯一标识的记录，分别取得 `applicationId`、`certificationId`、`exportId`。
3. 每条创建成功后立即把表名、record ID、业务 ID、对应 operation 和创建时间追加到 `temporaryRecordLedger`。若 ledger 持久化失败，应把刚创建的 record ID 保留在内存并立即尝试删除；不得继续创建下一条。
4. 创建期间任一错误或取消，立即转入 Flow F 清理；不得把第一条临时记录复用为不相干的资源类型，也不得从非 `TEST_` 正式数据中选择可变夹具。

### Flow E — 完整 65 项读取

1. 输入解析器使用权限投影、只读文件上下文和本次 `TEST_` 资源 ID 组成 operation-specific 输入。
2. runner 必须运行 registry 中全部 65 项，并保持 operation ID 唯一。阶段进度显示 `已完成 n/65`、passed/blocked/failed 当前计数和当前 operation ID；不输出原始请求对象或响应正文。
3. 只有真实调用成功且响应满足现有契约才是 passed。合法空集合可 passed，但必须附 `empty=true`；未请求、fixture、缓存旧证据、403、上下文缺失、5xx、超时或契约错误均不能 passed。
4. 单项失败不自动扩大权限或更换正式数据。为保留完整诊断，默认继续执行尚未运行的只读 operation；但身份失效、疑似凭证泄露、安全边界破坏或正式数据发生意外写入属于全局停止条件，立即跳至清理。
5. 正常完成或任何终止都进入 Flow F；不得从读取阶段直接宣布成功。

### Flow F — 补偿清理与残留复核

1. 清理由 `finally` 语义拥有，覆盖成功、失败、超时和用户取消。
2. 只消费 `temporaryRecordLedger`，逐条按明确 record ID 删除；不得按 `TEST_` 前缀模糊批量删除，不得消费权限账本，不得操作文件 token 来源记录。
3. 删除后使用独立读取路径按 record ID 和唯一执行标识复核“不存在”。删除返回成功但复核仍存在时，状态保持 `cleanup pending`。
4. 清理遇到瞬时错误时允许有界重试；每次重试记录次数、错误类别和 trace ID。超过上限后保留未清理 ID 的脱敏摘要及人工恢复入口，任务不得通过。
5. 只有临时记录全部确认不存在，才进入 Flow G。

### Flow G — 回归、证据和结论

1. 清理完成后执行相关自动化测试、完整测试和生产构建；测试失败不得重新创建临时数据。
2. 最终证据包含：runId、身份来源结论、65 项清单摘要、权限前后差异、本次新增权限记录脱敏标识、长期保留结论、文件上下文只读来源证明、临时记录创建/清理/复核结果、逐 operation 结果、测试和构建结果。
3. 只有 `expected=65`、`executed=65`、`passed=65`、`blocked=0`、`failed=0`，且清理无残留、8 项权限可追溯、测试与构建通过、秘密扫描通过，才显示“验收通过”。
4. 结论仅交付证据和任务状态建议；不提供或触发“部署”“发布”“同步正式数据”等后续动作。

## 5. 必需状态契约

这些状态应用于 CLI/日志阶段，以及复用同一执行器的内部 Web 验证入口。每个阶段必须有明确的开始、进度和终态；不能只显示旋转图标或让操作者从“点不动”推断正在执行。

| 状态 | 触发 | 内容与允许动作 | 恢复和安全规则 | 可访问性/可观察性 |
| --- | --- | --- | --- | --- |
| `normal` | 当前阶段成功完成，或 65 项中某项真实响应满足契约 | 显示阶段名、非秘密摘要、完成时间；可继续下一阶段 | 不允许跳过既定顺序；65 项结果需保留 operation ID | 输出稳定的行式文本和结构化 JSON；不用颜色作为唯一含义 |
| `loading` | 预检、快照、写入后验证、文件发现、临时记录创建、65 项读取、清理、复核或回归进行中 | 显示当前阶段、当前对象/operation、`n/total` 和已用时；允许请求取消 | 同一 `runId` 禁止重复启动；取消是协作式请求，当前不可中断远程调用结束后进入清理 | CLI 每个阶段至少输出开始和终态；Web 状态用 `role=status`/等效 live status，常规进度不抢焦点 |
| `empty` | 某项真实读取合法返回空集合 | 显示“真实空集合”，记录 `empty=true`；按契约可 passed | 不用 fixture 或默认数据填充；文件候选为空不是本状态，而是 `disabled/File context unavailable` | 清楚区分“0 条结果”“未执行”“失败” |
| `error` | 网络/5xx、契约错误、权限部分补齐失败、清理失败、测试/构建失败或安全守卫触发 | 显示失败阶段、错误类别、safe message、trace ID、下一步；若有临时记录必须先清理 | 权限未完整验证时仅回滚本次新增；完整权限不撤销；可恢复重跑前先执行遗留清理检查 | 错误必须有文字标签和非零退出码；不得打印原始错误对象中可能含秘密的字段 |
| `disabled` | 身份不符、表结构/唯一键未知、精确删除路径未确认、文件 token 不可用、已有运行锁或遗留清理未完成 | 明确列出缺失前置条件；写入、65 项读取按钮/命令不可用 | 只允许重新预检、继续清理或在外部修复后重新开始；不能手输 ID 绕过 | Web 使用真实 disabled 语义和关联说明；CLI 返回固定阻断码而非静默退出 |
| `permission-denied` | 当前身份不是 `3d8egf55`，8 项未生效，或 65 项返回 403 | 显示目标账号的脱敏标识、精确 required permission、受影响 operation | 只允许已批准的 8 项补齐；发现第 9 项立即停止，不自动授予、不改为通配权限 | 将“登录有效但权限不足”与 401/会话失效明确区分 |

附加终态：

- `cancelled-cleanup-complete`：取消已接受，未完成 operation 均非 passed，临时记录已清理并复核；可安全重跑。
- `cleanup-pending`：取消或错误后仍有 ledger 项未确认删除；只能继续清理，不能启动新 run 或宣称完成。
- `permission-rollback-complete`：8 项尚未完整建立，本次新增权限已精确回滚且基线未变；任务未通过。
- `file-context-unavailable`：没有可合法复用的 token；任务未通过，不出现上传或“继续忽略”动作。

## 6. 失败恢复、取消与幂等

### 6.1 恢复入口

每次启动先检查同任务未结束的 manifest：

- 有 `temporaryRecordLedger` 未清零：先进入“继续清理”，禁止新建记录或开始 65 项读取。
- 有“权限未完整验证”的 `createdPermissionRecordIds`：先依据快照继续精确回滚并复核。
- 已记录“8 项完整验证成功”：将其视为长期权限基线，不回滚；只重新预检其当前投影。
- 前次只有读取结果不完整且无清理遗留：生成新 runId，从预检重新开始，不把前次 passed 与本次结果拼接成 65/65。

### 6.2 取消规则

1. 取消仅表示“停止启动新的远程操作”，不强杀正在响应的单次请求。
2. 当前调用结束后，未开始项标记 `cancelled/not-executed`，随后无条件进入补偿清理。
3. 清理运行期间不提供普通取消；只能记录退出请求并在当前清理轮次后继续保存恢复 manifest。操作者关闭窗口或进程异常时，下次启动必须先恢复清理。
4. 完整验证成功的长期权限不因取消撤销；仅未完整权限阶段按本次新增 ID 回滚。

### 6.3 幂等键与重复保护

- 权限幂等键：`AD account + exact permission code`。先读后写，既有记录复用，不生成第二个有效授权。
- 执行幂等键：`taskId + runId`。同一 run 的并发第二次启动返回 `disabled/already-running`。
- 临时记录业务键：`TEST_<taskId>_<runId>_<resourceKind>`。创建后的唯一可信删除目标仍是正式 record ID，不是名称前缀。
- operation 结果键：`runId + operationId`。每个 run 的 65 个 ID 各有且仅有一个最终结果；重试记录放在同一结果的 attempt 列表，不额外冒充新 operation。
- 清理幂等：对 ledger 中已确认不存在的记录标记 `verifiedAbsent`；再次恢复时只复核，不把“已不存在”视为清理失败。

## 7. 日志、证据和秘密保护

### 7.1 可以记录

- taskId、runId、阶段、operation ID、状态、时间、耗时和计数；
- HTTP/业务状态、错误分类和 trace/request ID；
- 权限码、目标 AD 账号的脱敏显示、权限记录 ID 的脱敏/哈希形式；
- 来源表名、file token 不可逆指纹、候选兼容结论；
- `TEST_` 记录的表名、脱敏 record ID、清理和复核状态；
- 测试/构建命令名称、退出码和证据文件路径。

### 7.2 禁止记录或展示

- access/refresh/tenant token、Cookie、Authorization header、应用 ID/密钥组合、OAuth code/state；
- 完整 file token、带 token 的访问 URL、完整请求/响应 header；
- `.env` 内容、浏览器存储、原始飞书响应正文；
- 与验收无关的完整姓名、联系方式或其他个人信息。

所有异常先经过字段 allowlist 和脱敏器，再进入控制台、JSON 或 Web 状态；禁止直接 `console.log(error)`、`console.log(input)` 或序列化完整 client response。最终写证据前必须执行秘密扫描；命中时证据无效并进入 `error`。

## 8. 焦点、键盘与进度可理解性

1. 内部 Web 入口若存在，启动、取消、继续清理和重试必须是可键盘操作的具名控件；运行中相关启动控件禁用。
2. 常规 loading 不抢走焦点，不使用全屏遮罩阻断与任务无关的只读内容；当前阶段、计数和耗时在入口附近持续可读。
3. 用户发起取消后，焦点保留在取消控件或移动到一次性的“正在完成安全清理”状态；清理完成后宣布最终状态。
4. 错误、permission-denied、cleanup-pending 必须包含文本含义、受影响阶段和允许的下一动作，不依赖颜色、图标或 DevTools。
5. 并行日志不得以不可读的动态覆盖行作为唯一输出；结构化证据和最终摘要应可被屏幕阅读器、文本检索与自动验证消费。

## 9. Web 与未声明移动端差异

- **Web**：受控 CLI 是主要入口；若映射到内部 Web 验证页，使用上述非阻塞阶段状态、键盘控件和 live announcement，并继续从服务端 OAuth 会话锁定身份。
- **uni-app / 原生移动端**：未声明，不设计、不实施、不验收。本任务不能因为“响应式 Web 可在窄屏打开”而声称移动平台支持。

## 10. 设计评审检查点与开放问题

### 必须在设计批准前确认

1. 流程顺序采用：预检 → 权限快照 → 原子补齐/验证 → 文件 token 只读发现 → `TEST_` 上下文创建 → 完整 65 项读取 → `finally` 清理与独立复核 → 回归/结论。
2. 8 项长期权限和 `TEST_` 临时记录使用独立账本与相反的终态处理；不得共享清理按钮或清理函数输入。
3. 无合法文件 token、无精确删除路径、出现第 9 项权限需求或身份不符时均 fail closed。
4. 取消不会跳过清理，也不会撤销已完整验证的长期权限。
5. 交付不新增业务页面，不修改现有业务页视觉，也不触发部署或发布。

### 实施期证据问题（不改变已批准范围）

1. 权限表实际唯一性规则和字段名需由只读预检记录；不一致时停止，不猜测写入。
2. `COM-008` 与 `MAT-003` 的候选 token 是否分别满足当前契约需真实验证；若全部不兼容，结果固定为阻断。
3. `APP-010`、`CER-003`、`COM-010` 各自的精确删除与独立复核路径需在首次创建前用现有 API 能力证明。
