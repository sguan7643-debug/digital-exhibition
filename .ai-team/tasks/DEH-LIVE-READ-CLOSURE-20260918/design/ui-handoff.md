# UI Visual Handoff — 正式飞书 65 项读取全量闭环

## 1. 依据、平台与视觉边界

本视觉交接严格表达已批准的 [PRD](../prd.md) 与 [UX Handoff](ux-handoff.md)，不改变其中的流程顺序、业务规则、状态行为、恢复动作或安全边界。

设计证据：

- [Task brief](../task-brief.md)、[Decision log](../decision-log.md) 与 [Product review](../reviews/product-review.md)：身份、8 项精确权限、长期权限与 `TEST_` 临时记录的不同生命周期，以及 fail-closed 边界。
- [现有主题](../../../../src/style.css)：`--xlt-*` 色彩、字体、间距、圆角、阴影、表单焦点、强制色和减少动态效果规则。
- [既有 65 项证据](../../DEH-LIVE-101-20260914/evidence/reads-65-20260918.json)：运行器的 operation 数量、结果分类和既有状态语义。

任务仅声明 Vue Web。视觉工作限定为现有管理员运行器、阶段日志与证据报告中的状态表达；不新增业务页面、导航、弹窗体系、插画或新的视觉系统。uni-app、原生移动端和移动端安全区未声明，不设计、不实施、不验收。

## 2. 视觉方向与信息层级

沿用现有克制的企业后台语言：浅灰画布、白色有界表面、深蓝标题、蓝色操作强调、细分隔线和低阴影。运行界面按以下层级稳定呈现：

1. **运行摘要**：任务名、脱敏账号、`runId`、当前阶段、开始时间和总结果计数。
2. **阶段轨道**：预检 → 权限快照 → 权限补齐/验证 → 文件上下文发现 → `TEST_` 上下文创建 → 65 项读取 → 清理复核 → 回归/结论。仅表达进度，不允许点击跳步。
3. **当前状态面板**：阶段标题、明确状态词、`n/total`、已用时、允许动作和安全说明。
4. **逐 operation 日志**：稳定的行式列表；状态文本、operation ID、耗时和安全 trace ID 可搜索、可复制。颜色和图标仅辅助。
5. **三个隔离账本**：权限账本、临时记录账本、文件上下文账本在视觉上分区，避免误把长期权限纳入临时数据清理。
6. **最终证据摘要**：仅在清理复核和回归完成后出现；突出 `65 passed / 0 blocked / 0 failed`，并列出证据路径和秘密扫描结论。

整个运行期间不使用全屏 loading 遮罩，不覆盖导航，不拦截与本任务无关的只读内容，不以 DevTools 作为唯一状态来源。

## 4. 组件外观与变体

### 4.1 运行摘要与阶段轨道

- 摘要使用现有白色面板、16px 内边距、细边线和低阴影；任务名用 section 字号，元数据用 meta/caption 字号。
- 阶段轨道桌面端可横向排列；当前阶段使用 `--xlt-soft` 背景、蓝色左/下边强调和“执行中”文字。已完成阶段显示“已完成”，未开始阶段显示“未开始”，不允许只依赖圆点颜色。
- 不提供阶段跳转。轨道项不伪装成可点击控件。

### 4.2 状态面板

状态面板位于运行入口和日志之前，内容顺序固定为：状态标题 → 一句解释 → 进度/安全说明 → 允许动作。最小高度 112px，内边距 16px；长 trace ID 使用换行或 `overflow-wrap:anywhere`，不得触发横向页面滚动。

- 主操作使用白字蓝底；次操作使用蓝字白底和现有边线。
- 运行中只禁用会造成重复 run 的启动操作；现有日志和证据仍可滚动、选择和复制。
- “清理中”沿用 loading 变体，但标题必须明确为“正在清理临时验证数据”，并写明不能普通取消。

### 4.3 逐 operation 日志与账本

- 宽屏使用表格：状态、operation ID、安全摘要、耗时、trace ID；行高不低于 44px，表头使用浅画布底色。
- 窄屏 Web 将每行重排为两列标签/值或单列卡片；保持 DOM 阅读顺序，不只依赖横向滚动。
- `passed`、`empty=true`、`blocked/permission-denied`、`failed`、`cancelled/not-executed` 均显示完整文字标签。
- 权限、临时记录、文件上下文三个账本分别有标题和生命周期说明。临时记录账本才出现“清理状态”；权限账本明确显示“长期保留/未完整时精确回滚”；文件账本显示“只读复用”。
- 不渲染完整 token、Cookie、Authorization、原始响应正文、完整个人信息或可恢复的秘密值。

### 4.4 证据报告摘要

- 成功结论使用现有白色面板和蓝色强调，不新增绿色成功体系；标题“验收通过”与 `65 passed / 0 blocked / 0 failed` 同时出现。
- 未通过结论使用明确标题、失败阶段、错误分类、未完成计数、清理结论和下一步；不得只显示红色叉号。
- 证据路径、runId 和 trace ID 使用 caption/meta 字号并可换行；不要把路径做成无语义的装饰标签。

## 5. 必需状态的视觉表达

| 状态 | 视觉处理 | 控件与恢复表达 |
| --- | --- | --- |
| `normal / success` | 白色稳定面板；标题和完整文字结论使用 `--xlt-ink`；65 项计数、权限持久保留、文件只读复用和临时记录无残留分别成行。 | 不显示成功弹窗，不自动撤权，不出现部署/发布动作。可查看/复制证据。 |
| `loading / executing` | 当前阶段以 `--xlt-soft` 和蓝色强调；20–24px 现有旋转指示器旁显示阶段、对象、`n/total` 与已用时。可用内容保持正常对比度。 | 启动按钮 native disabled；允许的取消控件保持可用。常规进度不抢焦点。 |
| `empty` | 中性白色面板，标题“真实空集合”，正文标明 `empty=true` 与已完成请求；不显示错误边线或旋转指示器。 | 按契约可记为 passed；不得以 fixture 填充。文件候选为空必须使用 `file-context-unavailable`，不能伪装为空成功。 |
| `error` | 白色面板配 `--form-control-error` 细左边线/图标；标题、safe message、阶段、trace ID 和下一步均为文字。 | 若有临时记录，首要动作是“继续清理”；只有无遗留或清理完成后才允许重新预检/重跑。 |
| `disabled` | 控件使用既有禁用背景和文字，同时在控件附近以正常正文色显示阻断原因，例如身份未确认、已有 run 或遗留清理未完成。 | 必须使用真实 `disabled` 语义；不提供手输 ID、跳过预检或绕过安全检查的入口。 |
| `permission-denied` | 局部白色状态面板，红色细边线仅作辅助；标题“权限不足”，正文显示脱敏账号、精确 required permission 和受影响 operation，并区分于 401。 | 只允许已批准 8 项的受控补齐；出现第 9 项时显示“超出批准范围”并停止，不提供通配授权。 |
| `cleanup-in-progress` | loading 外观，标题“正在清理临时验证数据”，显示已清理/总数、当前脱敏记录 ID 和重试次数；权限账本保持“长期保留”。 | 清理阶段无普通取消按钮；关闭/异常后的恢复说明始终可见。 |
| `cleanup-failed / cleanup-pending` | error 外观，标题“临时验证数据尚未清理完成”，列出脱敏未清理记录、最后错误分类与 trace ID；不得出现“完成”或成功计数。 | 唯一主操作为“继续清理”；新 run、65 项读取和最终通过结论均禁用。 |

附加终态 `cancelled-cleanup-complete`、`permission-rollback-complete` 与 `file-context-unavailable` 使用上述 normal/error/disabled 组件外观，但必须保留 UX 规定的完整状态名称、安全结果和下一动作，不得被合并成笼统“失败”。

## 6. 响应式 Web、焦点、对比度与动态效果

### Web 响应式

- **> 1180px**：摘要、阶段轨道和日志使用完整宽度；三个账本可采用三列或两列加一列布局，列宽不得压缩关键状态文字。
- **761–1180px**：账本改为单列；阶段轨道允许换行，当前阶段仍在阅读顺序中唯一突出；日志保留表头并允许其容器局部滚动。
- **≤ 760px 的窄屏 Web**：所有面板单列，内边距 16px；阶段轨道纵向；日志行重排为标签/值块；主操作占可用宽度。该规则仅是响应式浏览器行为，不代表移动端支持。
- **最小 320px**：runId、trace ID 和证据路径换行；不得产生页面级横向滚动。

Web 控件沿用现有最小高度 36px；不新增原生移动触控规范或安全区 inset。uni-app/原生端未声明，因此无代表设备宽度、原生控件适配或移动端验收口径。

### 焦点与键盘

- 启动、取消请求、继续清理、重试和证据操作必须为具名键盘控件，按 DOM 流程获得焦点。
- 焦点使用现有 2px 蓝色 ring；`forced-colors: active` 保留现有 3px `Highlight` 轮廓。
- 常规阶段更新、进度和日志追加不抢焦点。用户触发动作后的错误只在必要时将焦点移动至一次性错误标题；否则保留在原控件或下一个允许动作。
- live status 只宣布阶段切换、取消接受、清理完成/失败和最终结论；逐条日志追加不持续打断屏幕阅读器。

### 动态效果

仅复用现有 0.72s 旋转进度动画，旁边始终有文字。`prefers-reduced-motion: reduce` 下停止旋转；状态切换不新增位移、闪烁或延迟交互的动画。现有 0.14–0.15s hover/focus 色彩过渡可保留。

## 7. Web 与 uni-app 差异

- **Web**：在现有管理员运行器、命令日志或证据报告中实现以上状态；鼠标 hover、键盘焦点、宽/窄浏览器重排和 live status 属于验收范围。
- **uni-app / 原生移动端**：任务未声明，故无界面、触控、安全区、原生导航或设备适配设计；不得因窄屏 Web 可用而声称移动端已支持。

## 8. 冲突与开放项

1. PRD 与 UX handoff 在流程、状态和平台边界上无视觉冲突。
2. 现有代码是否已有独立管理员运行器页面仍需 Web 工程实现期核实；若仅有 CLI，则相同视觉语义映射为稳定的文本段落、状态前缀和结构化证据，不因此新增业务页面。
3. 正式权限表字段、合法文件 token 候选和三个临时资源的精确删除路径属于实施证据，不由视觉设计猜测或补齐。
4. 本交接不构成设计批准、开发放行、正式数据写入授权或发布授权，也不修改 UX、任务状态、代码和飞书数据。
