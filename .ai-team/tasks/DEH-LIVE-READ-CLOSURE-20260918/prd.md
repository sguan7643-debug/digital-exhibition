## 1. 产品目标与目标用户价值

### 1.1 产品目标

在不扩大权限、不触碰非 `TEST_` 正式业务数据、不变更凭证或生产配置的前提下，为 AD 账号 `3d8egf55` 幂等补齐并长期保留 8 个明确且最小必要的业务权限码；对可由 API 精确删除的多维表记录创建、读取并清理 `TEST_` 验证数据；对 `COM-008`、`MAT-003` 只读复用现有合法文件 token，禁止新建无法确定删除或到期的飞书媒体对象；并修复仓库内可能导致权限识别或资源 ID 自动发现失败的问题。最终使正式飞书 65 项读取达到 `65 passed / 0 blocked / 0 failed`。如果不存在可复用的合法文件 token，则任务保持未通过，不得通过上传残留媒体或伪造结果绕过验收。

### 1.2 目标用户价值

- 最高权限用户可在其真实 AD 身份下获得完整、可信且可复核的正式飞书读取结果，不再因内部业务权限表缺项而收到 403。
- 验收人员可依据逐 operation 证据确认每一项读取确实访问正式飞书数据，而非 fixture、演示数据或被误归类为成功的阻断结果。
- 管理方可追溯 8 项长期权限的写入前快照、幂等补齐和持久保留，以及本任务创建且 API 可删除的 `TEST_` 多维表记录的创建、使用、补偿清理和无残留复核。

## 4. 主用户流程

### 4.1 入口

1. 验收人员从受控正式飞书读取验证入口启动任务。
2. 系统使用已完成 OAuth 的真实身份解析 AD 账号，并明确确认当前账号为 `3d8egf55`；不接受浏览器伪造身份字段。

### 4.2 权限补齐流程

1. 只读查询 `3d8egf55` 当前权限记录。
2. 保存写入前快照，对照精确 8 权限码，区分“既有”和“缺失”；既有权限永不修改或删除。
3. 仅写入缺失权限；每条新建权限记录权限码、目标账号、正式表记录 ID、写入时间和执行标识。
4. 写后重新读取权限投影，确认 8 个精确权限均生效且没有通配权限或额外权限被本任务写入。
5. 决策点：若 8 项未全部验证成功，仅回滚本次新建权限行，按写入前快照复核既有权限未变，然后停止；若 8 项全部验证成功，则标记为长期持久授权，后续读取失败也不自动撤销。
6. 决策点：若字段结构、唯一约束或权限来源与预期不一致，停止后续正式写入和读取，不进行猜测性修改。

### 4.3 资源上下文补齐流程

1. 为 5 个 operation 生成唯一执行标识，并据此建立上下文来源清单。
2. 对 `COM-008`、`MAT-003` 只读查找来源合法、当前有效且契约兼容的现有文件 token；只记录脱敏引用，不上传、不创建、不修改媒体对象。
3. 决策点：若没有可复用的合法文件 token，立即停止并将任务保持未通过；不得调用 `uploadMedia`，不得以残留媒体、fixture 或伪造 ID 继续。
4. 对 `APP-010`、`CER-003`、`COM-010`，先确认逐记录删除 API 和独立无残留复核路径，再按资源契约创建业务标识带 `TEST_` 前缀且字段最小化的多维表记录。
5. 读取上述来源并提取真实 `fileId`、`applicationId`、`certificationId`、`exportId`。
6. 决策点：若任一拟创建的多维表记录无法确认可精确清理，停止创建后续记录，对已创建记录立即执行补偿清理。

### 4.4 完整读取与结果判定

1. 使用 `3d8egf55` 和已取得的资源 ID 运行全部 65 项正式读取。
2. 对每个 operation 记录唯一 ID、输入摘要、HTTP/业务状态、真实数据来源标识、开始/完成时间及结果分类。
3. 只有真实调用成功且响应满足既有契约时才记为 passed。
4. 任一 401、403、404、409、5xx、超时、上下文缺失、降级或伪数据均不得记为 passed。

### 4.5 清理与最终结果

1. 无论读取成功、失败、超时或取消，对本任务创建且 API 可删除的 `TEST_` 多维表记录进入补偿清理阶段。
2. 按创建清单逐项删除这些临时表记录，不按模糊前缀批量删除，不触及非本次创建记录；本任务未创建媒体对象，因此清理清单不得以“删除媒体引用行”代替媒体对象清理。
3. 使用独立查询按表记录 ID 和唯一执行标识复核本任务创建的临时表记录无残留。
4. 8 项长期权限不属于 `TEST_` 数据：若已全部写齐并验证成功则永久保留；后续读取失败、超时或取消不得触发撤权。只有“本次新增但尚未形成完整 8 项有效授权”时，才回滚本次新增权限行。
5. 运行相关自动化测试和生产构建。
6. 只有同时满足 `65 passed / 0 blocked / 0 failed`、本任务创建且 API 可删除的 `TEST_` 多维表记录清理无残留、8 项长期权限可追溯、测试及构建通过、证据无秘密信息时，才输出验收通过；若无可复用合法文件 token 或存在其他阻断，则输出未通过，不得伪造成功。
