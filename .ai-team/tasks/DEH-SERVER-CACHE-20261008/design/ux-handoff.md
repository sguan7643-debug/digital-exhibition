# UX / Interaction Handoff — 服务器本地快照缓存与五秒完整读取

## 1. 文档定位

- 任务：`DEH-SERVER-CACHE-20261008`
- 阶段：`design`
- 平台：Web（Vue）
- UX 结论：缓存、快照及同步任务对用户保持透明；本任务不新增页面、路由、控件、提示气泡或操作步骤。
- 实现边界：前端源文件与前端构建产物零变更。本交接仅定义后端必须维持的现有前端可观察行为，不构成设计批准、视觉签署或开发路由。
- 批准依据：[PRD](../prd.md)、[任务简报](../task-brief.md)、[范围批准记录](../decision-log.md)、[产品范围复核](../reviews/product-review.md)。

## 2. 行为证据

### 2.1 已批准产品合同

1. 缓存命中时，实时鉴权后以 HTTP 200 返回当前授权范围内、符合 operation `successSchema` 的完整结果。
2. 无可服务缓存时，从服务收到请求起最多等待 5,000ms；五秒内完成则直接返回完整结果，五秒时仍运行则交给后台同步任务。
3. 后台同步不能随初始请求结束或客户端断开而取消；现有前端自动查询任务状态，直至 `completed` 或 `failed`，不要求用户手动刷新。
4. 飞书全部分页成功且确认零记录，才可返回并缓存完整空集合。超时、未完成、部分分页、权限失败或完整性失败不得伪装为空。
5. 前端不展示“正式飞书数据正在首次同步”“数据缺失”或同义提示；保留现有请求期间的 loading。
6. 缓存返回、同步任务查询和任务结果返回前均实时校验会话、权限、数据范围及任务归属。

### 2.2 现有前端只读证据

- [safe-proxy-client.js](../../../../src/integration/safe-proxy-client.js) 第 109–132 行：带有效 `syncId` 的处理中响应会进入自动轮询；`running` 继续查询，`completed` 返回完整结果，`failed` 抛出结构化错误。
- [safe-proxy-client.js](../../../../src/integration/safe-proxy-client.js) 第 115 行：轮询采用服务端 `pollAfterMs`，客户端将单次间隔限制在 100–5,000ms；后端必须返回正整数建议值。
- [safe-proxy-client.js](../../../../src/integration/safe-proxy-client.js) 第 183–244 行：普通请求在发起前创建 loading token，只有初始请求及后续轮询整体成功、失败或取消后才释放。
- [safe-proxy-client.js](../../../../src/integration/safe-proxy-client.js) 第 207–213 行：`FEISHU_INITIAL_SYNCING` 只有在携带有效 `syncId` 时才被静默接管；缺少 `syncId` 会产生“正式飞书数据正在首次同步”的用户可见错误，因此这种响应在本任务中被禁止。
- [safe-proxy-client.js](../../../../src/integration/safe-proxy-client.js) 第 292–346 行：批量请求同样保持一个 loading token，并对每个 HTTP 202、带 `syncId` 的处理中结果自动等待终态。
- [safe-proxy-client.js](../../../../src/integration/safe-proxy-client.js) 第 57 行：HTTP 403 被归一化为 `permission-denied`，且不可自动重试。
- [request-status.js](../../../../src/integration/request-status.js) 第 2–50 行：全局 loading 由活动请求计数和稳定 token 驱动；只要初始请求或轮询仍未终结，`isLoading` 就保持为 `true`。

## 3. 信息架构

### 3.1 用户可见层级

现有页面信息架构保持不变：

1. 用户进入现有业务页面。
2. 页面通过现有 integration client 请求业务数据。
3. 页面只感知 `loading`、完整成功结果、确认空结果、终态错误或权限拒绝。
4. 缓存来源、快照恢复、后台刷新、同步任务编号、重试次数及飞书分页过程均属于服务端内部信息，不进入页面信息架构。

### 3.2 不新增的界面元素

- 不新增“首次同步中”“数据准备中”“数据缺失”等提示气泡。
- 不新增同步进度页、任务详情页、手动刷新页或倒计时。
- 不展示 `syncId`、缓存命中类型、TTL、重试次数、快照版本或飞书分页进度。
- 不改变现有页面空态、错误承载区、导航、表单、按钮及布局。
- 不以后台刷新为由遮挡已返回的完整 stale 数据。

## 4. 核心用户流程

### 4.1 Fresh 缓存命中

1. 用户进入页面或触发现有读取动作。
2. 现有 loading 立即开始。
3. 服务端实时验证会话、权限和数据范围。
4. 服务端返回 HTTP 200 和完整 `successSchema` 数据。
5. 页面按现有逻辑渲染数据，loading 结束。
6. 用户不感知缓存命中，不出现额外提示或焦点变化。

### 4.2 Stale 但仍可服务

1. 用户发起读取，现有 loading 开始。
2. 服务端实时鉴权后立即以 HTTP 200 返回上一份完整、仍在 `max-stale` 内的数据。
3. 页面正常渲染，loading 结束。
4. 服务端在后台静默刷新；后台刷新不创建新的浏览器请求状态、不重新显示 loading、不弹提示，也不打断用户操作。
5. 后台刷新失败时，已经展示的完整结果不被替换成空态或“数据缺失”提示。

### 4.3 无缓存且五秒内完成

1. 用户发起读取，现有 loading 连续显示。
2. 服务端实时鉴权并读取飞书。
3. 五秒内完成全部分页与完整性校验：
   - 有记录：HTTP 200 返回完整数据；
   - 确认零记录：HTTP 200 返回符合 `successSchema` 的完整空集合。
4. 页面进入 `normal` 或 `empty`，loading 结束；不出现同步提示。

### 4.4 无缓存且五秒时仍运行

1. 用户发起读取，现有 loading 开始并保持。
2. 五秒时任务仍为 `running`，服务端返回现有客户端兼容的非 503 处理中合同：
   - 机器码可继续使用 `FEISHU_INITIAL_SYNCING` 以兼容现有分支；
   - 必须携带格式有效的 `syncId`；
   - 必须携带正整数 `pollAfterMs`；
   - 该机器码及内部 message 不得成为用户可见文案。
3. 现有客户端自动查询 `/operations/sync-jobs/{syncId}`；用户不操作、不刷新页面。
4. `running` 期间始终沿用同一个请求生命周期，loading 连续存在，不重复弹出或反复播报。
5. `completed`：客户端取得完整 `result`，页面进入 `normal` 或经确认的 `empty`，loading 结束。
6. `failed`：客户端收到结构化错误，页面进入 `error` 或 `permission-denied`，loading 结束。

### 4.5 批量读取

1. 批量读取只显示现有的一次整体 loading，不按子请求新增提示。
2. 任一子项进入 HTTP 202 处理中合同后，由现有客户端针对该 `syncId` 自动轮询。
3. 整批请求尚有子项未达到终态时，整体 loading 保持。
4. 每个子项按照现有 fulfilled/rejected 合同返回；不得用空集合替代失败子项，也不得展示“首次同步”提示。

### 4.6 页面离开或调用方取消

1. 用户按现有方式离开页面或触发调用方取消时，不拦截导航、不要求确认。
2. 客户端结束对应请求 token，不能留下永久 loading。
3. 服务端已接管的后台任务可继续执行，但任务结果不得主动把用户拉回原页面，也不得跨身份复用。

## 5. 六种必备状态合同

| 状态 | 触发条件 | 页面内容行为 | 允许的用户动作与恢复路径 | 焦点与读屏行为 |
| --- | --- | --- | --- | --- |
| `normal` | fresh/stale 命中、冷读取五秒内完成，或轮询返回 `completed` 且结果非空 | 按现有页面完整渲染；不显示缓存来源、同步提示或额外成功气泡 | 保持页面原有操作；stale 后台刷新不阻塞操作 | 缓存命中、后台刷新及轮询迭代不新增焦点移动；状态终结后沿用现有 `PageStateBoundary` 的结果标题聚焦与内容更新公告行为，不播报内部同步信息 |
| `loading` | 请求已开始且初始请求、五秒等待或自动轮询尚未终结 | 只保留现有“请求处理中”loading 气泡/指示；不得同时显示“首次同步”“数据缺失”或手动刷新提示 | 用户可按现有行为等待、离开页面或取消；不要求重复点击、不要求刷新 | loading 开始时由现有状态区礼貌公告一次；轮询继续时不重复公告，不形成焦点陷阱；同一请求 token 结束前保持 busy 语义 |
| `empty` | 飞书请求全部分页成功、完整性验证通过、实时权限校验通过且确认零记录 | 使用页面原有真实空态；不得使用“数据缺失”“同步中”“加载失败”冒充空态 | 保留页面原有空态动作；若原页面无动作则不新增 | 不因缓存或轮询额外移动焦点；状态终结时沿用现有 `PageStateBoundary` 的结果标题聚焦，空态与 loading/错误语义保持区分 |
| `error` | 同步任务 `failed`、网络/超时、分页不完整、schema 不符或其他非权限终态错误 | 结束 loading，交给现有错误处理；错误文案不得冒充空态，也不得使用“正式飞书数据正在首次同步” | 仅保留页面当前已有的恢复入口；若错误标记为可重试，重试必须重新走同一完整流程，不要求浏览器手动刷新 | 不新增自动跳转或焦点规则；沿用现有状态终结后的结果标题聚焦与一次错误公告，避免轮询迭代重复公告 |
| `disabled` | 仅由页面既有业务规则、集成关闭或原有控件条件触发；缓存命中、后台刷新和同步轮询本身不得新增 disabled 状态 | 沿用现有禁用内容及原因；不得因缓存刷新把已可用页面整体禁用 | 保留原有启用条件；本任务不新增按钮或恢复入口 | 沿用现有语义化禁用与键盘顺序；不创建仅视觉禁用、仍可误触的控件 |
| `permission-denied` | 初始请求或任一次任务查询实时鉴权返回 403，或权限/数据范围撤销 | 立即停止返回缓存、旧结果或任务结果；不得显示空集合，也不得泄露同步任务及其他授权范围信息 | 不自动重试；沿用现有无权限/重新授权路径，不提供绕过权限的刷新动作 | loading 结束；沿用现有 `PageStateBoundary` 将焦点移至“访问受限”标题并公告一次的行为；被拒绝内容内的操作不进入后续 Tab 顺序 |

补充：HTTP 401 按现有 `authentication-required` 登录/重新授权路径处理，不归并为空态或一般业务失败。

## 6. 内容与文案行为

### 6.1 允许出现

- 现有请求 loading 的既有文案，例如请求活动标签对应的“正在请求……”语义。
- 页面已有的正常内容、真实空态、终态错误和权限拒绝文案。
- 对运维日志可记录结构化错误、任务状态和 trace 信息，但不得把内部凭据或正式数据写入不安全日志。

### 6.2 禁止出现

- “正式飞书数据正在首次同步，请稍后重试”。
- “正式飞书数据正在首次同步”及任何要求用户稍后手动重试的同义文案。
- 将超时、部分分页、同步未完成、权限失败或 schema 错误描述为“暂无数据”“数据缺失”。
- `FEISHU_INITIAL_SYNCING`、`syncId`、内部 operation ID、缓存状态、快照状态、重试次数等技术信息。
- 因后台静默刷新而产生的成功、失败或刷新完成气泡。

### 6.3 兼容性硬约束

- 单请求的处理中响应不得缺少 `syncId`。否则现有客户端会走用户可见的“正式飞书数据正在首次同步”错误分支，属于验收失败。
- 批量子请求的处理中结果必须使用现有客户端可识别的 HTTP 202、兼容机器码和有效 `syncId`。
- `completed.result` 必须直接符合原 operation 的 `successSchema`，不能再包一层新结构。
- `failed.error` 必须是结构化终态错误；不得继续返回 `running` 文案，也不得返回伪造空结果。

## 7. 键盘与读屏交互

### 7.1 键盘

- 本任务不新增可聚焦元素，因此不改变现有 Tab 顺序、快捷键、返回行为或焦点管理；`PageStateBoundary` 在 loading 终结后聚焦结果标题、在 `permission-denied` 时聚焦“访问受限”标题的现有行为原样保留。
- loading 不得形成模态焦点陷阱，也不得强制把焦点移动到 loading 气泡。
- 缓存命中、后台静默刷新及每次轮询迭代不得新增焦点移动；只有现有页面状态组件在状态终结时执行其既有结果标题/权限标题聚焦。
- 用户离开页面时，异步任务不得阻止现有导航；请求 token 必须可靠释放。

### 7.2 读屏公告

- 请求开始：沿用现有全局 loading 状态区，礼貌公告一次正在加载；不把 operation、`syncId` 或缓存来源读给用户。
- 五秒接管与轮询：loading 保持同一生命周期，不重复播报“仍在加载”、重试次数或“首次同步”。
- 成功：停止 busy/loading 语义，按页面原有内容更新方式呈现完整结果；不追加缓存命中或同步完成公告。
- 真实空集合：读作页面原有空态，不能读作错误或数据缺失。
- 终态失败：由现有错误状态区公告一次；相同错误不得因轮询或重渲染重复播报。
- 权限拒绝：由现有权限状态区公告一次，并确保不可访问内容不再暴露给辅助技术。

现有两份只读证据能够证明 loading 信号的连续生命周期，但不证明具体 DOM 是否已配置 live region、`aria-busy` 或等效语义。由于本任务明确禁止前端修改，QA 必须核验现有 loading、错误、空态和权限状态区的读屏行为；若现状不满足上述语义，应记录为独立前端无障碍缺陷并另行立项，不得在本任务中暗改前端。

## 9. 后端交付给现有前端的交互合同

1. fresh/stale/五秒内完成：HTTP 200 + 原 operation 完整 `successSchema`。
2. 确认零记录：HTTP 200 + 原 operation 完整空集合结构。
3. 五秒时仍运行：非 503、现有客户端可识别的处理中合同，包含有效 `syncId` 和正整数 `pollAfterMs`。
4. 状态查询：只返回 `running`、`completed` 或 `failed`；`completed` 携带原 `successSchema` 的完整 `result`，`failed` 携带结构化 `error`。
5. 每次状态查询都实时鉴权；权限不符返回 403，不返回任务存在性、旧缓存或旧结果。
6. 后台刷新完全发生在服务端，不触发浏览器新的 loading、提示或焦点变化。
7. 任何路径都不得通过 503、处理中提示文案或缺失 `syncId` 把用户留在必须手动刷新的页面。

## 10. 交互验收清单

- [ ] fresh 命中：一次 loading 后直接展示完整数据，无额外气泡。
- [ ] stale 命中：立即展示完整数据；后台刷新期间页面不重新 loading、不弹提示。
- [ ] 无缓存且五秒内完成：连续 loading 后直接展示完整数据或确认空态。
- [ ] 无缓存超过五秒：不返回 503；loading 连续保持，前端自动轮询，无需手动刷新。
- [ ] 轮询 `completed`：完整结果出现，loading 结束，无“同步完成”气泡。
- [ ] 轮询 `failed`：loading 结束，进入现有错误状态，不显示空态或“首次同步”。
- [ ] 处理中合同缺少 `syncId` 的后端测试必须失败，避免触发现有首次同步文案分支。
- [ ] 批量读取有一个或多个子任务运行时，整体 loading 保持至全部子项终态。
- [ ] 飞书完整成功零记录：展示真实空态；部分分页、超时和权限失败均不能展示空态。
- [ ] 权限撤销后，下一次读取及旧任务查询进入 `permission-denied`，不泄露旧数据。
- [ ] 页面离开/取消后不残留 loading；服务端任务仍按隔离合同完成，不跨用户复用。
- [ ] loading、后台刷新和轮询迭代不新增焦点移动；终态沿用现有结果标题或权限标题聚焦，不产生额外焦点跳转。
- [ ] 读屏只公告一次 loading 起始和一次终态，不随每次轮询重复播报。
- [ ] 页面 DOM 中不出现“正式飞书数据正在首次同步”“数据缺失”或同义占位提示。
- [ ] 前端源码和构建产物的变更清单为空。

## 11. 开放问题与下游约束

### 11.1 无待决产品问题

本 UX 交接不需要新增页面、文案、用户操作或产品范围决定。所有可见行为均由已批准 PRD 和现有前端兼容合同确定。

### 11.2 技术设计必须闭环的兼容依赖

- 现有 `safe-proxy-client` 的有效普通请求超时为 30,000ms，首页聚合客户端上限为 29,500ms；部署包 Nginx API `proxy_read_timeout`/`proxy_send_timeout` 为 35s。服务端同步任务从创建起的硬上限冻结为 25,000ms，包含排队、重试、退避、飞书分页和结果归并；初始五秒等待包含在该 25,000ms 内。到期必须进入结构化 `failed`（`READ_SYNC_DEADLINE_EXCEEDED`），不得继续保持 `running`、返回 503、显示首次同步文案或要求手动刷新；终态至少保留十分钟。
- 业务投影字段白名单、测试环境真实用户 ID、总执行超时以及 `root` 到 `seaoil-deh` 的迁移/回滚命令由技术设计冻结；这些内容不得改变本交接中的用户状态、文案、焦点或轮询合同。
- UI Visual Designer 如参与，只能核验现有视觉保持不变，不得新增视觉方案、状态组件或提示文案。

## 12. 设计批准输入摘要

供后续设计批准使用的关键决策只有以下五项：

1. 前端零代码变更，缓存与同步任务完全透明。
2. 保留现有 loading，并让同一 loading 生命周期覆盖初始五秒等待和自动轮询。
3. 缓存命中或五秒内完成时直接返回完整结果；五秒未完成时由现有客户端无感轮询至终态。
4. 只移除“首次同步/数据缺失”等提示，不移除请求 loading；真实空集合、终态错误和权限拒绝严格分离。
5. Web 为唯一平台；不声明或推断 uni-app 行为。
