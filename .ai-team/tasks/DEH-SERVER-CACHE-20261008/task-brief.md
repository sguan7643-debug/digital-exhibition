# 任务简报 — 服务器本地快照缓存与五秒完整读取

## Goal

在飞书多维表格继续作为唯一业务数据库、且公司只提供当前共享服务器的前提下，为数智展厅增加受限内存缓存与服务器本地持久快照。普通读取返回符合 success schema 的完整正式数据或完整空集合，不再把“正式飞书数据正在首次同步”作为正常业务响应；固定代表读取在有有效快照或完成预热后至少 90% 于 5 秒内完成。

## User

- 已授权数智展厅 Web 用户：首次进入页面即可获得完整可用数据，或由现有 loading/轮询自动取得终态。
- 共享服务器运维人员：缓存不得挤占其他项目资源，服务身份、目录所有权、部署和回滚必须清晰可控。

## Mode / Platforms

- 现有 Vue Web 项目与现有 Node 服务的增量改造。
- Web：Vue；移动端/uni-app：未声明。
- 前端源文件和前端构建产物零变更。

## Scope

- 飞书仍是唯一业务事实来源；缓存目录固定为部署目录外的 `/home/seaoil/pre-demo/runtime-cache/`。
- Node 启动恢复有效快照，后台预热并按唯一 TTL 矩阵刷新；普通读取优先返回完整缓存。
- 无有效缓存时，从服务收到请求起最多等待 5,000ms。五秒内完成则 HTTP 200 返回完整结果；未完成则返回现有前端可识别的非 503 同步任务合同，任务不随请求结束或客户端断开取消，前端保持 loading 并自动轮询至终态。
- 同一租户下，身份、权限集合、数据范围、operation 和规范化参数全部相同的冷请求必须合并为同一任务；任一隔离维度不同，禁止合并、复用或查询。
- 每个任务总尝试次数最多 3 次，初次尝试计入；两次重试前分别退避 500ms、1,000ms，退避上限 1,000ms。`completed`/`failed` 终态至少保留 10 分钟。
- 缓存只保存业务数据投影；每次命中和任务查询前实时校验当前会话、权限、数据范围及任务归属。
- 强一致 operation、登录、审批实时状态、写入、写后确认、权限、幂等和审计直接访问实时链路，不使用 stale fallback。
- 正式业务写取消业务键和幂等键的 `TEST_` 前缀门禁，但身份、权限、必要审批、幂等和审计不得削弱；测试专用入口继续保留 `TEST_` 隔离。写成功后局部更新或精确失效，失败不污染缓存。
- 飞书全部分页成功完成且返回 0 条记录时，HTTP 200 返回符合该 operation success schema 的完整空集合并按所属 TTL 缓存；超时、分页未完成、权限失败或同步未完成不得伪装为空。
- systemd 使用专用非 root 用户和组 `seaoil-deh:seaoil-deh`。缓存目录、临时文件和快照 owner/group 均为 `seaoil-deh:seaoil-deh`；目录模式 `0700`，临时文件和快照模式 `0600`。
- 资源硬边界：CPU 1.5 核、内存 2GB、磁盘缓存 3GB、飞书同步并发最多 3 路。
- 容量超限时先清理过期任务/临时文件并按 LRU 淘汰非代表性缓存项，再减少或取消低频非代表性 operation 缓存；绝不删除 success schema 字段。若取消代表 operation 缓存，必须停止当前范围验收并触发范围变更重审。
- 交付自动化测试、性能与容量报告、完整服务器包、SHA-256、部署、验证与回滚命令；Codex 不直接执行服务器发布。

| 代表项 | 身份 | 每个适用场景样本数 |
| --- | --- | ---: |
| `POST /api/v1/homepage` | `CACHE_TEST_STANDARD` | 30 |

| `APP-002` | `CACHE_TEST_STANDARD` | 30 |
| `MAT-001` | `CACHE_TEST_STANDARD` | 30 |
| `WB-003` | `CACHE_TEST_STANDARD` | 30 |
| `ADM-003`（管理读取补充项） | `CACHE_TEST_ADMIN` | 30 |

- 每项适用场景固定为：内存命中、快照恢复、后台刷新期间、完全无有效缓存。
- 计时从服务收到请求到完整响应体发送完毕。
- `CACHE_TEST_REVOKED` 用于预热后撤权验证，不计入性能成功率。
- 测试开始时锁定同一测试 Base，报告记录 Base 标识、各表完整记录数与总记录数。全部代表项和场景使用该 Base，测试期间记录量不得缩小、替换或变化；发生变化则本轮样本作废并整轮重测。
- 有有效快照或预热完成后的样本中，至少 90% 必须在 5 秒内以 HTTP 200 返回完整结果，HTTP 202 不计入成功率。完全无有效缓存场景单独验证五秒任务接管与最终终态。

## Out of Scope

- Redis、外部数据库、新服务器资源或替换飞书。
- 缓存 token、Cookie、Secret、授权结论、附件文件本体或其他敏感材料。
- 修改任何前端源文件、前端构建产物、页面样式或轮询实现。
- 保证强一致/写操作或真正无快照的飞书冷读取必定在 5 秒内完成。
- 删除测试专用入口的 `TEST_` 隔离。
- 删除 success schema 字段、缩小测试 Base、取消代表 operation 缓存或突破资源上限来换取指标达标。
- 继续使用 root 或共享服务账号运行目标 systemd 服务。
- Codex 直接执行服务器部署或生产配置变更。

## Success Metric

- 固定代表矩阵按每项每适用场景 30 次执行；有有效快照或预热完成后的样本至少 90% 在 5 秒内以 HTTP 200 返回完整正式数据。
- 无有效缓存且五秒未完成时，五秒内返回非 503 兼容合同，后台继续；现有前端保持 loading、自动轮询并取得 `completed` 或 `failed`，无需手动刷新。
- 相同隔离键只产生一个任务，不同隔离范围无法合并或查询；单任务最多三次尝试，退避 500ms/1,000ms，终态至少保留 10 分钟。
- 飞书完整成功零记录返回 HTTP 200 success schema 空集合并缓存；超时、分页未完成、权限失败和同步未完成均不返回空集合。
- 每次缓存命中前实时鉴权；权限撤销后下一次读取和任务查询立即拒绝或收窄，不泄露旧范围数据。
- 正式业务允许合法非 `TEST_` 键写入且不削弱治理；同一幂等请求只产生一次远端副作用。
- 服务以 `seaoil-deh:seaoil-deh` 运行并从部署目录外恢复快照；目录/文件 owner、group 和模式均符合合同。
- CPU 不超过 1.5 核、内存不超过 2GB、磁盘不超过 3GB、同步并发不超过 3；容量降级不删除 success schema 字段，也不在未重审时取消代表项缓存。

## Deadline / Risk

尽快完成；不得跳过范围、设计和发布审批。风险等级为高，主要风险是正式数据快照、隔离错误、陈旧数据、systemd 身份迁移及共享服务器资源竞争。

## Dependencies 与证据

- 当前正式业务数据源是飞书多维表格，不能增加 Redis 或独立业务数据库。
- 目标服务器为 Ubuntu，Node.js `v22.23.2`，16 核 CPU、62GiB 内存、约 22GiB 可用内存、66GiB 可用磁盘。
- 当前 `digital-exhibition-test.service` 工作目录为 `/home/seaoil/pre-demo/test`、运行用户为 root、Node RSS 约 102MiB；本任务将运行身份迁移到 `seaoil-deh`。
- `vmstat` 后续样本 `si/so` 均为 0，当前无持续交换压力。
- 当前实现使用进程内读取缓存；冷请求可在 5 秒后返回 `FEISHU_INITIAL_SYNCING`，服务重启会丢失进程内缓存。
- 54 个可缓存 operation 和 11 个强一致 operation 已从 `server/feishu-read-cache-policies.mjs` 核验。
- 本简报不存在待确认产品假设；是否批准本范围由用户明确决定，并由 AI Team Lead 记录和路由。
