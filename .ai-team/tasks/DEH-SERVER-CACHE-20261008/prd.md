# PRD — 服务器本地快照缓存与五秒完整读取

## 1. 产品目标与目标用户价值

### 1.1 产品目标

在飞书多维表格继续作为唯一业务事实来源、且不增加 Redis、独立数据库或新服务器资源的条件下，为现有 Node 服务增加受限的进程内缓存和服务器本地持久快照。

普通读取命中可服务缓存时，以 HTTP 200 返回当前授权范围内、符合该 operation success schema 的完整正式数据；需要刷新时在后台静默执行。没有可服务缓存时最多等待飞书 5,000ms；五秒内完成则直接返回完整结果，未完成则交给兼容现有前端的后台同步任务。现有 Vue 前端零代码变更，继续保持 loading 并自动轮询至终态。

### 1.2 目标用户价值

- 已授权 Web 用户：稳定取得完整数据或完整空集合；冷读取超过五秒时无需手动刷新。
- 运维人员：缓存可重建、可恢复、容量受控，并由专用非 root 身份独占。
- 业务治理人员：缓存不绕过身份、权限、审批、幂等和审计；正式业务写可使用正常业务键，不再依赖 `TEST_` 前缀。

### 1.3 成功定义

- 有有效快照或完成预热后，固定代表清单中每项每个适用场景至少 30 次，至少 90% 在 5 秒内以 HTTP 200 返回完整正式数据。
- 无有效缓存且五秒未完成时，五秒内返回非 503 的兼容同步任务合同；后台继续执行，前端自动取得终态。
- 进程资源不超过 1.5 个 CPU 核、2GB 内存、3GB 磁盘缓存，飞书同步并发不超过 3 路。
- 服务重启可从部署目录外恢复快照；缓存隔离、空结果语义、写后更新、容量降级和回滚均有自动化或可复现证据。

### 2.3 同步任务合同

- 任务合并键固定由六类维度共同组成：当前会话身份、租户、完整权限集合、数据范围、operation ID、规范化参数。
- 六类维度全部相同的并发冷请求必须合并为一个同步任务；任一维度不同均不得合并、复用或互查任务。
- 每个同步任务总尝试次数最多 3 次，初次尝试计入；初次尝试失败后最多自动重试 2 次，两次重试前分别等待 500ms、1,000ms，退避上限固定为 1,000ms。总计 3 次尝试耗尽后进入 `failed`，不得无限重试。
- `completed` 与 `failed` 从进入终态起至少保留 10 分钟；查询时仍须实时校验身份和任务归属。

### 2.6 容量、运行身份与完整空结果基线

- 容量达到 2.4GB 时，先删除已过期终态任务与临时文件，再按 LRU 淘汰不在 2.5 节六项矩阵中的非代表性缓存项，并减少或取消低频非代表性 operation 缓存。
- 容量达到 2.85GB 时停止新增持久快照；3GB 是任何情况下均不得突破的硬上限。不得删除 success schema 字段或取消代表性 operation 缓存来换取容量达标。
- 若执行固定削减顺序后仍无法满足 2GB 内存与 3GB 磁盘边界，本任务验收失败并另行申请范围变更，不得自行扩大资源或返回不完整数据。
- systemd 服务运行目标固定为专用非 root 用户/组 `seaoil-deh:seaoil-deh`。`/home/seaoil/pre-demo/runtime-cache/` owner/group 必须为该用户/组，目录模式 `0700`；快照与同目录临时文件 owner/group 相同，模式 `0600`。
- 飞书调用完整成功、全部分页结束、实时权限校验通过且确认零记录时，HTTP 200 返回该 operation success schema 定义的空集合并按 2.4 节缓存。超时、分页未完成、同步未完成、权限失败或完整性失败不得伪装为空结果。

## 4. 主要用户流程

### 4.1 启动与恢复

1. systemd 以 `seaoil-deh:seaoil-deh` 启动 Node 服务。
2. 服务校验 `/home/seaoil/pre-demo/runtime-cache/` owner/group 为 `seaoil-deh:seaoil-deh`、模式为 `0700`；临时文件与快照 owner/group 相同、模式为 `0600`。
3. 仅恢复版本匹配、完整性通过、隔离元数据有效且未超过 max-stale 的快照。
4. 损坏、过期或范围不匹配的快照不参与读取；后台最多三路并发预热，但预热不作为接收普通读取的前置条件。

### 4.2 普通读取与任务接管

1. 实时验证会话、权限和数据范围，规范化参数，并构造包含租户、身份、权限集合、数据范围、operation 和规范化参数的隔离键。
2. fresh 命中：HTTP 200 返回符合 success schema 的完整结果。
3. stale 仍可服务：HTTP 200 返回最后完整结果，并启动或合并后台刷新。
4. 无可服务缓存：查找相同隔离键的运行任务；有则必须合并，无则创建任务，从请求到达起最多等待 5,000ms。
5. 飞书每一页均成功且完整结束：非空或零记录均按 success schema 形成完整结果并缓存；零记录返回 HTTP 200 空集合。
6. 五秒内任务完成：HTTP 200 返回完整结果。五秒时仍运行：返回非 503 的兼容处理中合同，任务继续。
7. 每个任务总尝试最多 3 次，初次尝试计入；初次失败后最多重试 2 次，两次重试前分别等待 500ms、1,000ms，退避上限为 1,000ms。最终进入 `completed` 或 `failed`，终态至少保留 10 分钟。
8. 前端自动轮询；每次状态查询均实时鉴权并核对任务隔离归属，任何不同隔离范围均不得读取任务。
9. 超时、分页未完成、权限失败或同步未完成分别保持错误/运行语义，绝不返回空集合。

### 4.3 写入与缓存一致性

1. 正式 operation 实时校验身份、权限、必要审批、幂等键和审计合同。
2. 合法业务键和幂等键无需 `TEST_`；测试专用入口继续执行既有前缀隔离。
3. 治理校验、飞书写入或写后确认任一失败，不修改缓存。
4. 飞书确认成功后，只更新或失效受影响的缓存；无关缓存保持可用。

### 4.4 容量控制与快照持久化

1. 仅将完整、校验通过且符合 success schema 的业务投影写入快照；不得通过删字段缩减结果。
2. 在同目录创建 `0600` 临时文件，校验完成后原子替换；失败保留上一份有效快照。
3. 达到 2.4GB 时，先清理过期终态任务和临时文件，再按 LRU 淘汰六项固定矩阵之外的非代表性缓存项，并减少或取消低频非代表性 operation 缓存。
4. 达到 2.85GB 时停止新增持久快照；任何情况下不得超过 3GB。
5. 若保持代表项缓存和完整 success schema 后仍不能满足 2GB/3GB 上限，本任务验收失败。取消任一代表 operation 缓存必须发起范围变更并重新审查。

## 5. 状态清单

| 状态 | 条件 | 预期行为 |
| --- | --- | --- |
| fresh 成功 | 年龄未超过 fresh TTL | 实时鉴权后 HTTP 200 完整返回。 |
| stale 可服务 | 超过 fresh、未超过 max-stale | HTTP 200 完整返回并后台刷新。 |
| 冷读取完成 | 无缓存且五秒内完成 | HTTP 200 完整返回并缓存。 |
| 完整空集合 | 飞书全部分页成功完成且为 0 条 | HTTP 200 返回 success schema 空集合并缓存。 |
| 请求处理中 | 五秒时任务仍运行 | 返回兼容非 503 合同，后台继续。 |
| running | 后台任务未终结 | 状态接口返回 `running`。 |
| completed | 后台任务成功 | 返回 `completed` 和完整 `result`，至少保留 10 分钟。 |
| failed | 总计最多 3 次尝试耗尽，或发生不可重试失败 | 返回 `failed` 和结构化 `error`，至少保留 10 分钟。 |
| 分页未完成/超时 | 未证明完整成功 | 不缓存、不返回空集合；保持运行或失败语义。 |
| 权限失败/权限撤销 | 实时鉴权失败或范围改变 | 拒绝或收窄，不返回缓存或他人任务。 |
| 快照无效 | 损坏、过期、版本或隔离不匹配 | 进入冷读取流程。 |
| 资源退避 | 达到并发或资源边界 | 排队、LRU、缩减非代表缓存或停止新增快照。 |
| 强一致实时 | 强一致清单及治理操作 | 绕过缓存，实时执行。 |
| 写入成功/失败 | 飞书确认成功或任一环节失败 | 成功精确更新/失效；失败不污染缓存。 |

## 6. 明确非目标 / 禁止事项

1. 不将快照变成第二业务事实来源。
2. 不修改前端，不改变现有 loading、轮询路径或兼容字段。
3. 不以后台预热完成作为普通读取准入条件。
4. 不把五秒超时返回为 503，不取消后台任务，不要求手动刷新。
5. 不在普通读取中返回“正式飞书数据正在首次同步”或同义文案。
6. 不缓存或复用身份、权限、审批、幂等、审计及强一致结论。
7. 不缓存 token、Cookie、Secret、密钥或附件二进制。
8. 不把超时、部分分页、权限失败或同步未完成伪装成空集合。
9. 不删除 success schema 字段，不缩小测试数据，不取消代表 operation 缓存以规避容量问题。
10. 不以 root 或其他共享账号运行目标服务；运行账号及缓存 owner/group 必须为 `seaoil-deh:seaoil-deh`。
11. 不全量清空缓存作为常规写后处理，不突破 CPU、内存、磁盘或并发上限。
12. 不把运行缓存或正式数据装入交付包，不由 Codex 直接部署服务器。

## 7. 范围批准前的开放问题与决策

## 8. Given / When / Then 验收标准

### AC-01：TTL 与完整返回

- **Given** 请求 operation 位于 54 项可缓存清单、实时鉴权通过且存在匹配隔离键的完整缓存
- **When** 缓存年龄位于所属 TTL
- **Then** fresh 直接 HTTP 200；stale 在 HTTP 200 完整返回后静默刷新
- **And** 用户范围 P0/普通缓存与管理范围使用 30 秒/5 分钟，租户范围 P0/普通缓存使用 60 秒/15 分钟
- **And** 返回保留该 operation success schema 全部字段

### AC-02：默认不缓存与强一致

- **Given** operation 位于 11 项强一致清单，或未列入可缓存清单
- **When** 请求执行
- **Then** 不读取、不写入 fresh/stale 业务缓存
- **And** 登录、审批实时状态、写入、写后确认、权限、幂等和审计始终实时执行

### AC-03：冷请求合并与查询隔离

- **Given** 多个运行中的冷请求具有相同租户、身份、权限集合、数据范围、operation 和规范化参数
- **When** 后续请求到达
- **Then** 必须复用同一 `syncId`，只产生一个飞书同步任务
- **And** 任一隔离维度不同的请求不得合并、复用或查询该任务

### AC-04：任务尝试、退避与终态

- **Given** 同步任务发生可重试失败
- **When** 执行任务级重试
- **Then** 每个任务总尝试次数最多 3 次，初次尝试计入，初次失败后最多自动重试 2 次
- **And** 两次重试前分别等待 500ms、1,000ms，退避上限为 1,000ms
- **And** `completed` 或 `failed` 终态自写入起至少可查询 10 分钟

### AC-05：五秒任务接管

- **Given** 实时鉴权通过且无可服务缓存
- **When** 同步在服务收到请求后的 5,000ms 内完成
- **Then** HTTP 200 返回完整结果并缓存
- **But When** 5,000ms 时仍为 `running`
- **Then** 五秒内返回兼容非 503 合同，包含有效 `syncId` 和正整数 `pollAfterMs`
- **And** 后台继续，客户端断开不取消任务，前端无需手动刷新

### AC-06：成功空集合与失败对照

- **Given** 飞书请求和全部分页均成功完成，当前授权范围记录数为 0
- **When** 服务形成响应
- **Then** HTTP 200 返回符合 success schema 的完整空集合，并按所属 TTL 缓存
- **But Given** 发生超时、分页未完成、权限失败或同步未完成
- **When** 服务形成响应或任务状态
- **Then** 不得返回或缓存空集合，必须保持对应运行或错误语义

### AC-07：权限撤销

- **Given** `CACHE_TEST_REVOKED` 已形成可服务缓存
- **When** 权限或数据范围撤销后再次读取或查询旧任务
- **Then** 实时拒绝或收窄结果，不返回旧授权数据，不允许查询旧隔离范围任务

### AC-08：固定性能矩阵

- **Given** 已按 2.5 节固定六个代表项、每项唯一适用身份和四类场景
- **When** 执行性能验收
- **Then** 每个代表项在其唯一适用身份下，对每类固定场景使用同一测试 Base 执行 30 次
- **And** 从服务收到请求计时至完整响应体发送完毕，四类场景分别报告
- **And** 有有效快照或预热完成后的样本至少 90% 在 5 秒内以 HTTP 200 返回完整结果，HTTP 202 不计入该成功率
- **And** 完全无有效缓存样本单独验证五秒内返回 HTTP 200 或合规任务合同及最终终态

### AC-09：测试 Base 锁定

- **Given** 性能测试尚未开始
- **When** 建立本轮基准
- **Then** 报告写入同一测试 Base 标识、全部相关表的完整记录数及总计
- **And** 全部代表项与场景共用该 Base
- **And** 测试期间记录量变化、数据缩小或替换会使本轮样本作废并触发整轮重测

### AC-10：容量降级保持完整合同

- **Given** 磁盘缓存达到 2.4GB 或预测将超过 3GB
- **When** 执行容量降级
- **Then** 先清理过期终态任务/临时文件，再按 LRU 淘汰六项固定矩阵之外的非代表性缓存项，并减少或取消低频非代表性 operation 缓存
- **And** 达到 2.85GB 停止新增持久快照，任何时刻不超过 3GB
- **And** 不删除任何 success schema 字段，不取消任何代表 operation 缓存
- **And** 若必须取消代表 operation 缓存，则停止按当前范围验收并发起范围变更重审

### AC-11：专用运行身份与快照恢复

- **Given** 服务部署、创建、替换或恢复快照
- **When** 检查 systemd 与文件系统
- **Then** systemd `User` 与 `Group` 均为 `seaoil-deh`
- **And** 缓存目录、临时文件和快照 owner/group 均为 `seaoil-deh:seaoil-deh`
- **And** 目录模式为 `0700`，临时文件与快照为 `0600`
- **And** 原子写入失败不破坏上一份有效快照，部署与回滚命令使用同一身份

### AC-12：正式写与缓存一致性

- **Given** 正式 operation 的身份、权限、必要审批、幂等和审计均满足
- **When** 合法业务键和幂等键不含 `TEST_`
- **Then** 不得仅因缺少前缀拒绝；同一幂等请求只产生一次远端副作用
- **And** 写成功后只更新或失效相关缓存；任一治理或写后确认失败不污染缓存
- **And** 测试专用入口仍执行原 `TEST_` 隔离

### AC-13：资源、安全与交付

- **Given** 预热、刷新、故障恢复、并发读取及服务器包生成完成
- **When** 检查运行和交付证据
- **Then** CPU 不超过 1.5 核、内存不超过 2GB、磁盘不超过 3GB、同步并发不超过 3
- **And** 缓存、日志、部署包、备份和回滚包不含 token、Cookie、Secret、其他密钥、附件二进制或运行快照正式数据
- **And** 提供修改清单、测试结果、服务器包绝对路径、SHA-256、部署、验证与回滚命令；Codex 不直接部署
