# 飞书 OAuth 授权会话持久化 PRD

## 1. 产品目标与目标用户价值

目标是在本地 Vue Web 开发服务重启后，让已完成飞书用户授权的同一浏览器恢复有效授权会话，不必因服务进程重启重复完成授权；当会话已失效、过期或无法安全恢复时，明确引导用户重新授权。

目标用户是在本地完成应用上线申请 POC、且需要多次重启开发服务的已授权业务用户。该能力减少 POC 验证过程中的重复授权阻塞，同时不降低 OAuth 回调校验、会话过期处理和登出语义的安全性。

## 3. 范围边界

### 范围内

- 仅持久化恢复既有浏览器授权所必需的服务端会话材料，存放在本机受保护、运行时、Git 忽略的位置。
- 在服务重启后，依据同一浏览器提交的既有会话标识安全恢复未失效的会话。
- 对丢失、过期、无效或不完整的会话清理不可恢复状态，并提供清晰的重新授权引导。
- 保留 OAuth `state`、回调校验、过期处理及登出语义。
- 为“授权一次 → 重启服务 → 刷新上线申请页”的路径提供自动化与浏览器验证；验证输出必须脱敏。

### 范围外

- 变更飞书应用权限、OAuth 提供方、审批提交逻辑、Base 表结构、POC 数据或其他业务功能。
- 将令牌、Cookie 或其他授权材料暴露至前端响应、浏览器可读代码、日志、测试快照或 Git 仓库。
- 生产部署、发布、GitHub 推送、主分支合并、移动端或 uni-app 实现。
- 增加第三方身份系统或替换飞书 OAuth。

## 4. 主用户流程

1. 用户从本地应用上线申请页进入，服务检查浏览器携带的既有会话标识。
2. 若没有可恢复会话，用户通过既有飞书授权入口完成授权；服务照常生成并校验 OAuth `state` 与回调。
3. 服务在回调成功后，将仅用于服务端恢复的授权会话材料写入受保护的本地运行时存储，并继续使用既有浏览器会话标识。
4. 用户或开发人员重启本地开发服务。
5. 用户刷新同一浏览器中的应用上线申请页：服务从受保护存储恢复对应且仍有效的会话，页面继续可访问。
6. 决策点：若存储记录不存在、记录不完整、已过期、验证失败或无法安全恢复，服务删除或拒绝该记录，并显示重新授权入口；不得返回敏感细节。
7. 用户主动登出时，服务同时撤销当前浏览器会话与对应持久化记录；之后刷新页面必须重新授权。

## 5. 状态清单

| 状态 | 用户可见行为 | 服务端行为 |
| --- | --- | --- |
| 成功：新授权 | 授权回调后可进入应用上线申请页。 | 校验回调后建立浏览器会话并安全写入可恢复记录。 |
| 成功：重启恢复 | 重启并刷新后保持已授权，可继续 POC 流程。 | 以浏览器会话标识读取并恢复有效记录。 |
| 加载 | 页面在检查或恢复会话期间显示既有的加载状态，不提前显示未授权结论。 | 串行完成会话检查/恢复，不泄露会话内容。 |
| 空 | 没有既有会话时显示飞书授权入口。 | 不创建空或伪造授权记录。 |
| 错误 | 不可恢复状态显示可理解的“重新授权”引导，不显示令牌、Cookie、`state` 或内部路径。 | 拒绝会话、清理失效记录（如适用）并记录脱敏诊断。 |
| 禁用 | 重新授权操作进行中时防止重复提交；完成或失败后恢复可操作状态。 | 防止同一授权流程重复建立互相冲突的会话记录。 |
| 权限相关 | 用户已授权且会话有效时可访问需要授权的页面；会话不可恢复时只能发起重新授权。 | 仍执行现有授权、回调和会话校验，不以持久化记录替代权限校验。 |

## 6. 明确非目标 / 不做事项

- 不把“服务重启后恢复会话”扩展为永久登录、跨设备登录或跨环境共享会话。
- 不修改应用上线申请、飞书审批、文件上传、Base 写入或其他业务页面的业务规则。
- 不为避免重新授权而跳过 OAuth `state`、回调、过期、登出或权限校验。
- 不以模拟授权、硬编码用户、前端令牌或日志输出替代真实授权会话。
- 不进行生产发布、外部发布或代码仓库推送。

## 7. 范围审批所需的开放问题与决策

1. **本地存储实现与位置：** 确认采用何种受保护、运行时且 Git 忽略的存储实现，并定义最小文件/目录权限与清理责任；不得写入仓库受版本控制路径。
2. **恢复有效性策略：** 确认服务重启时以何种安全方式判定持久化会话仍可用（例如到期时间与既有安全校验），以及不可确认时一律重新授权的行为。
3. **恢复期：** 确认持久化记录仅服务于本地 POC 开发进程重启，且不会被用于跨机器、跨浏览器或生产环境恢复。

## 验收标准

### 主流程

- **AC-01：首次授权与安全保存**
  - Given 用户没有有效的本地授权会话且处于应用上线申请页，
  - When 用户通过现有飞书 OAuth 流程成功完成授权，
  - Then 服务在通过现有 `state` 与回调校验后建立授权会话，并仅将恢复所需材料写入受保护、运行时、Git 忽略的本地存储。

- **AC-02：重启后恢复**
  - Given 同一浏览器已通过 AC-01 建立仍有效的授权会话，
  - When 本地开发服务重启且用户刷新应用上线申请页，
  - Then 服务恢复该浏览器的有效授权会话，用户无需再次完成飞书授权即可访问该页。

- **AC-03：不重复授权**
  - Given 同一浏览器的有效会话已在一次服务重启后恢复，
  - When 用户在该服务运行期间再次刷新应用上线申请页，
  - Then 页面保持授权状态，且不自动发起新的飞书授权流程。

### 边界与状态

- **AC-04：无会话或不可恢复会话**
  - Given 浏览器没有会话标识，或服务找不到、无法读取或无法安全恢复对应记录，
  - When 用户访问需要授权的页面，
  - Then 页面显示清晰的重新授权引导，且不会将该用户视为已授权。

- **AC-05：失效或过期会话**
  - Given 持久化会话记录已过期、无效或不完整，
  - When 用户刷新需要授权的页面，
  - Then 服务拒绝该会话、按设计清理不可用记录，并仅引导用户重新授权。

- **AC-06：登出语义**
  - Given 用户拥有可恢复的有效授权会话，
  - When 用户执行现有登出操作，
  - Then 当前浏览器会话及其对应持久化恢复记录均不可再用于恢复授权，刷新后必须重新授权。

- **AC-07：加载与重复操作**
  - Given 页面正在检查或恢复授权会话，
  - When 用户观察或尝试重复触发授权操作，
  - Then 页面显示加载/禁用状态以避免重复授权提交，并在恢复完成或失败后转为已授权或重新授权状态。

### 安全与验证

- **AC-08：不泄露敏感材料**
  - Given 任意首次授权、重启恢复、失效处理或登出流程，
  - When 检查浏览器响应、前端资源、应用日志、测试输出和 Git 变更，
  - Then 不得出现 OAuth 令牌、Cookie、授权码、`state` 原值或其他可复用授权材料。

- **AC-09：回调安全保持**
  - Given 用户进入飞书 OAuth 回调路径，
  - When `state` 校验失败、回调材料不完整或回调不合法，
  - Then 服务拒绝建立或恢复授权会话，并提供不含敏感细节的重新授权引导。

- **AC-10：验证证据**
  - Given 实现完成并具备可用的本地飞书 OAuth 配置与浏览器，
  - When 执行自动化验证及浏览器中的“授权一次 → 重启服务 → 刷新上线申请页”验证，
  - Then 两类验证均记录脱敏结果，证明 AC-02、AC-05、AC-06 与 AC-08 的行为符合本 PRD。
