# DEH-SYSTEM-POC-CLOSURE-20260927 产品需求

## 1. 产品目标与用户价值

为数智产品展厅 Web 形成一套可重复执行、可追溯、不能靠口头判断的系统整体 POC 验收闭环。产品负责人和业务验收人员能够据此确认：核心页面可访问、真实数据可读、受控 TEST_ 数据可写、应用上线申请可完成从上传到审批通过后的多表投影，且系统在常用桌面、窄屏和放大场景下没有阻断问题。

## 2. 已知事实、证据与假设

### 已知事实

- 当前仓库为 Vue Web 项目，服务入口为 `/test2/`。
- 已完成过一次真实 TEST_ 上线申请闭环：图标与附件上传、审批创建、审批通过、状态同步、上架申请、附件资料、应用索引和海能work应用详情投影均有同一申请标识和 TEST_ 归属证据。
- `test:onboarding-poc`、`test:ui-source-sync`、`test:no-mock-data` 已有通过记录。
- 全量 `npm test` 当前最先被过期的首页问候语断言阻断；实现已改为读取真实首页数据。
- `test:integration` 当前最先被过期的收藏清理提示断言阻断；页面已采用新的权限提示文案。
- 浏览器路由测试使用无授权的临时浏览器会话时会被飞书授权重定向，不能代表已授权用户的真实路由结果。
- 旧任务处于发布评审或已达到修复次数上限，不能继续混入新的系统级修改和验收。

### 假设

- 本机现有飞书授权浏览器资料可用于 POC 验收；服务重启后允许通过正常授权流程恢复会话。
- 修正首批过期测试后可能暴露新的真实缺陷，最多按治理规则执行两轮修复。
- “系统整体 POC 通过”表示本任务定义的 Web 范围通过，不等同于生产发布、外部系统生产可用或移动端通过。

## 3. 范围

### 范围内

- 修复全量测试和集成测试中与当前正确实现不一致的过期断言。
- 修复回归过程中发现的 Web 真实运行缺陷，保持授权、真实读取、TEST_ 写入和安全边界。
- 执行生产构建、无模拟数据检查、UI 源同步检查和当前已批准专项测试。
- 使用已授权飞书浏览器会话完成 30 路由桌面、360 像素宽屏和 200% 缩放回归。
- 重新执行真实 TEST_ 应用上线申请，包括图标和附件上传、提交审批、审批状态同步、详情查看及审批通过后的多表投影核验。
- 完成功能 QA、Web 代码审查、跨场景兼容性检查和发布就绪评审。

### 范围外

- 生产部署、发布、主分支合并、远程仓库推送。
- 写入、修改或删除任何非 TEST_ 业务数据。
- 绕过飞书授权、权限校验、安全门禁或失败结果。
- 建设本仓库之外的 RPA、EAD、机器人、监控或其他外部平台能力。
- 将缺少正式外部输入的生产级能力描述为完成。
- 移动端和 uni-app 实现或验收。

## 4. 用户流程

1. 启动本地 Web 服务并确认健康状态。
2. 使用现有已授权浏览器会话进入系统；如会话失效，通过正常飞书授权流程恢复。
3. 执行静态检查、全量测试、集成测试和生产构建，记录每项退出结果。
4. 对发现的阻断按“真实实现缺陷”或“过期测试契约”分类，只修复可证实的问题。
5. 使用已授权会话执行桌面 30 路由、360 像素和 200% 缩放浏览器回归。
6. 创建唯一 TEST_ 上线申请，上传真实图标和附件，提交审批并同步到最终审批状态。
7. 读取上架申请、附件资料、应用索引和海能work应用详情，核验唯一性、归属、审批实例和文件投影。
8. 汇总功能 QA、兼容性 QA、代码审查和发布就绪结论；任何阻断未关闭时不得结论为通过。

## 5. 必须覆盖的状态

- 正常：页面、筛选、跳转、上传、提交、查看和状态刷新可用。
- 加载：请求期间有可理解的等待状态，不重复发起完整业务请求。
- 空数据：页面提供明确空态，筛选重置和清空仍可操作。
- 错误：网络、飞书读取或审批失败显示可行动提示，并保留可用旧数据。
- 禁用：提交中、无权限或缺少必填项时，操作不可重复触发。
- 权限要求：授权失效必须进入正常授权恢复流程，不输出无法理解的裸 JSON 页面。
- 窄屏与放大：360 像素和 200% 缩放下核心内容、导航和操作可达。

## 6. 非目标

- 不证明生产环境容量、灾备、长期稳定性或第三方 SLA。
- 不以修改测试来掩盖真实产品缺陷。
- 不批量制造无业务价值的飞书记录；测试数据必须唯一、可追溯且使用 TEST_ 前缀。
- 不承诺本任务范围外的所有菜单都具备完整生产业务能力。

## 7. 决策与待确认项

- 本任务按 Web 系统整体 POC 收口，不包含生产发布。
- OAuth 会话跨服务重启的长期持久化仍属于独立任务；本 POC 允许通过正常授权流程恢复会话，但不允许绕过授权。
- 实际修复需等本任务范围和设计分别获得明确批准后开始。

## 8. 验收标准

### AC-01 自动化与构建

Given 当前任务代码与配置，When 执行 `npm test`、`npm run test:integration`、`npm run build`、`npm run test:no-mock-data` 和 `npm run test:ui-source-sync`，Then 所有命令退出码为 0，且不存在通过删除有效覆盖、放宽安全门禁或引入模拟业务数据获得的假通过。

### AC-02 已授权桌面路由

Given 有效飞书授权会话，When 执行 30 条声明路由的桌面浏览器回归，Then 每条路由均进入预期页面，不出现白屏、未处理异常、资源 500 或意外授权循环。

### AC-03 兼容性路由

Given 同一有效授权会话，When 在 360 像素宽度和 200% 缩放下执行声明路由，Then 核心导航、内容和主操作均可访问，且没有阻断级重叠、裁切或不可点击问题。

### AC-04 真实上线申请闭环

Given 唯一 TEST_ 申请数据和真实测试文件，When 完成上传、提交审批、审批通过和状态同步，Then 我的申请与详情页显示同一申请、审批实例、申请人、授权用户、授权部门、图标和附件信息。

### AC-05 批准后多表投影

Given AC-04 已完成，When 读取上架申请、附件资料、应用索引和海能work应用详情，Then 每类记录均可由同一申请标识唯一关联，属于本次 TEST_ 运行，文件数量和审批实例一致，无重复或串单。

### AC-06 数据与权限边界

Given 任何写入或清理动作，When 服务执行操作，Then 只允许处理当前运行账本中的 TEST_ 数据，非 TEST_ 数据和授权门禁保持不可绕过。

### AC-07 最终结论

Given 自动化、构建、浏览器回归和真实闭环证据齐全，When 功能 QA 与兼容性 QA 完成复核，Then 阻断缺陷为 0 才能给出“系统整体 POC 通过”；否则必须列明未通过项，不得虚报。
