# Design Review

## Findings

### Finding: Build/import side effects and deployment-package controls are now decision-ready

- **PRD Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/prd.md` §§2.1, 3.1–3.3, AC-B01, AC-B02, §4.2 and §7.1 require zero Feishu prewarm/network calls during Vite build, configuration load, and test import; prewarm only after actual Node service startup; a backend-only candidate tied to SHA-256; deploy, verify, and rollback commands; and no direct deployment by Codex.
- **Aggregate Design Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design-handoff.md` “Cross-Source Traceability” now identifies PRD AC-B01/AC-B02 as authoritative, explicitly marks UX/UI inapplicable to the internal startup mechanism, and requires side-effect-free construction/config imports plus separate zero-call tests. “Startup and Deployment Artifact Decisions” specifies listener-before-prewarm ordering, build/config/test-import coverage, backend-only package exclusions, ZIP plus sidecar and in-package hashes, deploy/READY/live/contract/resource-limit verification, directory-swap rollback commands, and no upload or server execution.
- **UX Source Handoff Evidence:** not applicable: UX does not own build/config/test-import trigger mechanics, artifact checksums, or deployment commands; comparison performed against `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ux-handoff.md` §§1, 2.3 and 11.3, which consistently preserves the backend-only boundary and later evidence gates without contradicting AC-B01/AC-B02.
- **UI Source Handoff Evidence:** not applicable: UI does not own server startup, packaging, checksum, deployment, verification, or rollback mechanics; comparison performed against `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ui-handoff.md` §§1–3 and 10–11, which consistently requires zero frontend/root-`dist` visual change and introduces no conflicting package behavior.
- **Impact:** The earlier false four-source traceability is removed. Engineering and QA now have explicit, testable boundaries for import purity, one-time real-server prewarm, artifact integrity, operational verification, recovery, and the prohibition on direct deployment.
- **Recommendation:** Preserve this PRD-authoritative trace exactly in implementation handoff and automated evidence. Treat any prewarm/token/read call before successful Node listener startup, missing package hash/manifest/command set, inclusion of sensitive/runtime material, or direct server action as a failed boundary criterion.

### Finding: Formal-name projection failure now has one exact terminal contract

- **PRD Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/prd.md` §5.1 requires every error to have a stable HTTP/code mapping and mandatory `retryable`; §5.2 and AC-S01 require APP-001/002/003 to fail structurally when required formal names cannot be resolved and prohibit ID fallback or partial success. The design correction supplies the previously missing bounded mapping without changing those product semantics.
- **Aggregate Design Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design-handoff.md` “API and State Decisions” item 7 fixes successful-upstream-but-unresolved-required-name failures to direct HTTP/status 422 and sync `failed.error` status 422 with `code="NAME_PROJECTION_INCOMPLETE"` and `retryable=false`. It separately preserves transient Feishu network, rate-limit, timeout, and upstream failures as their specific 502/503/504 contracts with their actual retryability.
- **UX Source Handoff Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ux-handoff.md` §5.1 distinguishes successful upstream reads with unresolved required owner/developer/department names from transient name-lookup failures; §6.1 repeats the direct and nested terminal mappings; §10 requires separate direct-response and sync-failure evidence for both branches, including no `completed.result`, ID-as-name, partial APP success, or empty-success degradation.
- **UI Source Handoff Evidence:** not applicable: UI does not choose server HTTP status, nested terminal status, error code, or retryability; comparison performed against `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ui-handoff.md` §§7.1–7.2, which consistently maps projection and upstream failures to the existing error surface and forbids partial cards, empty-state substitution, or ID fallback.
- **Impact:** Direct responses, sync-job terminal errors, schemas, tests, and client recovery now have one deterministic classification. A non-transient data-quality failure cannot be retried as an upstream outage, while a transient upstream fault cannot be collapsed into a non-retryable projection failure.
- **Recommendation:** Mirror the exact distinction in machine schemas and contract tests: direct 422 versus poll transport 200 with `state="failed"` and nested status 422 for `NAME_PROJECTION_INCOMPLETE`; preserve each transient upstream code/status/retryability in both paths.

### Finding: Six states, accessibility, and responsive Web behavior remain aligned

- **PRD Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/prd.md` §§5.5–5.6 distinguishes success/normal, loading/sync, genuine empty, error, disabled, and permission-dependent behavior, while keeping 401 authentication separate; §§3.2–3.3 require zero frontend/root-`dist` change and define Web as the only platform.
- **Aggregate Design Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design-handoff.md` “UX/Interaction Evidence,” “UI Visual Evidence,” “Cross-Source Traceability,” and “Engineering Boundaries” preserve the six mutually exclusive states, separate 401 handling, one loading lifecycle, one terminal update, existing focus/announcement behavior, Web-only scope, and zero frontend visual changes.
- **UX Source Handoff Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ux-handoff.md` §§6–10 defines triggers, content, actions, recovery, focus, and announcements for `normal`, `loading`, `empty`, `error`, `disabled`, and `permission-denied`; it prevents repeated poll announcements, focus theft, stale-tree clearing, permission-as-empty behavior, and cross-page loading residue. Mobile/uni-app is explicitly not declared.
- **UI Source Handoff Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ui-handoff.md` §§3 and 5–10 preserves the existing tokens, text scaling, contrast pairs, `:focus-visible`, forced colors, reduced motion, keyboard order, semantic disabled behavior, 44–48px narrow-Web targets, safe areas, local horizontal scrolling, and all existing Web breakpoints. It prohibits new components, variants, copy, assets, responsive rules, or Figma work.
- **Impact:** The backend contract can drive existing Vue surfaces without introducing duplicate announcements, focus jumps, false empty/disabled states, inaccessible controls, undeclared mobile behavior, or visual drift.
- **Recommendation:** Keep task-attributed frontend source and root `dist` at zero diff. Web QA should verify all six states, 401/403 separation, long real names, text scaling, keyboard-visible focus and recovery, live regions, forced colors, reduced motion, touch targets, safe areas, and representative widths on both sides of existing breakpoints. Record Mobile/uni-app as not applicable.

### Finding: Privacy, authorization, and sensitive-data boundaries remain consistent

- **PRD Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/prd.md` §§4.1, 5.1–5.4 and AC-P01–AC-P07 require the six-dimension isolation key, authorization before result release, COM-004 self-only access, no raw contacts in shared/persistent storage or logs, current-user WB/favorites, preserved approval/idempotency/audit controls, and same-origin file delivery without Feishu tokens.
- **Aggregate Design Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design-handoff.md` “API and State Decisions” excludes contacts from shared cache, persistent snapshots, logs, and cross-user results; preserves 401/403/404 semantics; prevents writes/downloads from bypassing controls; and limits diagnostics to safe correlation fields.
- **UX Source Handoff Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ux-handoff.md` §§4.2–4.7, 5.2 and 5.4–5.7 requires real-time owner/permission/scope checks before cache/task release, owner-only short-lived COM-004 results, fixed cross-user rejection, no uncertain-write auto-replay, and material/file binding through a same-origin no-store delivery path.
- **UI Source Handoff Evidence:** `.ai-team/tasks/DEH-SERVER-REAL-DATA-20261010/design/ui-handoff.md` §§7.1–7.2 keeps 401, 403, 409, no-file, projection, upstream, and download outcomes on distinct existing surfaces and prevents restricted contacts, cached content, partial records, or files from entering the visible tree.
- **Impact:** Cache and sync performance do not weaken identity, privacy, data-scope, approval, idempotency, audit, or file-access controls, and restricted data cannot be exposed through recovery or visual fallback.
- **Recommendation:** Preserve these boundaries in implementation and require two-user isolation, revoke-before-release, negative contact cache/log, idempotency/version conflict, file-binding/same-origin, and sanitized-trace evidence before later quality gates claim success.
