# Task Brief

## Goal

交付应用上线申请的完整 Web POC：从应用中心进入、查看并填写真实表单、提交海能Work飞书审批、查看本人的申请列表与详情，并同步展示真实审批进度。为完成闭环，允许新增缺失页面、接口、飞书表与字段，以及可清理的 `TEST_` 验证数据。

## User

需要申请应用上线并持续查看本人审批进度的已授权Web用户，以及验证申请结果的业务运营人员。

## Mode

现有 Vue Web 项目增强。复用现有申请表单、飞书授权、审批实例服务和多维表格投影能力。

## Platforms

- Web：Vue。
- Mobile：未声明。

## Scope

- 应用中心提供申请入口和我的申请入口。
- 申请表单使用真实飞书目录与字典数据。
- 海能Work申请提交真实飞书审批并写入上架申请记录。
- 当前用户可查看自己的申请列表、单条详情及最新审批状态。
- 飞书侧审批结果可在页面刷新后同步展示。
- 新建完整闭环所缺失的页面、路由和接口。
- 对指定飞书 POC 多维表格执行幂等补表、补字段；不得删除或破坏既有结构。
- 真实数据为空时创建可追踪、可清理且带 `TEST_` 标识的验证数据。
- 海能Work应用图标及申请附件真实持久化，并可在详情中核验。
- 覆盖加载、空态、失败、重试、成功与无编号状态。
- 自动化测试、真实浏览器 POC、验证数据清理能力和构建回归。

## Out of Scope

- 不在本系统内实现飞书审批人的审批操作界面。
- 不删除或改坏既有飞书表和字段，不批量处理历史业务记录。
- 不重做RPA或其他应用类型后端。
- 不实现移动端，不执行部署、发布、推送或合并。

## Success Metric

用户可从应用中心完成一条真实海能Work申请，在“我的申请”看到记录并打开详情；飞书审批状态改变后，页面能够刷新为同一实例的最新状态；缺失页面、接口、表、字段、附件链路和验证数据均已补齐并有真实证据，全流程不依赖前端模拟业务数据。

## Deadline

尽快完成当前POC验证。

## Risk

高风险。主要风险是飞书审批实例与多维表格投影的最终一致性、远端表结构变更、验证数据污染、附件泄露、重复提交和状态同步。通过指定POC数据源、只增不删的幂等结构变更、`TEST_` 数据隔离、当前用户过滤、失败重试、状态核对和可清理清单控制。

## Dependencies

- 当前飞书用户授权会话可用。
- 飞书应用凭据、审批接口和多维表格“上架申请”表可用。
- 当前凭据具备在指定 POC 多维表格中创建表、字段和验证记录的权限。
- 现有 `T005` 海能Work审批和上架申请投影继续作为提交主链路。
- 用户确认本任务范围与设计后才进入实现。
