### 1.2 必须保留的 UX 决策

1. 应用中心提供“应用上线申请”与“我的申请”；个人中心“我的申请”进入统一列表。
2. `/apps/onboarding/apply` 保持 UX 规定顺序：页面标题与说明 → 依赖/权限状态 → 申请人身份 → 应用基础与 T005 详情 → 授权用户与授权部门 → 图标与附件 → 提交与恢复反馈。
3. `/apps/onboarding/status` 无 query 时只显示当前用户的 `APP_ONBOARDING`，按提交时间倒序；不增加搜索、批量操作或跨用户筛选。
4. `/apps/onboarding/status?applicationId=…` 使用 `applicationId` 作为路由主键；详情内容按 UX 规定顺序展示，`instanceId` 仅为详情数据。
5. 详情进入时对既有实例自动同步一次；手动刷新每次只查询一次；不做 WebSocket、SSE、持续轮询或重复完整提交。
6. 同一 attempt 的业务键、幂等键、表单快照和上传关联保持稳定；“结果待确认”只能继续确认原 attempt。
7. 权限受限、不存在和非本人场景不泄露业务字段、ID、附件或缓存内容；附件访问不展示原始 file token。
8. `PENDING` 不表达已发布；只有 `APPROVED` 允许表达发布投影；`REJECTED/CANCELLED` 不发布；未知状态绝不映射为通过。

## 5. 申请页 `/apps/onboarding/apply`

### 5.1 内容与卡片顺序

严格按 UX 顺序渲染，视觉重排不得改变 DOM/读屏顺序：

1. 面包屑、页面标题、说明、飞书授权/返回动作。
2. 页面级依赖、权限、服务门禁或错误状态。
3. 申请人身份。
4. 应用基础信息与 T005 应用详情。
5. 授权范围；适用部门必须在适用用户之前。
6. 应用图标与普通附件。
7. 备注及提交/取消/恢复反馈。

不因视觉整洁改变现有表单合同内仍生效的字段或必填性；不新增 POC schema、TEST_ 数据或清理管理界面。

### 5.2 表单分组

- 每个 `fieldset` 为白色表面，1px `#d9e4ee` 边框，7px 圆角，桌面内边距 18px 16px，组间距 12px。
- `legend` 使用分区标题色，前置 23px 蓝色编号圆点；`2.1` 可使用宽度自适应的小胶囊，避免文字挤压。
- 标签在控件上方；必填标记红色星号同时配合可感知“必填”文本/语义，不能仅靠星号。
- 控件常态：白底、1px `#7891a8` 可识别边界、4px 圆角；hover 使用现有 `#8da9c4` 并保持边界可见；focus 见 10.2；错误态使用 `#c62828`/`#a52222`。
- 帮助文字与字数提示使用 `#61758c`，紧邻对应控件；字段错误位于帮助文字之后，使用错误图标/文字，不能只改边框。
- 目录/字典尚不可用时，只使受影响控件进入 busy/disabled；已填写的无关字段保持可见，不以全页遮罩清空上下文。

### 5.3 文件上传

申请页只呈现两个用途明确的上传分组，不出现“资源压缩包”：

| 变体 | 说明 | 文件规则 |
| --- | --- | --- |
| 应用图标 | 必填；上传区可在成功后显示缩略图和真实元数据。 | 最多 1 个；PNG/JPEG/WebP；≤5MB。 |
| 申请附件 | 日常表单可选；真实 POC 验收至少 1 个。 | 最多 3 个；单个 ≤20MB；PDF/DOCX/XLSX/PNG/JPEG。 |

- 未选择：白色或 `#fbfdff` 底、1px `#7891a8` 虚线边界，上传图标/“选择文件”文字为 `#0060a6`；说明完整列出类型、数量、大小。
- 待校验/上传中：提示蓝表面；文件行显示 spinner、文件名和“正在校验/上传”，只禁用该文件重复上传与提交，不锁死其他字段。
- 成功：成功绿状态文字 + “已上传”；显示文件名、大小、MIME、SHA-256 摘要和上传时间。SHA-256 可换行/选择，不能截断后失去完整可访问值。
- 失败：对应文件行使用错误表面，显示服务端可行动原因及“重试此文件”；其他文件与表单保持正常。
- 移除：原生按钮，动作名包含文件名；完成后文件行移除并在 polite live region 宣布。不得显示原始 file token。
- SVG、HTML、脚本、可执行文件、ZIP/RAR/其他压缩包和白名单外类型没有灰色“尝试上传”路径；选择/服务端拒绝后明确说明，不显示为已上传。

### 5.4 错误摘要

- 阻塞性校验失败时，错误摘要置于表单首个字段组之前、依赖状态之后；`role=alert`。
- 外观：`#fff5f5` 底、1px `#efb8b8` 边、左侧 4px `#a52222` 强调、7px 圆角、16px 内边距。
- 标题格式：“请检查以下 N 项”；下方为按 DOM 顺序排列的字段错误链接。链接使用可读错误红并带下划线，激活后聚焦对应字段。
- 字段本身同时显示错误文本和 `aria-invalid=true`；摘要不能替代字段级错误。
- 网络/提交错误不伪装成字段错误；“结果待确认”使用警示黄表面和“继续确认提交结果”动作，只恢复原 attempt。

### 5.5 提交动作区

- 顺序保留 UX 动作：取消、提交；若现有非 T005 “保存草稿”继续存在，不得让其改变 T005 幂等和持久化合同，也不得把浏览器会话草稿描述为服务端持久化成功。
- 主提交按钮蓝底白字；取消为白底蓝字。提交中按钮保持焦点，显示“提交中…”和非纯动画的忙碌名称，`aria-busy=true`。
- 因四项预写门禁、上传中或依赖不可用而禁用时，在动作区上方以正文色说明原因，并通过 `aria-describedby` 关联；不提供“忽略检查/仍然提交”。
- 明确成功不展示独立泛化成功页，按 UX 直接进入同一 `applicationId` 详情；瞬时成功反馈只供 live region 使用。

## 7. 申请详情 `/apps/onboarding/status?applicationId=…`

### 7.1 内容顺序与版面

严格按以下 DOM/读屏顺序：

1. 返回我的申请；页面标题 `<应用名称> 上线申请`，名称缺失时“上线申请详情”。
2. 状态摘要：状态、当前节点、最近同步时间、刷新动作。
3. 标识信息：`businessId`、`applicationId`、`resourceId`、`instanceId`。
4. 应用信息：名称、编码、类型、业务域。
5. 申请信息：申请人、提交时间、完成时间、退回原因。
6. 授权范围：授权用户、授权部门。
7. 图标和申请附件：真实元数据与服务端允许的查看/下载动作。

- 页面使用单列主叙事；宽屏下“应用信息/申请信息”或“标识信息/授权范围”可视觉并排为两张等高卡片，但 DOM 顺序不变，1180px 以下恢复单列。
- 每张卡片白底、1px `#d9e2ec`、7px 圆角、16–18px 内边距；分区标题左侧使用 3px 蓝色短条。
- 信息项采用 156px 标签 + 自适应值的定义列表；760px 以下标签缩至 128px，极窄宽度改为上下排列。
- 可选值缺失显示“—”；`instanceId` 缺失必须显示“暂无审批跟踪编号”，不能用普通占位符。
- ID、长文件名和 SHA-256 使用 `overflow-wrap:anywhere`，可选择复制，不产生页面级横向滚动。

### 7.2 状态摘要

- 状态摘要是标题后的第一张主卡片。左侧为中文状态徽标和当前节点/同步时间，右侧为“刷新审批状态”；窄屏改为先摘要后按钮。
- 自动同步时保留已读内容，只在摘要区域显示 spinner 与“正在同步”；不得用全页 loading 覆盖详情。
- 同步失败时在摘要下显示局部错误：“状态同步失败，以下为 <时间> 的最后成功结果”，并提供“重新刷新”；旧值仍可读且明确标注时间。
- 无 `instanceId` 时刷新动作视觉禁用，旁边显示可读说明“暂无审批跟踪编号”；其他详情和附件动作不受影响。

### 7.3 状态徽标变体

所有徽标包含机器状态对应的中文文本，不使用纯圆点：

| 机器状态 | 显示 | 视觉 | 含义限制 |
| --- | --- | --- | --- |
| `PENDING` | 审批中 | `#174a7a` 字、`#eef6ff` 底、蓝色小圆/时钟图形 | 当前节点、最近同步时间；不得出现“已发布”。 |
| `APPROVED` | 已通过 | `#165f45` 字、`#f0faf6` 底、勾形图形 | 展示完成时间；仅该状态可核验发布投影。 |
| `REJECTED` | 已拒绝 | `#a52222` 字、`#fff5f5` 底、叹号/叉形图形 | 展示完成时间和有值的退回原因；不发布。 |
| `CANCELLED` | 已取消 | `#8f2d24` 字、`#fff5f5` 底、停止形图形 | 展示完成时间和有值的原因；不发布。 |
| 未知/缺失 | 状态暂不可确认 | `#664c12` 字、`#fffae8` 底、问号图形 | 显示最后成功同步时间并允许重新刷新；绝不按通过处理。 |

### 7.4 审批时间线

- 时间线是状态摘要下的只读视觉化，不增加流程步骤或审批操作。
- 只渲染服务端/持久化记录已提供的事实。最小可用数据下显示“提交申请（提交时间）”与“当前审批节点/最终结果”；若服务端提供真实审批事件，可按时间追加。不得虚构审批人、未来节点、预计时间或已完成步骤。
- 宽屏为水平时间线，节点间线使用 `#7891a8`；当前节点使用蓝色实心圆与 2px 蓝边；已完成节点使用绿色勾；拒绝/取消终点使用红色图形。760px 以下改为纵向时间线。
- 每个节点都有可见标题与时间；颜色、连线和图标均为辅助。未知状态不点亮“通过”节点。
- 时间线不改变详情语义顺序；读屏使用普通有序列表，装饰线 `aria-hidden=true`。

### 7.5 图标与附件详情

- 应用图标独立为 74×74px 预览框，白底、`#d9e2ec` 边框、7–8px 圆角；无法安全预览时显示文件类型图标和“查看图标”动作，不显示破损图片。
- 普通附件宽屏使用语义表格，列为文件名、类型/大小、SHA-256、上传时间、操作；窄屏转为逐项卡片，字段标签保持可见。
- “查看”仅在服务端声明可安全内联时出现；“下载”按服务端能力出现；动作名称包含文件名。DOCX/XLSX 不新增在线转换。
- 单文件授权失败在该文件行显示；410 过期提示“重新获取访问权限”，不复用旧 URL；其他附件和详情不被清空。
- 无附件是详情的局部 normal：“暂无附件”；不是页面级 empty。

## 8. 六态视觉合同

六态由真实请求和权限结果驱动，不使用测试 query 伪造。状态样式可复用，但内容、动作、恢复、焦点和数据可见性严格遵循 UX。

### 8.1 申请页

| 状态 | 视觉处理 | 保留动作与可访问性 |
| --- | --- | --- |
| `normal` | 白色分组完整显示，当前上传状态贴近对应文件。 | 编辑、上传/移除、取消、提交；进入页聚焦主标题，Tab 按 DOM 顺序。 |
| `loading` | 初始依赖提示使用提示蓝面；上传/提交仅在作用域内显示 spinner 与 busy 文案。 | 初始可返回应用中心；抑制同作用域重复动作；不抢焦点。 |
| `empty` | 表单前显示白色空态卡 + 蓝色信息边，说明真实目录/字典不足。 | 返回应用中心、重试读取；提交不可激活；不出现 TEST_ 数据创建动作。 |
| `error` | 页面级错误摘要、字段级错误或单文件错误各自就近显示；结果待确认用警示黄。 | 读取重试、单文件重试、明确失败修正、原 attempt 继续确认；校验后聚焦首个无效字段。 |
| `disabled` | 保留页面和已填内容；受影响控件灰底，动作区显示正文色原因。 | 返回/查看仍可用；无绕过门禁入口；禁用原因通过 `aria-describedby` 关联。 |
| `permission-denied` | 不渲染业务字段/候选项；显示单一白色受限卡、错误图形和标题。 | “完成飞书授权”后“返回应用中心”；聚焦受限标题，`role=alert`；不保留旧数据。 |

### 8.2 我的申请列表

| 状态 | 视觉处理 | 保留动作与可访问性 |
| --- | --- | --- |
| `normal` | 表格/窄屏卡片和状态徽标。 | 打开详情、发起申请；加载完成 polite 宣布条数。 |
| `loading` | 首次使用表格骨架行或状态面；后台重取可保留可信旧结果并降低非必要交互。骨架不进入读屏。 | 可离开页面；重试按钮保持焦点；列表 `aria-busy=true`。 |
| `empty` | “暂无上线申请”空态卡，不显示伪表格。 | 发起申请、返回应用中心；`role=status`，不自动跳焦点。 |
| `error` | 错误红状态卡，不能出现“0 条”。 | 重试、返回应用中心；成功后聚焦列表标题或空态标题。 |
| `disabled` | 保留标题；列表区域不渲染业务行，显示灰色不可用状态卡。 | 仅返回应用中心；说明非用户可修复原因。 |

### 8.3 申请详情

| 状态 | 视觉处理 | 保留动作与可访问性 |
| --- | --- | --- |
| `normal` | 完整详情；可叠加状态摘要内“同步中”。 | 刷新、附件、返回；进入聚焦详情标题，自动同步不移焦。 |
| `loading` | 首次读取使用详情骨架/状态面；自动同步只替换摘要局部。 | 首次仅返回列表；自动同步保留其余只读内容和附件。 |

## 9. Web 响应式规则

### 9.1 断点与重排

断点沿用现有实现，不另建移动信息架构：

| 宽度 | 视觉行为 |
| --- | --- |
| `>1400px` | 申请页最多四列表单；列表语义表格；详情信息卡可两列；页面内边距 18–22px。 |
| `1181–1400px` | 申请四列降为两列，上传两大区改为单列；列表仍可保持表格；详情在空间足够时两列。 |
| `901–1180px` | 详情和复杂面板单列；标题操作仍可同行，空间不足可换行；侧栏保持现有 220px。 |
| `761–900px` | 申请页标题和页面级动作纵向；表单两列或单列依容器宽度；列表在列标题不可读前切卡片，不引入页面横向滚动。 |
| `≤760px` | 使用现有顶部 56px + `env(safe-area-inset-top)`、导航抽屉和单列主内容；页面内边距 10–12px；表单、列表卡片、详情、附件、时间线全部单列；主要触控目标 ≥44px。 |
| `320–639px` | 操作按钮可满宽堆叠；定义列表标签/值上下排列；长 ID、哈希、文件名强制可断行；不得产生整页横向滚动。 |

### 9.2 Resize 与密度

- 断点切换只改变布局和密度，不改变字段、必填、状态含义、权限、文件规则或动作可达性。
- 表格转卡片时使用同一数据和 DOM 语义映射，不复制两套可能不同步的业务状态。
- 页面可在 320px 至宽屏工作；浏览器缩放 200% 时保持单列可读和所有动作可达。
- 壳层抽屉打开后背景 inert、焦点困在抽屉，Escape/关闭后返回菜单触发器；任务页不覆盖该行为。

### 9.3 Web 安全区与触控

- Web 窄屏继续使用壳层已有 `env(safe-area-inset-top/right/bottom/left)`；任务页面不重复叠加顶部安全区。
- 底部动作区不是固定悬浮条，避免遮挡浏览器 UI；若实现粘性反馈，必须为底部 safe area 预留空间并不得覆盖最后一个字段。
- 44px 最小触控目标适用于移动 Web 的主按钮、附件动作、刷新、返回和抽屉动作；桌面可保持 38–42px 紧凑密度。

## 10. 交互视觉与可访问性

### 10.1 Hover、active 与 disabled

- 蓝色主按钮 hover 变为 `#00528e`，active 可保持同色并轻微降低阴影；不使用缩放导致布局位移。
- 次按钮 hover 使用 `#eff7fc`/`#f7fbfe`，边框加深；文本链接 hover 增加下划线并保持颜色对比。
- 只读信息卡不显示可点击 hover；可打开列表项使用边框/阴影变化，同时保留明确详情链接。
- disabled 不响应 hover、不使用 `cursor:wait` 表达永久禁用；只有进行中使用 busy/wait。禁用原因始终可见。

### 10.2 键盘可见焦点

- 保留现有橙色焦点识别：链接、按钮、文件触发器使用 3px `#ffb648` 外圈、2–3px offset。
- 因橙色对白仅约 `1.74:1`，单独使用不满足非文本 3:1；本任务组件必须再加 1–2px `#0060a6` 内圈/box-shadow。橙色对蓝约 `3.73:1`，组合后既延续现有橙色体系，又形成可测边界。
- 表单控件 focus 使用现有蓝色边框/蓝环，并在外层叠加橙色可见轮廓；错误焦点保留红色错误信息，不以蓝色覆盖错误语义。
- `:focus-visible` 生效，鼠标点击不强制显示整套轮廓；forced-colors 下使用系统 `Highlight`。
- 新路由进入后主标题可编程聚焦；校验失败聚焦首个无效字段；重试、刷新、上传期间不自动移动焦点。

### 10.3 对比度验收

- 普通文本目标 ≥4.5:1；大字目标 ≥3:1；必要控件边界、焦点和状态图形目标 ≥3:1。
- `#0060a6`/白约 6.51:1；主标题 `#102a4c`/白约 14.41:1；正文 `#3e5571`/白约 7.66:1；提示、成功、错误、警示组合均高于 6.8:1。
- 现有 `#6b7d91`/白约 4.23:1，不用于小号关键帮助文字；改用已有 `#61758c` 或 `#526b83`。
- 现有浅边框只作分组辅助；输入、选择、上传触发区以 `#7891a8` 边界达到约 3.27:1。
- 状态不只靠颜色；每处都有中文文本，并在徽标/时间线中加入不同图形。

### 10.4 Live region 与动画

- `role=alert`：权限拒绝、提交失败、详情首次读取失败、阻塞性错误摘要。
- `aria-live=polite` / `role=status`：加载完成、上传结果、提交进行中、同步结果、文件授权结果。
- 同一消息只播报一次；spinner 和骨架不含逐帧/逐字播报。
- 动画只允许现有 0.15–0.22s hover/抽屉过渡和线性 spinner；`prefers-reduced-motion:reduce` 时移除卡片/抽屉过渡，spinner 改为静态忙碌图形或显著减速，文字仍完整表达状态。

## 13. 安全与内容视觉护栏

- 权限被撤销或会话过期时，先清除受保护可见内容，再呈现权限卡；不先闪现缓存数据。
- 非本人、不存在与非法 query 使用同一“无法查看该申请”，不通过色彩、标题、长度或骨架差异暗示资源是否存在。
- 页面、URL、DOM 属性、附件名旁提示、错误摘要、截图区均不展示 Base token、app secret、tenant token、原始 file token 或敏感个人信息。
- 附件动作视觉不能暗示永久 URL；过期后重新授权。
- 四项首次写入门禁失败时，只显示普通用户可理解的“申请服务暂不可用”及是否需要重新授权；不展示 manifest、runId、Base 结构或绕过入口。
- TEST_ 字典数据按真实接口结果正常呈现，不加“真实租户身份”视觉暗示，也不把其设计成审批人身份。
