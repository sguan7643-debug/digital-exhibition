# DEH-ONBOARDING-POC-20260926 设计交接汇总

Owner: AI Team Lead

本汇总保留两个角色来源，不替代原始交接，也不代表设计已获批准。产品范围依据为 [prd.md](./prd.md)，交互来源为 [design/ux-handoff.md](./design/ux-handoff.md)，视觉来源为 [design/ui-handoff.md](./design/ui-handoff.md)。本任务仅覆盖现有 Vue Web 产品；uni-app 与原生移动端明确不在范围。

## 1. 设计结论

在现有数智产品展厅中补齐一条真实、可恢复、可验证的应用上线申请闭环：

1. 应用中心保留“应用上线申请”，新增同级“我的申请”；个人中心“我的申请”也进入统一列表。
2. `/apps/onboarding/apply` 承载真实飞书目录/字典、T005 表单、图标与附件上传、稳定 attempt 提交及不确定结果恢复。
3. `/apps/onboarding/status` 无 query 时显示当前用户自己的 `APP_ONBOARDING` 列表。
4. `/apps/onboarding/status?applicationId=<applicationId>` 显示本人申请详情；提交成功直接进入该详情。
5. 详情进入时只自动同步既有审批实例一次，并提供单次手动刷新；不轮询、不重复完整提交。
6. 状态、申请字段、授权范围、标识、真实图标与附件均由持久化数据恢复；附件通过当前用户与申请归属校验后的短期同源地址访问。

视觉上完整延续现有 `#0060a6` 蓝色顶栏/导航、`#f5f7fa` 页面底、白色卡片、细边框、轻阴影与橙色键盘焦点语言，不重新换肤。

## 2. 信息架构与导航

### 2.1 入口

| 来源 | 动作 | 目标 | 设计合同 |
| --- | --- | --- | --- |
| 应用中心标题区 | 应用上线申请 | `/apps/onboarding/apply` | 主按钮；DOM/键盘顺序在“我的申请”之前。 |
| 应用中心标题区 | 我的申请 | `/apps/onboarding/status` | 次按钮；与主按钮同一操作区。 |
| 个人中心快捷入口 | 我的申请 | `/apps/onboarding/status` | 复用既有快捷入口样式。 |
| 个人中心上线申请项 | 申请标题 | `/apps/onboarding/status?applicationId=…` | 仅 `APP_ONBOARDING` 使用此详情路由。 |

入口可见性不能代替服务端权限校验。直接访问仍必须校验有效飞书会话和当前用户归属。

### 2.2 路由合同

- 无 `applicationId`：列表，不再解释成单实例状态页。
- 有合法 `applicationId`：本人申请详情。
- 非法、非本人或不存在：统一“无法查看该申请”，不泄露资源是否存在，也不渲染缓存业务内容。
- `instanceId` 与 `resourceId` 只作为详情字段，不作为用户导航主键。
- 从列表进详情再返回时恢复滚动位置与触发链接焦点；直接打开详情则返回列表首部。

## 3. 核心流程

### 3.1 申请

页面依次呈现标题与说明、依赖/权限状态、申请人身份、应用基础与 T005 详情、授权范围、图标与附件、提交与恢复反馈。真实目录或字典不足时不注入模拟选项；普通用户页面不提供 TEST_ 数据或 schema 管理入口。

图标最多 1 个，仅 PNG/JPEG/WebP，最大 5MB。附件最多 3 个，单个最大 20MB，仅 PDF/DOCX/XLSX/PNG/JPEG。服务端验证扩展名、MIME、魔数并计算 SHA-256。SVG、HTML、脚本、可执行文件、压缩包及其他未列类型明确拒绝。

第一次有效提交创建稳定 attempt，并冻结业务键、幂等键、表单快照与上传关联。重复点击、网络超时、响应丢失、投影失败、页面内重试和服务重启恢复均不得创建第二审批实例。明确成功返回 `applicationId` 并进入详情；不确定结果只提供“继续确认提交结果”，查询或修复原 attempt。

### 3.2 我的申请列表

服务端从授权会话确定当前用户，只返回其 `APP_ONBOARDING`，按提交时间倒序。宽屏使用语义表格，列为应用名称/编码、状态、提交时间、当前节点、详情；窄屏转为带字段名的信息卡片，不通过整页横向滚动保留桌面列。列表不新增搜索、批量操作、审批动作或跨用户筛选。

### 3.3 详情与状态同步

详情先从持久化申请读取本人数据与附件关联，再在存在合法 `instanceId` 时自动同步一次。自动同步期间保留已读详情，只让状态摘要局部忙碌。手动刷新每次只查询同一实例一次，进行中抑制重复触发并保留焦点。

同步失败保留最后一次成功数据，显示其时间并允许重试；未知状态绝不映射为通过。缺少 `instanceId` 时显示“暂无审批跟踪编号”，只禁用刷新，不禁用详情与附件。服务重启后及不少于 7 天仍可从持久化记录恢复。

### 3.4 附件访问

每个附件显示真实文件名、大小、类型、SHA-256 与上传时间。查看/下载能力由服务端声明；DOCX/XLSX 不发明在线转换。每次动作都以 `applicationId + fileId + mode` 重新校验当前会话、申请归属与文件关联，再签发短期同源 URL；浏览器永不接收原始 file token。单文件失败不清空其他附件或详情。

## 4. 详情内容与状态表达

详情 DOM 与读屏顺序固定为：返回列表与标题；状态摘要；标识信息；应用信息；申请信息；授权范围；图标和附件。

状态必须同时使用中文文字、图形与颜色：

| 机器状态 | 文案 | 视觉 | 业务含义 |
| --- | --- | --- | --- |
| `PENDING` | 审批中 | 蓝色提示面与时钟/圆点 | 只存在申请与附件关联，不表达已发布。 |
| `APPROVED` | 已通过 | 绿色成功面与勾形 | 仅此状态允许核验发布投影。 |
| `REJECTED` | 已拒绝 | 红色错误面与叉/叹号 | 显示完成时间及有值的退回原因，不发布。 |
| `CANCELLED` | 已取消 | 红色终止面与停止形 | 显示完成时间及有值原因，不发布。 |
| 未知/缺失 | 状态暂不可确认 | 黄色警示面与问号 | 显示最后成功同步时间并允许重试，绝不按通过处理。 |

审批时间线只展示服务端或持久化记录提供的事实。最小形态为“提交申请”与“当前节点/最终结果”；不得虚构审批人、未来节点、预计时间或已完成步骤。宽屏水平、760px 以下纵向，读屏为有序列表。

## 5. 六态合同

状态均由真实请求和权限结果驱动，不使用测试 query 或模拟数据替代。

| 状态 | 申请页 | 列表 | 详情 |
| --- | --- | --- | --- |
| `normal` | 真实表单与文件状态可操作。 | 当前用户真实记录；可发起申请、打开详情。 | 本人持久化详情；可刷新与访问允许的附件。 |
| `loading` | 初始依赖或局部上传/提交忙碌；不清空已填内容。 | 初次骨架或重试忙碌；不重复触发。 | 初读为详情骨架；自动同步仅局部忙碌。 |
| `empty` | 真实目录/字典不足；可重试或返回，不注入模拟项。 | 明确 0 条时显示“暂无上线申请”和发起动作。 | 无合法页面级 empty；无附件是局部 normal。 |
| `error` | 错误摘要、字段/文件错误；不确定提交只确认原 attempt。 | 请求失败不显示成 0 条；可同作用域重试。 | 初读错误为全页；同步/文件错误就近呈现并保留成功数据。 |
| `disabled` | 门禁、上传或提交导致相关动作不可用；显示原因。 | 能力未启用时只保留标题与返回动作。 | 缺实例只禁用刷新；服务未启用时全页只读不可用。 |
| `permission-denied` | 不渲染业务字段；提供授权或返回。 | 受限卡替代列表，不闪现缓存行。 | 统一安全文案，不呈现名称、ID、附件或存在性。 |

错误摘要位于首个字段组之前，包含“请检查以下 N 项”和可跳转字段链接。`role=alert` 用于权限拒绝、提交失败、首次详情读取失败与阻塞校验；`aria-live=polite` 用于加载完成、上传、提交进行中、同步和文件授权结果。

## 6. 视觉系统

### 6.1 核心令牌

- 品牌/主动作/进行中：`#0060a6`；主动作 hover `#00528e`。
- 页面底：`#f5f7fa`；表面：`#ffffff`。
- 主标题：`#102a4c`；正文：`#3e5571`；次级信息：`#61758c` 或 `#526b83`。
- 常规边框：`#d9e2ec` / `#d9e4ee`；控件必要边界：`#7891a8`；分隔：`#e7edf3`。
- 错误：`#a52222` / `#fff5f5` / `#efb8b8`。
- 成功：`#165f45` / `#f0faf6` / `#b9dfcf`。
- 提示：`#174a7a` / `#eef6ff` / `#a9caeb`。
- 警示：`#664c12` / `#fffae8` / `#e6c86f`。
- 焦点：3px `#ffb648` 外圈 + 1–2px `#0060a6` 内圈；forced-colors 使用系统 `Highlight`。

字体继续使用 `Microsoft YaHei, PingFang SC, Arial, sans-serif`。页面标题使用现有响应式 26–32px；正文 15–17px；必要辅助信息不低于 13px。间距沿用 4/8/12/16/20px；同层卡片默认 7px 圆角；移动 Web 主要操作不小于 44×44px。

### 6.2 组件外观

- 申请页继续使用白色 `fieldset`、蓝色编号、上标签下控件、真实文件行与独立错误摘要。
- 列表宽屏为白色语义表格，窄屏为 10–12px 圆角信息卡；每项保留显式“查看详情”链接。
- 详情使用单列主叙事；宽屏允许信息卡两列，但 DOM 顺序不变；状态摘要是标题后的第一张主卡。
- 图标预览框约 74×74px；附件宽屏表格、窄屏卡片；长 ID、哈希和文件名使用 `overflow-wrap:anywhere`。
- 只读卡片不显示可点击 hover；可交互卡片采用轻边框/阴影变化，但明确链接始终存在。

## 7. 响应式与可访问性

- `>1400px`：申请最多四列、列表表格、详情卡可两列。
- `1181–1400px`：申请降两列，上传区单列。
- `901–1180px`：复杂详情与面板单列。
- `761–900px`：标题动作可纵排，列表在列不可读前转卡片。
- `≤760px`：沿用现有安全区与导航抽屉，任务内容全部单列，主要操作至少 44px。
- `320–639px`：按钮可满宽堆叠，定义列表上下排列，长内容强制断行。

页面在 320px、200% 缩放和键盘操作下保持可达。新路由进入聚焦主标题；浏览器返回恢复来源焦点；校验失败聚焦首个无效字段；自动同步、重试、上传和刷新不抢焦点。状态不只靠颜色；普通文本目标对比度至少 4.5:1，必要非文本边界与复合焦点至少 3:1。`prefers-reduced-motion` 下移除非必要过渡。

## 8. 权限、安全与 POC 护栏

- 身份只能来自有效飞书会话；客户端不能传其他用户 ID 决定列表范围。
- 返回业务字段前校验本人归属；权限失效时先清除受保护内容再显示受限状态。
- 页面、URL、DOM、日志和公开证据不暴露 Base token、app secret、tenant token、原始 file token 或敏感个人信息。
- 首次真实写入前必须依次满足 Base 指纹、真实审批人、schema dry-run、runId 清理台账四项门禁；普通用户界面无绕过入口。
- `PENDING` 只创建/更新申请与附件关联；仅 `APPROVED` 幂等创建/更新应用索引与海能work详情；负向终态不发布。
- POC 完成证据必须包含真实浏览器闭环、服务重启恢复、可控时钟跨 7 天、精确记录/上传关联与清理结果；请求拦截或 fixtures 不能替代真实证据。

## 10. 实现与验收重点

1. 修正当前申请页文件规则与真实上传链路，不再接受 SVG、压缩包或宽泛 5 附件。
2. 提交成功与恢复结果必须获得稳定 `applicationId`，不再用实例 query 导航。
3. 将现有单实例 `OnboardingPage` 改为无 query 列表、有 `applicationId` 详情，同时保留六态和归属保护。
4. 个人中心与应用中心入口统一指向新路由；其他申请类型不混入本列表。
5. 状态摘要、时间线与附件只展示真实事实；未知/失败不误报成功，旧数据在同步失败时保留并标明时间。
6. 完成桌面/窄屏、键盘、200% 缩放、对比度、真实审批、附件、重启恢复、跨 7 天自动化与精确清理验证。
