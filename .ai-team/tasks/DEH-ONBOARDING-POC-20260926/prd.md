# DEH-ONBOARDING-POC-20260926 — 应用上线申请完整 POC 闭环 PRD

> 治理状态：用户已于 2026-09-26 明确批准本任务范围，`approvals.scope.approved=true`，任务已进入 `design`。设计批准前仍不授权修改业务代码、配置、飞书结构或飞书数据。

## 1. 产品目标与目标用户价值

### 1.1 产品目标

- **事实（任务包）**：在现有 Vue Web 项目中交付应用上线申请完整 POC：用户从应用中心进入申请页，使用真实飞书目录和字典，提交海能Work（`T005`）飞书审批，在“我的申请”查看本人申请列表、详情和同一审批实例的最新进度。
- **事实（扩展方向）**：为使 POC 闭环通过，允许新增缺失页面、路由和服务端接口；允许在指定飞书 POC Base 中幂等、只增不删地创建缺失表或字段；真实数据为空时允许创建带 `TEST_`、可追踪、可清理的验证数据。
- **事实（扩展方向）**：T005 应用图标和申请附件必须真实上传、持久化、关联到同一申请，并能在申请详情中核验。
- **事实（治理）**：扩展方向已写入任务包，并已于 2026-09-26 获得用户明确范围批准。

### 1.2 目标用户价值

- 已授权 Web 用户能够连续完成“找到入口—填写真实数据—上传图标/附件—提交真实飞书审批—查看我的申请—打开详情—刷新审批进度—核验附件”。
- 业务运营或 POC 验证人员能够依据同一组 `applicationId`、`resourceId`、`instanceId`、飞书记录 ID、上传 ID 和 `traceId` 复核页面、审批、多维表和附件的一致性。
- 真实飞书数据为空或结构不完整时，验证不被空页面阻断，也不使用前端模拟业务数据冒充成功。

### 1.3 POC 成功定义

只有同时满足以下条件，才可判定 POC 通过：

1. 已授权用户从应用中心 UI 进入真实申请页并完成一条 T005 申请。
2. 类型、业务域、申请人、部门等选项来自真实飞书；若真实 POC 必需数据为空，则使用本次运行创建并登记的 `TEST_` 数据。
3. 图标和至少一个申请附件真实上传到飞书，file token 不暴露给浏览器，并与同一申请持久化关联。
4. 只创建一个真实飞书审批实例和一条对应“上架申请”记录；模糊失败重试不得重复创建。
5. “我的申请”只显示当前用户的上线申请；详情展示同一实例、关键表单字段、图标、附件和同步时间。
6. 飞书审批状态变化后，进入详情或手动刷新可显示同一实例的最新状态。
7. `PENDING` 只落“上架申请”及附件关联；仅 `APPROVED` 才进入应用索引和海能work详情；拒绝或取消不得发布应用。
8. 首次真实写入前，Base 指纹匹配、真实审批人可用、POC schema dry-run 无越界/冲突、runId 清理台账已创建四项前置检查必须全部通过。
9. 真实浏览器即时闭环、服务重启/持久化恢复和可控时钟跨 7 天自动化共同形成当前 POC 完成证据；第 7 天真实复查为可选非阻塞观察项。
10. 真实网络请求、真实飞书审批、多维表结构/记录及清理结果形成可复核证据；仅自动化测试绿灯不算 POC 通过。

## 3. 范围边界

### 3.1 范围内

#### A. 页面与路由

- 应用中心提供“应用上线申请”和“我的申请”入口；个人中心可提供同一“我的申请”入口。
- `/apps/onboarding/apply` 提供真实目录/字典驱动的 T005 表单、图标上传、附件上传、校验、提交中、防重复、成功和失败状态。
- `/apps/onboarding/status` 无 `applicationId` 时显示当前用户列表；带参数时显示对应详情。
- 缺失页面、页面区块、路由和交互可新增，不要求复用不能满足验收的空壳页面。

#### B. 服务端接口

- 保留真实飞书审批创建、查询和状态同步接口。
- 允许新增当前用户的上线申请列表、详情、手动同步、文件上传和未提交文件移除接口。
- 允许新增仅供受控 POC 执行的结构检查、验证数据准备和清理工具；不得作为匿名公网管理接口暴露。
- 列表、详情、上传、同步和清理必须要求有效飞书会话或服务端受控身份，并保留同用户归属校验。

#### C. 指定 POC Base 结构补齐

- 本任务必须建立独立版本化的 POC schema manifest 和 POC 专用编排器；禁止直接调用现有通用迁移器完成本任务 dry-run 或 execute。
- 结构写入白名单严格限定为：`上架申请`、`文件上传会话`、`附件资料`、`应用索引`、`海能work应用详情`。允许字段及类型以第 3.2 节为唯一来源。
- manifest 或执行计划一旦出现非白名单表、非白名单字段、删改重命名或未知动作，整个计划失败且不得执行结构写。
- `应用类型配置`、`业务域字典`、`用户字典`、`部门字典`只允许在表已存在时新增最少 TEST_ 记录；禁止为它们建表、增字段或补齐通用审计结构。
- `FEISHU_POC_BASE_FINGERPRINT` 必须配置为目标 `FEISHU_BASE_TOKEN` 的 SHA-256 脱敏指纹。POC 专用编排器在 dry-run 和 execute 前分别计算当前 token 指纹并精确匹配；变量缺失、格式非法或不一致时立即停止，且不得读取或写入远端 schema。
- 日志和证据只记录指纹，不记录 Base token；不得自动选择、搜索或切换其他 Base。
- dry-run 必须比较表名、字段名、字段类型、主键属性、单选/多选选项兼容性和附件字段类型。兼容要求为类型相同、既有选项至少覆盖 manifest 必需选项、附件字段确认为 Attachment；同名异型或必需选项缺失立即停止。
- 执行顺序固定为：本地指纹预检 → 远端只读发现 → 白名单/兼容性 dry-run → 变更前清单 → 显式开启结构写门禁 → 幂等 execute → 再发现 → 变更后清单。
- 只允许缺失时建白名单表、缺失时加白名单字段；禁止删表、删字段、重命名、改类型、覆盖既有配置或清空数据。

#### D. TEST_ 验证数据与命名

- TEST 数据记录写入白名单严格限定为：`应用类型配置`、`业务域字典`、`用户字典`、`部门字典`、`上架申请`、`文件上传会话`、`附件资料`、`应用索引`、`海能work应用详情`。任何其他表写入均失败。
- 四张目录/字典表必须已经存在；仅当真实数据为空或不足以完成 POC 时，才可新增本次运行所需的最少 TEST_ 记录，不允许修改既有记录或结构。
- 每次运行使用唯一 `runId`：`TEST_ONBOARDING_POC_<UTC时间>_<8位随机串>`。
- 派生标识使用同一后缀：
  - 应用 ID：`TEST_APP_<后缀>`
  - 应用编码：`TEST_HW_<后缀>`
  - 业务键：`TEST_ONBOARDING_<后缀>`
  - 幂等键：`TEST_IDEM_ONBOARDING_<后缀>`
  - 追踪 ID：`TEST_TRACE_<后缀>`
  - 图标：`TEST_ONBOARDING_ICON_<后缀>.<ext>`
  - 附件：`TEST_ONBOARDING_ATTACHMENT_<后缀>.<ext>`
- 审批标题不以是否含 `TEST_` 作为接口合法性条件；但由 POC 自动创建的验证应用名称应包含 `TEST_`，便于人工识别。
- 九张白名单表中创建的每条记录必须携带同一 runId：目标表允许 `运行标识` 时写入该字段；不允许或四张字典表没有该字段时，主键/唯一键必须包含完整 `TEST_<runId>`；已有 `追踪ID` 时同时写入同一 runId。
- 四张字典表允许写入的最小字段为：
  - `应用类型配置`：类型ID、类型名称、类型编码、排序、状态、是否系统内置、类型描述，以及表已存在时的追踪ID；
  - `业务域字典`：业务域ID、业务域名称、业务域编码、描述、启用、排序，以及表已存在时的追踪ID；
  - `用户字典`：AD账号、姓名、工号、所属部门ID、所属部门名称、邮箱脱敏值、手机号脱敏值、启用、任职状态，以及表已存在时的追踪ID；
  - `部门字典`：部门ID、部门名称；部门ID 必须包含完整 TEST_ runId。
- 字典 TEST_ 记录只用于 POC Base 下拉和展示，不代表飞书租户通讯录身份。不得创建或修改租户通讯录用户、真实部门、用户权限、会话、授权关系或登录身份。
- 真实审批申请人和审批人必须来自实际授权会话，并与飞书实例请求中的真实身份一致；不得用字典 TEST_ 记录伪造审批身份。
- 首次真实写入前必须创建 runId 清理台账。每个创建对象登记对象类型、Base 指纹、table_id、record_id、runId、主键/业务键、文件名、上传 ID、实例 ID、创建时间、清理策略和结果。

#### E. T005 图标与附件

- 图标固定最多 1 个，仅允许 PNG、JPEG、WebP，大小不超过 5MB。
- 普通申请附件固定最多 3 个，单个不超过 20MB，仅允许 PDF、DOCX、XLSX、PNG、JPEG。
- 普通附件在日常表单中可选，但本次真实 POC 必须实际上传至少 1 个允许类型附件，以验证完整持久化与访问链路。
- 明确拒绝可执行文件、脚本、HTML/SVG 等主动内容、压缩包及未列入白名单的其他类型。
- 服务端必须同时校验扩展名、声明 MIME、文件特征/魔数并交叉确认，同时计算并持久化 SHA-256；任一不一致即拒绝。只检查扩展名或 MIME 不算满足。
- 图标和申请附件通过服务端真实上传到飞书；浏览器不得接收或持久化 tenant token 或原始 file token。
- 上传成功后形成可追踪上传会话，再关联同一 `applicationId`、`resourceId`、`instanceId` 和“上架申请”。
- 提交前移除的文件、提交明确失败后的孤立文件进入可重试清理。
- 详情展示图标预览或安全访问入口，以及附件名称、大小、类型、SHA-256、上传时间和下载/预览操作。
- 文件访问只向当前申请人签发短期、同源、绑定文件与用户的授权 URL；服务端再次校验申请归属。URL、页面、日志和响应不得暴露 file token。
- 审批通过后，图标和附件幂等投影到发布态数据；重复同步不得重复创建附件记录。

#### F. 我的申请与审批进度

- 列表只显示当前用户的 `APP_ONBOARDING`，按提交时间倒序，不混入使用或复用申请。
- 详情至少展示：`businessId`、`applicationId`、`resourceId`、`instanceId`、应用名称、编码、类型、业务域、申请人、授权用户、授权部门、提交时间、规范状态、当前节点、完成时间、退回原因、最近同步时间、图标和附件。
- 规范状态为 `PENDING`、`APPROVED`、`REJECTED`、`CANCELLED`；未知状态不得映射为通过。
- 进入详情自动同步一次；用户可手动刷新；不以重复完整提交刷新，不做 WebSocket/SSE/持续轮询。
- 实现必须将当前 24 小时注册表限制提升到不少于 7 天，或能够从持久化“上架申请”恢复实例归属和查询上下文；仅延长内存变量而不能服务重启恢复不算满足。
- 当前 POC 的 7 天完成证据固定为：真实浏览器即时完整闭环 + 服务重启后的持久化恢复验证 + 可控时钟跨 7 天自动化。第 7 天真实环境复查为可选、非阻塞观察项。

#### G. 投影、幂等和真实验证

- 同一表单 attempt 在确定结果前复用稳定业务键和幂等键；重复点击、响应丢失、超时和首次投影失败不得创建第二实例或第二申请。
- `PENDING` 只创建/更新“上架申请”、上传会话和附件关联；`APPROVED` 才创建/更新应用索引和海能work详情；拒绝/取消只更新原申请终态。
- 必须执行自动化、生产构建和真实浏览器 POC；真实 POC 不得拦截审批、列表、详情、同步或附件接口。
- 证据必须包含结构前后清单、数据创建清单、页面状态、网络响应、审批实例、多维表记录、附件核验、状态变化和清理结果。

#### H. 首次真实写入前的四项硬门禁

以下四项必须按顺序全部通过；任一失败时，结构、记录、媒体和审批实例均不得发生首次真实写入：

1. **Base 指纹匹配**：`FEISHU_POC_BASE_FINGERPRINT` 存在、格式合法，并与当前目标 Base token 的 SHA-256 完全一致。
2. **真实审批人可用**：授权会话有效，真实申请人和真实审批人可由飞书确认且具备完成 POC 的权限。
3. **schema dry-run 无越界/冲突**：计划只包含五张结构白名单表和第 3.2 节字段；名称、类型、选项和附件兼容性检查全部通过。
4. **runId 清理台账已创建**：台账在首次记录、媒体或审批写入前持久化，且能记录精确 `table_id + record_id + runId`。

四项均为范围门禁，不是可跳过的运维建议，也不能通过命令参数、环境开关或手工确认绕过。

### 3.3 清理与回滚边界

- **验证记录清理**：只删除本次 runId 清理台账登记的 TEST_ 数据。每次删除前必须同时按精确 `table_id + record_id` 读取目标，并二次核对记录中的 `运行标识=runId`；没有运行标识字段时，二次核对主键/唯一键包含完整 `TEST_<runId>`。三项任一不一致即拒绝删除。
- **禁止批量删除**：禁止仅按表名、TEST_ 前缀、模糊条件、时间范围或搜索结果批量删除；禁止删除台账外记录和执行前既有记录。删除后必须再次按相同 `table_id + record_id` 查询并证明不存在。
- **审批实例清理**：如不支持物理删除，则保留实例并标记终态和不可删除原因；不得伪报已清理。
- **附件清理**：删除上传会话、附件资料和申请记录的测试关联；若媒体二进制不可删，则登记 file token 哈希、文件名、保留策略和待 GC 状态，原始 token 不进入公开证据。
- **结构回滚**：禁止删除表/字段，新增结构默认保留。应用回归时，代码停止使用新增字段；结构清单保留为可审计、向后兼容扩展。
- **失败原子性**：结构补齐中途失败时停止后续写入，重新发现并输出已创建/未创建/冲突清单；再次执行跳过已完成项。数据准备失败时只按上述精确三元核对规则清理已创建记录。
- **验收边界**：存在未解释业务记录残留、无法定位的附件关联、重复实例或结构冲突时，不得判定 POC 通过。

## 4. 主要用户流程

### 4.1 POC 准备流

1. 范围和设计获批后，POC 专用编排器先校验 `FEISHU_POC_BASE_FINGERPRINT`；缺失或不匹配立即停止，dry-run 也不得继续。
2. 编排器验证授权会话和真实审批人可用，不创建或修改租户通讯录身份。
3. 编排器使用独立 manifest 执行只读发现和兼容性 dry-run；任何非白名单动作、同名异型、选项或附件类型冲突均停止。
4. 编排器创建并持久化唯一 runId 的清理台账；以上四项前置检查全部通过后，才允许首次真实写入。
5. 受控执行者显式开启结构写门禁，编排器幂等补齐五张白名单表中的允许字段，并生成变更后清单。
6. 若四张目录/字典表已存在但真实数据不足，按记录白名单创建最少 TEST_ 数据并精确登记；表不存在时停止，不为目录/字典建表。

### 4.2 申请提交流

1. 用户从应用中心进入 `/apps/onboarding/apply`。
2. 页面加载真实类型、业务域、人员和部门，并呈现加载、空、失败和权限状态。
3. 用户选择海能Work，填写申请、应用、业务域、适用用户和适用部门。
4. 用户选择图标和附件；服务端完成校验、飞书上传和上传会话持久化。
5. 用户提交；前端冻结同一 attempt 的业务键和幂等键，服务端只创建一个审批实例。
6. 系统将实例、授权、表单、图标和附件写入同一申请及关联记录。
7. 成功后进入详情；明确失败保留表单，模糊失败使用原 attempt 恢复。

### 4.3 我的申请列表与详情流

1. 用户进入无参数 `/apps/onboarding/status`。
2. 服务端按当前申请人过滤，用户查看状态、应用名称、提交时间和详情入口。
3. 用户打开详情；服务端校验归属，读取申请、附件关联和实例。
4. 有合法实例时自动同步一次；用户也可手动刷新。
5. 页面显示规范状态、节点、终态信息、同步时间、图标和附件。
6. 通过后核对应用索引和海能work详情；拒绝/取消时不得出现已发布应用。

### 4.4 真实验证与清理流

1. 使用真实浏览器完成入口、填表、上传和提交，不拦截关键请求。
2. 保存页面、网络、业务 ID、记录 ID、实例 ID 和上传台账的脱敏证据。
3. 飞书审批人对真实实例作出决定；用户刷新并核对同一实例状态。
4. 核验多维表记录、发布投影和附件访问，确认无重复。
5. 重启服务，证明可从持久化申请恢复同一实例、详情和附件归属；再以可控时钟执行跨 7 天自动化并证明仍可恢复/读取。
6. 按台账的精确 table_id、record_id 和 runId 三元核对执行清理并复查；不可删除对象记录残留策略。
7. 自动化、构建、真实即时闭环、重启恢复、跨 7 天自动化、结构核验和清理核验全部符合标准后，才能报告当前 POC 通过；第 7 天真实复查单独登记为可选观察。

## 8. Given / When / Then 验收标准

### AC-01 入口与页面闭环

- **Given** 有效飞书会话；**When** 进入应用中心；**Then** 可进入申请页和“我的申请”，且不是空壳或无效链接。

### AC-02 列表与详情

- **Given** 访问 `/apps/onboarding/status`；**When** 无 `applicationId`；**Then** 显示本人上线申请列表；**When** 带合法参数；**Then** 显示该申请详情。

### AC-03 真实目录与字典

- **Given** 飞书目录/字典有数据；**When** 打开申请页；**Then** 类型、业务域、申请人和部门均来自真实接口，无前端模拟补位。

### AC-04 空数据准备

- **Given** POC 必需目录数据为空；**When** 受控准备执行；**Then** 只在已存在的应用类型配置、业务域字典、用户字典、部门字典中创建第 3.1.D 节允许字段和同一 runId 的最少 TEST_ 记录，重复执行不重复创建；任一字典表不存在时停止且不建表。

### AC-05 Base 指纹门禁

- **Given** `FEISHU_POC_BASE_FINGERPRINT` 缺失、格式非法或与当前 Base token 的 SHA-256 不一致；**When** 请求 dry-run 或 execute；**Then** 两者都在远端 schema 读取/写入前停止，错误不包含 Base token。

### AC-06 独立 manifest 与 dry-run 白名单

- **Given** Base 指纹匹配；**When** POC 专用编排器执行 dry-run；**Then** 使用独立 manifest，只生成五张结构白名单表和第 3.2 节字段的计划，并比较名称、类型、主键、选项和附件类型；计划出现任何其他对象或动作时整体失败。

### AC-07 结构冲突停止

- **Given** 同名字段类型不同、必需单选/多选选项缺失、附件字段不是 Attachment 或权限不足；**When** dry-run 或 execute；**Then** 停止并报告，不删除、不改型、不创建影子对象，也不忽略冲突后继续。

### AC-08 结构幂等执行和后核验

- **Given** 范围/设计已批准、四项写入前置检查通过且结构门禁开启；**When** execute；**Then** 仅创建第 3.2 节实际缺失对象，重复执行无重复；再次发现证明名称、类型、选项和附件类型兼容，前/计划/后清单使用同一 manifest 版本和哈希。

### AC-09 T005 表单校验

- **Given** 选择 T005；**When** 适用用户、适用部门、名称、编码、业务域或图标缺失；**Then** 页面和服务端均阻止提交。

### AC-10 图标真实上传

- **Given** 用户选择 1 个 PNG/JPEG/WebP 且不超过 5MB 的图标；**When** 服务端验证扩展名、声明 MIME 和文件特征一致并计算 SHA-256 后上传；**Then** token 仅在服务端，上传会话和申请关联可由上传 ID、元数据、哈希、用途和 runId 核验。

### AC-11 附件真实上传

- **Given** 用户选择不超过 3 个附件，每个不超过 20MB 且为 PDF/DOCX/XLSX/PNG/JPEG；**When** 服务端验证扩展名、声明 MIME 和文件特征一致并计算 SHA-256 后上传；**Then** 附件真实持久化，详情显示元数据与哈希，并只向当前申请人提供短期同源授权 URL，不暴露 file token。

### AC-12 文件失败与孤立清理

- **Given** 图标超过 1 个或 5MB、附件超过 3 个或单个 20MB、文件是可执行文件/脚本/HTML/SVG/压缩包、类型不在白名单，或扩展名/MIME/文件特征不一致；**When** 请求上传；**Then** 服务端拒绝且不创建成功上传记录。
- **Given** 上传失败、用户移除文件或提交明确失败；**When** 恢复/清理；**Then** 不保留错误关联，可删除测试记录按台账精确清理并记录结果。

### AC-13 稳定 attempt

- **Given** 同一 attempt 正在提交或结果不确定；**When** 重复点击、重复触发或超时；**Then** 复用业务键/幂等键，只保留一个任务，不创建重复实例、申请或附件关联。

### AC-14 真实审批提交

- **Given** 合法 T005 表单和上传，且申请人/审批人来自实际授权会话；**When** 提交；**Then** 使用真实会话身份创建一个飞书实例，返回合法 instanceId，并创建一条同 resourceId 的“上架申请”；不得以用户字典 TEST_ 记录替代审批身份。

### AC-15 申请关键字段

- **Given** 提交成功；**When** 核验“上架申请”；**Then** 包含申请/应用标识、名称、编码、类型、申请人、业务域、状态、节点、时间、来源、实例、授权、attempt、追踪、图标和附件关联。

### AC-16 模糊失败恢复

- **Given** 实例已创建但响应丢失或首次投影失败；**When** 原 attempt 重试；**Then** 恢复原实例并补齐原记录，无重复。

### AC-17 PENDING 投影

- **Given** 状态为 PENDING；**When** 提交或同步；**Then** 只更新申请和附件关联，不产生应用索引或发布详情。

### AC-18 APPROVED 投影

- **Given** 同一实例变为 APPROVED；**When** 进入详情或刷新；**Then** 更新原申请并幂等发布，图标/附件可核验，重复刷新无重复记录。

### AC-19 REJECTED/CANCELLED 投影

- **Given** 同一实例拒绝或取消；**When** 同步；**Then** 只更新原申请终态、完成时间和原因，不发布应用。

### AC-20 我的申请隔离

- **Given** 多用户、多申请类型并存；**When** 打开“我的申请”；**Then** 服务端只返回当前用户的 APP_ONBOARDING。

### AC-21 列表状态

- **Given** 列表加载、空、成功、错误、超时或无会话；**When** 渲染；**Then** 显示对应状态，错误不冒充空列表，无会话不返回业务内容。

### AC-22 详情读模型

- **Given** 打开本人合法 applicationId；**When** 读取成功；**Then** 展示第 3.1.F 节字段、图标和附件，缺失可选值显示“—”。

### AC-23 边界详情

- **Given** 非本人、不存在、缺 instanceId 或未知状态；**When** 请求详情/同步；**Then** 安全拒绝、禁用同步或报错，不泄露、不伪造通过。

### AC-24 详情同步

- **Given** 合法 instanceId；**When** 首次进入或手动刷新；**Then** 每次只查询既有实例一次，更新同步时间，不创建实例或持续轮询。

### AC-25 七天核验窗口

- **Given** 即时真实浏览器闭环已通过；**When** 服务重启；**Then** 系统从持久化申请恢复同一实例、当前用户归属、状态和附件，不依赖仅存于内存的 24 小时注册表。
- **Given** 可控时钟推进超过 7 天；**When** 自动化重新读取同一申请；**Then** 列表和详情仍指向同一实例并显示准确状态，或能从持久化记录恢复；该自动化与重启恢复共同作为当前 POC 的 7 天证据。
- **Given** 当前 POC 已按上述证据完成；**When** 第 7 个自然日到达；**Then** 可登记一次真实环境复查作为非阻塞观察，不因尚未等待 7 天而阻塞当前 POC 完成。

### AC-26 真实 POC 证据

- **Given** 实现完成；**When** 执行真实 POC；**Then** 证据包含 Base 指纹匹配、POC manifest 版本/哈希、无越界/冲突 dry-run、清理台账创建、真实审批人可用、UI 入口、真实数据、真实上传/提交、runId、businessId、applicationId、resourceId、instanceId、精确 table_id/record_id、上传 ID、关键字段、状态前后、列表/详情同实例、附件访问、服务重启恢复、跨 7 天自动化和结构前后清单。

### AC-27 禁止模拟替代

- **Given** 自动化全部通过；**When** 即时真实浏览器闭环的 AC-26 证据缺失或关键请求被拦截；**Then** 不得判定真实 POC 通过。可控时钟自动化只证明跨 7 天持久性维度，不能替代即时真实提交、审批、附件和多维表证据。

### AC-28 TEST_ 数据清理

- **Given** 验证结束；**When** 清理器处理某条台账记录；**Then** 删除前按精确 table_id 与 record_id 读取，并核对记录的运行标识等于 runId，或主键/唯一键包含完整 TEST_<runId>；任一不符则拒绝删除。
- **Given** 三元核对通过；**When** 删除完成；**Then** 再按同一 table_id 与 record_id 复查不存在，执行前既有数据不变；禁止按前缀、模糊条件、时间范围或表名批量删除。

### AC-29 不可删除对象披露

- **Given** 审批实例或媒体不可物理删除；**When** 清理完成；**Then** 台账记录对象、原因、已解除关联、脱敏标识和 GC 策略，不报告“零残留”。

### AC-30 结构回滚边界

- **Given** 新增结构已应用但实现需回滚；**When** 代码回滚；**Then** 应用停止依赖新增字段，结构保留且不影响旧数据，不通过删结构回滚。

### AC-31 自动化与构建

- **Given** 后续范围/设计获批并实现；**When** 执行测试和生产构建；**Then** 页面、数据映射、上传安全、幂等、投影、本人隔离、状态、POC 专用 manifest/编排器、Base 指纹、白名单越界拒绝、兼容性检查、重启恢复、跨 7 天时钟和精确清理均有通过证据。

### AC-32 完成判定

- **Given** 四项写入前置检查、自动化、构建、即时真实浏览器、真实审批、服务重启恢复、可控时钟跨 7 天、结构、数据、附件和清理核验均已执行；**When** 所有阻塞项通过且残留完整披露；**Then** 才可报告“完整 POC 验证通过”，否则必须报告未通过项。

### AC-33 TEST 记录写入白名单

- **Given** POC 专用编排器准备创建记录；**When** 目标表不属于第 3.1.D 节九张记录白名单，或字段超出第 3.1.D/3.2 节允许集合；**Then** 写入在调用飞书前失败，且不能通过通用管理客户端绕过。

### AC-34 租户身份禁止变更

- **Given** 目录数据不足；**When** 准备验证数据；**Then** 只在已存在的 POC Base 字典表创建 TEST_ 记录，不调用飞书租户通讯录、部门、权限或会话身份的创建/修改接口。

### AC-35 四项首次写入门禁

- **Given** Base 指纹匹配、真实审批人可用、schema dry-run 无越界/冲突、runId 清理台账已创建四项中的任一项未通过；**When** 请求任何结构、记录、媒体或审批实例的首次真实写入；**Then** 写入被拒绝且证据标记 POC 未开始真实写入。
