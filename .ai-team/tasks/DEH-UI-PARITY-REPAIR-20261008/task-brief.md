# Task Brief

## Goal

纠正 `DEH-UI-PARITY-20260930` 只校验共享外壳和 5 个代表路由、却错误宣称 30 路由 UI 已一致的问题。以产品指定源码包为唯一基准，对全部共同页面逐页修复和验收。

## User

数智产品展厅 Web 端业务用户、产品验收人员和版本维护人员。用户需要真实业务能力保持不变，同时每个页面都使用产品确认的同一套 UI，而不是由用户自己逐页寻找遗漏。

## Mode

现有 Vue Web 项目返工。

## Platforms

- Web：Vue。
- H5：作为响应式 Web 覆盖。
- 原生移动端 / uni-app：不声明。

## Evidence

- 用户提供的对照截图：`codex-clipboard-fbeec724-189a-4dd1-851b-d94468448018.png`（参考详情页）与 `codex-clipboard-23257612-8b71-41b0-b55a-669c91246178.png`（当前详情页），页面主体结构明显不同。
- 参考包：`digital-exhibition-SOURCE-20260916-165348.zip`，SHA-256 `F99F06B769F45075C34EF58E3C118E5ECB16D6F2CEA3455BE54C2BEE3C27C035`。
- 旧浏览器验收 `tools/browser-ui-reference-parity.test.mjs` 只覆盖 5 个路由，并且只断言顶栏、框架、侧栏、背景与溢出，没有检查详情页主体。
- 旧 Web 交接明确记录实现只改 `App.vue`、`style.css` 和 `ExhibitionShell.vue` 等共享外壳文件，没有迁移 30 个页面主体。
- 2026-10-08 全量模板结构审计：9 类应用详情页、后台管理、公告编辑和应用编辑与参考页面文件的路由级结构令牌匹配度为 0%；认证页、上架详情也存在大幅缺口。

- 用户提供的素材中心截图 `codex-clipboard-7ab39f08-fb3a-4b3c-93ab-57817b4a9d91.png`：全局“数据更新时间”文本及其所在行占用页面顶部空间。

## Scope

- 对 30 个共同路由逐页建立参考/当前对照矩阵。
- 修复共同页面的结构、布局、组件外观、间距、字体、色彩、边框、动作区和响应式行为。
- 9 类应用详情必须恢复参考包的详情头部、动作区、指标条、详情面板和对应类型区块，同时继续绑定真实数据与真实操作。
- 当前项目独有页面复用相同设计系统，并保留全部业务能力。
- 全量修正用户可见人员字段，统一通过用户字典显示真实姓名，禁止用人员编码回退充当姓名。
- 全站移除“数据更新时间”的可见内容和布局占位，不删除内部同步时间及缓存刷新能力。
- 建立不允许抽样冒充全量的自动化视觉、结构和可访问性回归。

## Out of Scope

- 不恢复参考包的模拟数据和演示业务逻辑。
- 不修改后端、飞书表结构、权限和审批规则。
- 不执行部署、发布、合并或推送。

## Success Metric

30 个共同路由全部具备逐页证据；每个路由至少完成三档视觉对照和六档响应式/溢出检查；所有阻断差异归零；人员展示位不出现原始编码；全站不显示也不占位“数据更新时间”；构建、业务集成和可访问性回归通过。

## Deadline

未指定，按当前最高优先级处理。

## Risk

高风险。页面面广，且必须避免视觉迁移破坏真实数据与操作。由 Web 工程实现、独立代码评审、功能 QA 和兼容性 QA 分层验证。

## Dependencies

- 固定参考包及其 SHA-256。
- 当前项目本地服务与参考项目独立服务。
- 既有真实数据投影、身份、权限、审批、上传和写入测试套件。
- 用户对本修复任务范围和设计的明确批准。
