# Task Brief

## Goal

将首页五项飞书读取合并为一个页面级聚合接口，避免浏览器重复触发完整读取，并在缓存命中、陈旧刷新和真正冷启动下提供稳定、可恢复的响应。

## User

目标用户是访问数智产品展厅首页的已授权 Web 用户；重复需求是每次进入或刷新首页时尽快看到可用的正式飞书数据，而不是经历多轮 500/504 和重复请求。

## Mode

现有 Vue Web 产品改造。

## Platforms

- Web（Vue）
- 不包含 uni-app、原生移动端或小程序。

## Scope

- 飞书上游默认超时调整为约 20 秒，不再被 12 秒硬上限截断。
- 整表读取默认预算调整为约 35 秒，不再被 15 秒硬上限截断。
- 首页 `COM-001`、`COM-002`、`COM-005`、`WB-001`、`WB-002` 聚合为一个浏览器请求。
- 冷启动时按租户、身份、权限与输入范围只创建一个后台同步任务。
- 前端轮询轻量状态接口，不重复执行五项飞书读取。
- 服务启动后预热首页关键公共表，并暴露就绪/同步状态。
- 刷新失败但存在合规陈旧快照时继续返回旧数据并明确标记。
- 聚合 HTTP 请求设置不超过 30 秒的响应边界。

## Out of Scope

- 不承诺飞书上游冷读取一定在 30 秒内完成。
- 不持久化业务快照。
- 不以模拟数据、静态 JSON 或空对象代替正式数据。
- 不修改应用申请、培训、认证、人才、运营等其他业务交互流程。
- 不部署、不发布、不合并主分支。

## Success Metric

- 热态首页聚合读取在 2 秒内返回正式数据。
- 任一聚合请求在 30 秒内返回 `200 fresh`、`200 stale` 或 `202 syncing`，不无限等待。
- 同一冷启动同步范围同时只有一个后台任务。
- 已有合规快照时，飞书刷新失败不会让首页变空。

## Deadline

尽快完成。

## Risk

高风险。涉及身份隔离缓存、服务启动就绪状态、冷启动并发、陈旧数据语义及 Nginx/浏览器超时边界。实现与验证责任归 Web 工程实施和独立 QA。

## Dependencies

- 正式飞书多维表格及现有服务端凭据保持可用。
- 现有五项读取 operation 合同保持兼容。
- Nginx 的代理超时必须高于应用层 30 秒响应边界。
- 复用现有身份、权限指纹、共享表快照和缓存失效机制。
