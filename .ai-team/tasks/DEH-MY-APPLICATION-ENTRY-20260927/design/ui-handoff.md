# UI Visual Handoff — DEH-MY-APPLICATION-ENTRY-20260927

## 1. 依据、范围与不变项

本视觉交接以已批准的 [PRD](../prd.md) 和 [UX / Interaction Handoff](ux-handoff.md) 为唯一产品与交互依据，并以以下现有实现作为设计系统证据：

- [个人中心](../../../../src/pages/ProfilePage.vue) 的快捷入口、卡片、断点与键盘焦点。
- [申请状态页](../../../../src/pages/OnboardingPage.vue) 的标题区、状态摘要、时间线、详情卡片、状态色和响应式规则。
- [应用上架申请页](../../../../src/pages/OnboardingApplyPage.vue) 的标题区、表单状态、焦点和减少动态规则。

仅覆盖 Web：两处“我的申请”入口的等价呈现、申请详情时间线的可读性，以及申请页移除“飞书授权”可见入口。不得改动路由目的地、权限判定、OAuth、审批、数据写入、提交或状态同步逻辑；不得新增替代授权入口。

## 2. 视觉方向与信息层级

沿用当前“白色内容卡片 + 海洋蓝主操作 + 浅灰蓝边界”的企业工作台语言，不引入新品牌、插画或图标集。

1. **页面层级：** 页面标题区保持最高层级；申请状态摘要居次；时间线独立置于一张白色卡片中；详情信息维持双列卡片。卡片边界和阴影只用于分组，不用阴影模拟可点击性。
2. **个人中心入口：** 标题文字入口和“我的申请”快捷卡片是同一目标的两个可操作层级。文字入口为紧凑次级导航；快捷卡片为整块主可点击区域。两者使用相同的可用或不可用视觉状态，不能只让其中一个变灰或移除。
3. **时间线：** 图标中心为唯一的进度轨道。阶段标题和时间为轨道下方/旁侧的文本信息层；连线只能出现在相邻图标中心之间，永远不进入文本区域。
4. **申请页标题操作：** 移除“飞书授权”后，保留的“返回应用中心”右对齐，不补位成新的主按钮，也不留下空白、分隔符或可聚焦残留。

## 4. 字体、图标、组件外观与动态

### 4.1 排版

- 页面标题沿用 `clamp(26px, calc(23.5px + .28vw), 32px)`；个人中心快捷入口区标题沿用 `16px`，卡片标题沿用 `13px`，辅助说明沿用 `10–13px` 的现有级差。
- 申请详情卡片标题沿用 `18px`、左侧 `3px #0060a6` 识别条；正文使用现有深灰蓝，不以纯黑替换。
- 时间线阶段标题使用现有加粗 `strong` 规格；时间沿用 `13px`、`#61758c`。标题和时间不得截断、重叠或覆盖连线；长文本可自然换行。

### 4.2 个人中心“我的申请”入口

- 快捷卡片沿用现有 `103px` 高度、`5px` 圆角、`#dfe7ef` 边界、`17px` 横向内边距、`18px` 内容间距；保持现有 `65px` `AppIcon` 及右侧箭头的视觉角色。
- 正常可用时，卡片整块均为单一链接命中区；鼠标悬停采用申请状态页已存在的淡蓝表面反馈（`#eff7fc`）或项目中等价已用 hover，不添加位移、缩放或闪烁动画。
- 标题文字入口沿用已有小号链接风格和 `#0060a6`，可用时与卡片拥有一致的可见焦点规则。
- 不可用时，标题文字入口与卡片一起遵循既有禁用呈现；保留说明文本或现有 title，不用“不可见链接”伪装为可操作状态。

### 4.3 申请详情时间线

- **宽视口（≥761px）：采用确定性的两行网格，不使用文字遮线。** 时间线容器沿用白色卡片、`18px` 内边距、`7px` 圆角。当前产品实际渲染的两个阶段各占一个相等的网格列；第一行是独立的图标轨道行（高度 `28px`），第二行是独立的文本行。每枚状态图标保持 `28px × 28px`，在其所属列水平居中。阶段标题与时间仅可出现在同列的第二行，不能进入第一行。
- **轨道段归属与边界：** 每一段归其左侧（较早）阶段的图标轨道单元所有；末阶段没有轨道段。对于左侧阶段单元，段从该单元图标的右外缘开始，即轨道单元自身的 `50% + 14px`；段延伸到相邻阶段图标的左外缘，即宽度为该单元宽度减 `28px`（`left: calc(50% + 14px); width: calc(100% - 28px)`）。轨道固定在图标行垂直中点（`top:13px; height:2px`），可跨入相邻图标轨道单元，但绝不跨入第二行文本单元。由较早阶段单元的 `::after` 绘制，并位于图标之下；文本行不参与轨道的层叠上下文。
- **文字换行与列宽：** 每个文本单元使用 `min-width:0`；标题与时间使用 `white-space:normal` 和 `overflow-wrap:anywhere` 自然向下换行。文字只能增加第二行的高度，不能挤压、移位、覆盖或裁断第一行的图标与轨道；不得通过降低线条透明度、隐藏标题/时间、截断文本、移动图标或不透明文字遮罩规避碰撞。
- **确定性回退：** `max-width:760px`（包括浏览器缩放后 CSS 视口不超过 `760px`）立即切换到现有竖向时间线：图标列宽 `28px`，轨道只在该列内相邻图标外缘之间延伸，标题和时间在独立文本列中自然换行。`761px` 及以上始终使用上述两行横向布局；不再使用“文字完整才横向”的条件性布局。
- **阶段数量边界：** 当前详情模板与可用审批数据均提供两个阶段；这已满足 PRD 所述“两个或更多阶段”的最低验收条件。本任务的视觉验收只针对这条现有两阶段链路，在宽视口、窄视口和 200% 缩放下验证。第三及更多阶段的渲染泛化、数据模型、审批数据来源和验收样本均不在本任务范围；不得为此创建审批数据或改变审批阶段模型，后续若需要必须另行立项。
- 阶段图标保持 `z-index` 高于连线；成功、审批中、驳回/取消、未知分别使用现有绿色、主蓝、红色、警示棕色，同时保留图标字符和阶段文字。

### 4.4 标题区与按钮

- 移除 `.feishu-auth-link` 的可见渲染；只保留 `.back-link`，继续使用现有次级按钮外观：至少 `42px` 高、白底、`#7891a8` 边界、`7px` 圆角、`#0060a6` 文字。
- 原生可用控件保持最小高度 `42px`；窄视口按既有规则提升至 `44px`。禁用按钮不应出现主操作蓝底或 hover 反馈。
- 不引入新的图标含义。时间线图标仅为状态辅助，须继续设置为装饰性；入口快捷卡片仍使用项目现有 `AppIcon`。

### 4.5 动态与偏好

- 本任务不增加转场、自动滚动或进度动画。
- 保持现有 `prefers-reduced-motion: reduce`：禁用滚动行为与过渡；申请页仅保留其已存在的加载器降级规则。
- 在 `forced-colors: active` 下，沿用现有 `Highlight` 焦点色覆盖，不用背景色作为唯一状态区分。

| 状态 | 个人中心两个入口 | 列表 / 详情与时间线 | 申请页标题区 |
| --- | --- | --- | --- |
| `normal` | 标题链接和快捷卡片均以 `#0060a6` 可操作语义呈现；卡片使用白底、浅边界，整块一个焦点目标。 | 卡片白底、状态徽章和图标依既有语义色；时间线轨道只在图标间，标题/时间清晰可读。 | 不展示“飞书授权”；只显示次级“返回应用中心”。 |
| `loading` | 保持两个入口的等价性；不以颜色暗示新权限状态。 | 保留既有 `role=status` 加载文本；正在刷新的详情维持上一次可读内容，刷新按钮采用现有禁用外观，避免与失败色混淆。 | 保留既有提交加载反馈；不重现授权按钮。 |
| `empty` | 两个入口仍为等价入口并可进入列表。 | 使用既有白底空态卡片、居中内容、`#61758c` 辅助文字；“发起申请”和“返回应用中心”按现有主/次操作层级呈现。 | 不因申请列表为空新增标题区内容。 |

| `disabled` | 两入口同时使用同一现有不可用视觉规则；不可操作项没有悬停或虚假手型反馈。 | 使用既有 `#f2f4f7` 表面和 `#3e5571` 文字；恢复动作仍可见，避免与权限拒绝红色混同。 | 仅按既有目录/表单不可用状态呈现，不恢复授权按钮。 |
| `permission-denied` | 两入口同步采用既有权限拒绝外观和说明，不能出现一个仍为蓝色可点击链接。 | 使用既有错误/拒绝色组并配 `role=alert`；详情的返回动作保持次级按钮外观。 | 保持当前申请页已有的权限提示；不引入、显示或替换为“飞书授权”入口。 |

## 6. Web 响应式与密度规则

| Web 视口 | 布局规则 |
| --- | --- |
| `>1180px` | 申请详情信息维持两列卡片；时间线使用两行横向网格：第一行为独立图标轨道，第二行为同列文本。个人中心保留四列快捷卡片。 |
| `901–1180px` | 详情卡片改为单列（现有 `1180px` 规则）；时间线仍使用两行横向网格，文本仅在第二行同列内换行。个人中心在 `1200px` 以下按现有两列快捷卡片重排。 |
| `761–900px` | 列表表格已按现有规则转换为可读卡片行；详情时间线仍使用两行横向网格，不以标题长度作为条件性切换依据。 |
| `≤760px` | 时间线使用现有竖向顺序：`18px` 阶段间距，轨道仅位于左侧图标列（图标中心 `13px`），文本列独立于轨道。标题区纵向排列，操作至少 `44px` 高；个人中心快捷入口单列。 |
| `≤639px` | 详情定义列表与附件表保持现有单列堆叠；按钮/文件操作满宽。长标题、时间、申请标识允许换行且不裁切。 |

Web 的鼠标 hover 只作为补充，不能是唯一可用性提示；触摸板与键盘须获得等价结果。页面在浏览器缩放 200% 时不得使阶段文本和连线相交，横向空间不足即使用现有竖向时间线阅读流。

## 7. 键盘、焦点与可访问视觉要求

- 入口标题链接和快捷卡片在可用时均必须具有清晰的 `:focus-visible` 外框；采用页面既有 `3px` 焦点环与 `2–3px` 偏移，且不得被卡片 `overflow`、连线或白色遮罩裁掉。
- 快捷卡片只呈现一个键盘焦点和一个可访问名称；图标和箭头不形成额外焦点。禁用项不提供虚假链接焦点。
- 路由完成后，页面标题的程序化焦点不显示鼠标式装饰轮廓（沿用现有 `h1:focus{outline:none}`），其他键盘控件仍显示焦点环。
- 时间线连线不可聚焦、不可作为独立辅助技术内容；其文本背景分层也不得遮挡图标焦点或状态说明。
- 错误和权限拒绝使用现有高对比错误表面并保持 `role=alert`；加载/空态的状态文本维持非中断式反馈。视觉修复不得改变 UX 交接规定的焦点落点。

## 9. 冲突、验证与交接限制

### 已识别冲突

- **无产品或 UX 冲突。** UX 已明确两处入口必须同目的地、时间线不得穿越文本、授权按钮只移除显示。视觉实现不得以隐藏标题或时间、改变权限门禁、添加授权 CTA 等方式“修复”问题。
- **实现注意：** 现有横向时间线的伪元素在 `OnboardingPage.vue:90` 位于 `top:13px`，而阶段文本当前可处在同一绘制层。实现必须按第 4.3 节重组为独立图标轨道行和独立文字行；不得以文字遮罩维持表面效果，也不得改变审批阶段数据。
- **验收边界：** 当前模板的两阶段时间线是本任务唯一已有、可渲染的阶段来源，并作为“两个或更多阶段”的最低有效实例。第三阶段及以上的呈现和验收不在本任务中暗示、模拟或扩展；这不是缺失的测试数据，而是明确的范围外事项。

### 视觉验收清单

1. `≥761px` 宽视口下，现有两个阶段在独立图标轨道行与独立文本行中渲染：轨道段由左侧阶段拥有，只从左图标右外缘连至右图标左外缘，标题和时间不与轨道相交；在 200% 浏览器缩放下同样成立。
2. `≤760px` 下，时间线为图标列 + 文本列的竖向流，轨道不进入文本列；缩放造成 CSS 视口落入该断点时，同样使用此回退。
3. 个人中心的文字“我的申请”和整张快捷卡片均能获得相同显著焦点，且可用/禁用状态一致。
4. 申请页标题区无可见、可聚焦或读屏可见的“飞书授权”残留；“返回应用中心”视觉位置与功能保留。
5. 正常、加载、空、错误、禁用、权限拒绝六种状态保持既有内容和操作，且状态可通过文字/图标/边界而非单一颜色辨识。
6. 在强制颜色、减少动态和 200% 浏览器缩放下，焦点、状态文本、现有两阶段时间线和按钮仍可辨识；第三及更多阶段的模型泛化与验收不属于本任务。
