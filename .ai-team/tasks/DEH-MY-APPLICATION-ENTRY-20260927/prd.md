# DEH-MY-APPLICATION-ENTRY-20260927 PRD

## 1. 产品目标与目标用户价值

让已授权的 Web 端业务用户能够从个人中心稳定进入“我的申请”，清晰阅读应用上线申请详情中的审批进度，并在申请表单中不再看到不需要的“飞书授权”按钮；已有申请提交与查看进度链路必须保持可用。

## 2. 事实、待确认假设与证据

### 事实

- **事实：** 当前任务仅覆盖现有 Vue Web 项目。  
  **证据：** `task.json` 的 `platforms` 为 `web`，`web_framework` 为 `vue`。
- **事实：** 个人中心中，文字形式的“我的申请”入口可正确跳转，而快捷卡片不能跳转。  
  **证据：** `task-brief.md` 的 Evidence。
- **事实：** 申请详情时间线的连线与“提交申请”阶段标题存在视觉重叠。  
  **证据：** `task-brief.md` 的 Evidence。
- **事实：** 用户要求申请表单不再展示“飞书授权”按钮。  
  **证据：** `task-brief.md` 的 Evidence。
- **事实：** 已有授权、审批、数据写入和 OAuth 回调行为不属于本任务修改范围。  
  **证据：** `task.json` / `task-brief.md` 的 In Scope 与 Out of Scope。
- **事实：** 验收需要覆盖空申请列表和已有真实申请详情。  
  **证据：** `task-brief.md` 的 Scope。

### 待确认假设

- **假设：** 快捷卡片与文字入口应使用完全相同的目标路由和可用性规则。  
  **依据：** 任务成功标准要求“两处入口均能进入同一我的申请页”；具体路由实现需在设计阶段以现有工作入口为准核验。
- **假设：** 时间线的阶段标题可通过布局层级或留白与连线分离，无需改动审批状态数据。  
  **依据：** 本任务仅要求视觉重叠修复，明确不修改审批配置或数据写入。
- **假设：** 移除按钮仅影响页面展示，不删除或修改已有授权能力。  
  **依据：** 任务明确要求不改变授权会话、回调或审批提交逻辑。

## 3. 范围边界

### In Scope

- 修复个人中心“我的申请”快捷卡片的路由和可用状态，使其进入与现有文字入口相同的页面。
- 保留并回归核验现有“我的申请”文字入口。
- 修复申请详情页审批时间线中连线与阶段标题的视觉重叠。
- 从应用上线申请页移除“飞书授权”按钮的展示。
- 在本地 Web 应用中验证两处入口、空列表、已有申请详情、申请表单展示和既有查看进度链路。

### Out of Scope

- OAuth 会话持久化、OAuth 回调、令牌或授权流程变更。
- 飞书审批配置、审批规则、Base 表结构、业务数据、上传工作流及数据创建。
- 其他个人中心入口、素材中心、移动端/uni-app、生产发布、外部推送或合并主分支。

## 4. 主用户流程

1. 已授权用户进入个人中心。
2. 用户点击文字“我的申请”入口或“我的申请”快捷卡片。
3. 系统将两种入口都导航至同一“我的申请”页面。
4. 用户在有申请记录时选择一条申请，进入申请详情页。
5. 系统显示可阅读的审批时间线，连线不遮挡任何阶段标题或时间。
6. 用户返回或进入应用上线申请页时，页面不显示“飞书授权”按钮；其他既有表单与查看进度入口保持可用。

## 5. 状态清单

| 状态 | 预期行为 |
| --- | --- |
| 成功 | 两处“我的申请”入口均可进入同一页面；详情时间线标题、时间与连线清晰分离；申请页不显示授权按钮。 |
| 加载 | 申请列表或申请详情加载时，沿用现有页面加载反馈；入口不应重复导航或进入错误页面。 |
| 空态 | 没有申请记录时，两处入口仍可进入“我的申请”页并显示既有空态。 |
| 错误 | 申请列表或详情读取失败时，沿用既有错误反馈；不得将入口变为错误路由或错误地显示授权按钮。 |
| 禁用 | 若现有权限模型确实要求禁用入口，文字入口与快捷卡片必须保持一致，不出现一处可用、一处不可用。 |
| 权限相关 | 本任务面向已授权用户；不新增、更改或绕开授权、回调、会话和审批权限逻辑。 |

## 6. 明确不做

- 不新增“飞书授权”替代入口、提示或自动授权机制。
- 不修改申请提交字段、审批实例、同步策略、飞书审批模板或 Base 写入时机。
- 不为没有申请的用户创建测试申请或业务数据。
- 不扩展到个人中心的收藏、积分、消息等其他快捷入口。
- 不进行移动端适配、部署或发布操作。

## 7. 范围批准所需的开放问题与决策

- 无新增业务决策待确认。设计阶段须以现有可用文字入口为唯一基准，确认快捷卡片的目标路由和可用性条件。
- 设计阶段须确认时间线在两阶段及更多阶段时均不会发生标题与连线重叠。
- 用户已明确要求移除申请页“飞书授权”按钮；该决定仅限 UI 展示，不扩大到授权机制。

## 验收标准

1. **Given** 已授权用户位于个人中心，**When** 点击文字“我的申请”入口，**Then** 系统进入现有“我的申请”页面，且行为保持与修复前一致。
2. **Given** 已授权用户位于个人中心，**When** 点击“我的申请”快捷卡片，**Then** 系统进入与文字入口完全相同的“我的申请”页面。
3. **Given** 当前权限规则允许用户查看申请，**When** 页面同时展示文字入口和快捷卡片，**Then** 两个入口均可用，不出现只有其中一个不可点击的情况。
4. **Given** 当前权限规则不允许用户查看申请，**When** 页面展示两种入口，**Then** 两者遵循同一既有权限反馈，不新增授权或绕过权限的行为。
5. **Given** 用户的“我的申请”列表为空，**When** 从任一入口进入，**Then** 页面显示既有空态且页面可正常返回或继续操作。
6. **Given** 用户存在一条已有申请，**When** 打开该申请详情，**Then** 每个阶段标题与时间均不被进度连线遮挡，且连线仍正确表达阶段顺序。
7. **Given** 申请详情包含两个或更多审批阶段，**When** 页面在本任务声明的 Web 视口中渲染，**Then** 阶段标题、时间、图标与连线互不重叠。
8. **Given** 用户进入应用上线申请页，**When** 页面完成渲染，**Then** 不展示“飞书授权”按钮。
9. **Given** 已授权用户在本任务修复后进入应用上线申请页与申请详情页，**When** 查看既有申请进度，**Then** 原有查看进度链路仍可用，且本任务未触及授权、回调、审批提交或数据写入行为。
